## 阶段时机

Vue 组件在创建、挂载、更新、卸载时会经历不同阶段。生命周期钩子的作用，是把初始化、订阅、清理放到正确的时间点。

```ts
onMounted(() => {
  loadData();
});
```

生命周期不是业务逻辑的容器，它只负责“什么时候做”。真正的数据请求、资源管理和状态写入，最好仍然封装在清晰的函数或组合函数里。

生命周期钩子最容易被滥用成“组件初始化大杂烩”。更好的做法是先把业务动作命名成函数，再在合适的钩子里调用它。这样代码表达的是“挂载时加载数据”，而不是“挂载时执行一大段不明逻辑”。

```ts
onMounted(() => {
  loadUser();
  startPolling();
});
```

如果这两个动作没有强关联，也可以继续拆进不同组合函数，让订阅和清理靠近自身逻辑。

生命周期真正解决的是“时机问题”，不是“职责问题”。也就是说，它帮你决定一段逻辑何时进入、何时退出，但不应该替你决定这段逻辑属于哪个模块。职责还是要靠组件、组合函数和状态边界来划分。

## 挂载阶段

`onMounted` 适合访问真实 DOM、初始化第三方库、绑定浏览器事件。

```ts
onMounted(() => {
  window.addEventListener("resize", handleResize);
});
```

能在 `setup` 里直接准备的数据，不必等到挂载。只有依赖 DOM 或外部环境时，挂载阶段才真正必要。

`onMounted` 不会在服务端渲染阶段执行，所以浏览器专属逻辑放在这里通常更安全。例如访问 `window`、`document`、DOM 尺寸、第三方浏览器 SDK，都应该等客户端挂载后再做。

```ts
const width = ref(0);

onMounted(() => {
  width.value = window.innerWidth;
});
```

如果数据请求不依赖 DOM，在支持 SSR 的框架里可能更适合走框架的数据获取机制，而不是全部放进 `onMounted`，否则首屏会先空白再请求。

另一个常见场景是根据 DOM 尺寸做布局测量，例如虚拟列表、图表容器、自适应弹层。它们通常也应该放到挂载后，再结合 `nextTick` 或观察器读取尺寸，而不是在 `setup` 里提前假设节点已经存在。

## 更新阶段

`onUpdated` 会在组件更新后执行。

```ts
onUpdated(() => {
  console.log("DOM 已更新");
});
```

大多数业务不需要它。如果只是响应某个状态变化，用 `watch` 更明确；如果只是派生值，用 `computed` 更合适。

`onUpdated` 是组件 DOM 更新后触发的整体钩子，粒度比较粗。它不知道你真正关心哪个状态变化，所以容易造成过度执行。只有在确实需要“DOM 更新完成后再测量或操作”时才考虑它。

```ts
watch(
  () => props.activeId,
  async () => {
    await nextTick();
    scrollToActiveItem();
  },
);
```

很多“更新后操作 DOM”的需求，用 `watch + nextTick` 会比 `onUpdated` 更精确。

这背后的原因是：`onUpdated` 面向的是“整个组件完成一次更新”，而很多业务真正关心的是“某个特定状态变化以后，某个特定 DOM 已经更新完”。粒度越精确，副作用越容易控制，也越不容易误触发。

## 卸载阶段

卸载时要清理定时器、事件监听、请求订阅和外部实例。

```ts
onUnmounted(() => {
  window.removeEventListener("resize", handleResize);
});
```

不清理会导致内存泄漏、重复触发和幽灵副作用。弹窗、长列表、轮询、第三方组件尤其容易出问题。

卸载清理应该和创建逻辑成对出现。添加事件就移除事件，启动定时器就清除定时器，创建实例就销毁实例，发起订阅就退订。

```ts
let timer: number | undefined;

onMounted(() => {
  timer = window.setInterval(refresh, 5000);
});

onUnmounted(() => {
  if (timer) window.clearInterval(timer);
});
```

如果清理逻辑散在多个地方，后续很容易漏。组合函数的价值之一，就是把创建和清理封在一起。

如果组件里存在异步请求，还要考虑卸载后的结果回写问题。组件已经离开页面，但请求稍后才返回，如果不做取消或状态保护，就可能出现“页面已销毁但仍然写状态”的警告，或者把旧数据写进新页面。

## `KeepAlive`

`KeepAlive` 会缓存组件实例，避免频繁销毁重建。

```vue
<KeepAlive>
  <RouterView />
</KeepAlive>
```

缓存页面还要处理激活和失活。

```ts
onActivated(() => {
  refreshIfNeeded();
});

onDeactivated(() => {
  pausePolling();
});
```

轮询、播放器、地图、编辑器这类资源，要特别注意失活后的暂停和恢复。

`KeepAlive` 下组件不会真正卸载，因此 `onUnmounted` 不会在每次离开页面时触发。需要在离开缓存页面时暂停资源，就要用 `onDeactivated`；回到页面时再用 `onActivated` 恢复。

```ts
onActivated(() => {
  resume();
});

onDeactivated(() => {
  pause();
});
```

缓存页面适合保留表单草稿、滚动位置和列表状态，但不适合无脑缓存所有页面。缓存越多，内存和状态一致性成本越高。

使用 `KeepAlive` 时还要特别关注数据新鲜度。缓存能保留状态，但也意味着页面可能带着旧数据再次激活。对于订单状态、通知列表、权限信息这类变化较快的数据，回到页面时通常还要配合一次轻量刷新或失效判断。

## 错误捕获

`onErrorCaptured` 可以捕获子树错误，用于上报和局部降级。

```ts
onErrorCaptured((err) => {
  reportError(err);
  return false;
});
```

它适合复杂组件库、异步组件和第三方组件区域，避免局部错误拖垮整页。

错误捕获适合做局部降级和上报，但不能替代正常错误处理。请求失败、表单校验失败、权限不足这些业务错误，应在业务流程中明确处理；`onErrorCaptured` 更适合捕获渲染和子组件异常。

```ts
onErrorCaptured((error, instance, info) => {
  reportError(error, { info });
  return false;
});
```

返回 `false` 可以阻止错误继续向上传播。是否阻止要看页面是否有更上层的错误边界。

错误捕获更适合做“兜底”，而不是做“常规流程”。如果一个组件经常依赖 `onErrorCaptured` 才能维持页面可用，通常说明真正的问题在于数据校验、异步边界或子组件防御性还不够。

## 组合函数

组合函数里也可以使用生命周期钩子。

```ts
function useResize() {
  onMounted(() => window.addEventListener("resize", handle));
  onUnmounted(() => window.removeEventListener("resize", handle));
}
```

好的组合函数应该自己完成订阅和清理，不把资源管理责任丢给调用方。

生命周期和组合函数结合时，要保证组合函数只能在组件 setup 上下文中调用。不要把依赖生命周期的组合函数当普通工具函数在任意地方调用。

```ts
function useInterval(callback: () => void, delay: number) {
  let timer: number | undefined;

  onMounted(() => {
    timer = window.setInterval(callback, delay);
  });

  onUnmounted(() => {
    if (timer) window.clearInterval(timer);
  });
}
```

这样调用方只表达“我要一个定时器”，不用记得手动清理。生命周期钩子的价值，是把资源和组件存在周期对齐。

从工程角度看，生命周期和组合函数配合得越好，组件本身就越薄。页面只描述“我需要轮询、我需要监听尺寸、我需要同步标题”，至于什么时候订阅、什么时候销毁，都沉淀在组合函数内部，这样复用性和稳定性都会更高。
