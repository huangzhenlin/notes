## 语法本质

JSX 不是 HTML，而是 JavaScript 的语法扩展。它让组件可以直接用接近结构化标记的方式描述 UI，最后会被编译成 `React.createElement` 或新的 JSX 运行时调用。

```tsx
const title = "Dashboard";

function Header() {
  return <h1>{title}</h1>;
}
```

JSX 的核心价值不是“写起来像 HTML”，而是把界面结构、数据和条件逻辑放在同一段 JavaScript 里表达，便于组合、拆分和复用。

现代 React 项目通常使用新的 JSX 运行时，文件里不再必须手动 `import React from "react"` 才能写 JSX，但这不代表 JSX 是浏览器原生语法。它仍然需要 Babel、TypeScript、SWC 或构建工具编译。

```tsx
const element = <button disabled>保存</button>;
```

编译后大致会变成对 JSX 运行时的函数调用，React 再根据这些对象描述更新界面。理解这一点后，就能明白 JSX 里的表达式是 JavaScript，属性传递是对象数据，组件名是变量引用，而不是字符串模板替换。

## 表达式位置

JSX 花括号里只能放表达式，不能直接写语句。

```tsx
const count = 3;

function Counter() {
  return <span>{count + 1}</span>;
}
```

如果逻辑变复杂，先在外部计算再放回 JSX，通常比把所有判断塞进模板更清晰。

```tsx
function Price({ value }: { value: number }) {
  const label = value > 100 ? "高价" : "普通";
  return <strong>{label}</strong>;
}
```

表达式可以是变量、函数调用、三元表达式、数组 `map`，但不能直接写 `if`、`for`、`switch` 这类语句。复杂逻辑应该提前计算或拆成组件。

```tsx
function StatusText({ status }: { status: "idle" | "loading" | "error" }) {
  const label = {
    idle: "未开始",
    loading: "加载中",
    error: "加载失败",
  }[status];

  return <span>{label}</span>;
}
```

把映射关系提出来，不仅 JSX 更干净，也更容易补齐状态。如果状态来自 TypeScript 联合类型，还能配合类型检查避免漏分支。

## 属性写法

JSX 属性名接近 DOM，但并不完全一样。

```tsx
function Card() {
  return (
    <div className="card" style={{ padding: 16, borderRadius: 8 }}>
      内容
    </div>
  );
}
```

`class` 要写成 `className`，内联样式是对象而不是字符串，事件处理器也是函数引用而不是字符串。JSX 不是字符串模板，所以不要把它当成拼接 HTML 的工具。

| 写法 | 含义 |
| --- | --- |
| `className` | CSS 类名 |
| `style={{}}` | 内联样式对象 |
| `onClick={() => {}}` | 事件处理函数 |
| `{value}` | 动态表达式 |

布尔属性、数字属性和对象属性也要按 JavaScript 语义理解。

```tsx
<button disabled={isSubmitting} tabIndex={0} />
<div style={{ width: 120, opacity: 0.8 }} />
```

样式对象里的数字通常会自动追加单位，但不是所有属性都这样。更重要的是，内联样式不支持伪类、媒体查询和复杂选择器，所以只适合动态少量样式，不适合作为组件样式的全部方案。

属性展开要谨慎。它适合透传基础 DOM 属性，但如果把业务对象直接展开到 DOM 上，可能产生无效属性或泄露数据。

```tsx
function Button(props: React.ComponentProps<"button">) {
  return <button {...props} className="button" />;
}
```

## 条件渲染

React 常见的条件渲染方式有提前返回、三元表达式和逻辑与。

```tsx
function Profile({ user }: { user?: { name: string } }) {
  if (!user) {
    return <div>未登录</div>;
  }

  return <h2>{user.name}</h2>;
}
```

```tsx
{isLoading ? <Spinner /> : <Content />}
{hasError && <ErrorBanner />}
```

如果分支太多，通常说明 UI 结构该拆了，而不是继续在 JSX 里堆嵌套。

逻辑与写法要注意左侧值的类型。`0 && <Component />` 会渲染出 `0`，这不是 React bug，而是 JavaScript 表达式结果就是数字 `0`。

```tsx
{items.length > 0 && <List items={items} />}
```

复杂条件可以先命名。命名本身就是整理业务语义的过程。

```tsx
const canSubmit = formValid && !submitting && hasPermission;

return <button disabled={!canSubmit}>提交</button>;
```

如果条件表达式长到需要读两遍，就应该把它提出来，让 JSX 继续承担结构表达，而不是承担推理题。

## 列表渲染

列表渲染通常用 `map`，`key` 要稳定且唯一。

```tsx
function UserList({ users }: { users: { id: string; name: string }[] }) {
  return (
    <ul>
      {users.map((user) => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}
```

`key` 的作用是帮助 React 识别元素身份，避免重排时误用旧节点。不要优先用数组索引，除非列表天然静态且不重排。

`key` 不会作为普通 props 传给子组件，它是 React 自己用来识别元素身份的特殊属性。如果子组件也需要 id，要单独传。

```tsx
{users.map((user) => (
  <UserItem key={user.id} userId={user.id} user={user} />
))}
```

错误的 key 会导致状态保留到错误项上。比如列表项里有输入框，使用索引作为 key 后，在列表头部插入新项，原来输入框的状态可能跟着位置走，而不是跟着数据走。

## 片段容器

Fragment 用来包裹多个兄弟节点而不额外增加 DOM。

```tsx
function Layout() {
  return (
    <>
      <Header />
      <Main />
      <Footer />
    </>
  );
}
```

当组件只想返回一组并列元素时，Fragment 比额外加一个空容器更干净，也更少影响布局和样式。

短语法 `<>...</>` 不能设置 key。如果在列表里返回一组兄弟节点，需要使用完整的 `React.Fragment` 并提供 key。

```tsx
{sections.map((section) => (
  <React.Fragment key={section.id}>
    <h2>{section.title}</h2>
    <p>{section.description}</p>
  </React.Fragment>
))}
```

这能避免为了 key 多包一层无意义 DOM，也不会破坏表格、列表或网格布局。

## JSX 不是 HTML

JSX 仍然受 JavaScript 规则控制，变量、函数、作用域和模块边界都会影响它。

```tsx
function Avatar({ user }: { user: { name: string; avatarUrl: string } }) {
  return <img src={user.avatarUrl} alt={user.name} />;
}
```

这也意味着 JSX 默认更接近安全的文本输出。只要不是主动把不可信内容塞进 `dangerouslySetInnerHTML` 这类入口，它通常会比字符串拼接更不容易引入 [[1.6.1 XSS|XSS]]。

JSX 里的小写标签会被当作原生元素，大写开头会被当作组件变量。因此组件名必须大写。

```tsx
function avatar() {
  return <img alt="" />;
}

function Profile() {
  return <avatar />;
}
```

上面 `<avatar />` 会被当成自定义 HTML 标签，而不是调用 `avatar` 函数组件。正确写法是 `Avatar`。

JSX 和 HTML 另一个重要差异是属性名更贴近 DOM API，例如 `htmlFor`、`className`、`onClick`。写 JSX 时如果不确定某个属性名，优先查 React 对应元素类型或编辑器提示，而不是照搬 HTML。

## 写法边界

| 场景 | 更合适的写法 |
| --- | --- |
| 简单结构 | 直接写 JSX |
| 复杂条件 | 提前计算变量 |
| 大段重复 | 拆成子组件 |
| 动态列表 | `map` + 稳定 `key` |
| 富文本渲染 | 先净化再渲染 |

JSX 最适合表达“结构”，不适合承担所有业务逻辑。把它当成视图层语法，组件会更清楚，维护也更轻松。

一个可维护的 JSX 通常具备三个特征：结构一眼能看出层级，复杂判断有命名，重复块被拆成组件。JSX 不是越短越好，而是让 UI 结构和业务语义对齐。真正复杂的页面，不应该靠一段巨大 JSX 撑住，而应该靠组件模型拆开。
