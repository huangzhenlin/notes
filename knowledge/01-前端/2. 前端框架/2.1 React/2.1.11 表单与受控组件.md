## 受控输入

受控组件把输入值放在 React state 里，界面显示完全由状态驱动。

```tsx
function SearchBox() {
  const [value, setValue] = React.useState("");

  return <input value={value} onChange={(event) => setValue(event.target.value)} />;
}
```

它适合实时校验、条件联动、提交前统一处理和复杂表单。代价是每次输入都会进入 React 更新流程。

受控组件的关键是 `value` 和 `onChange` 成对出现。只传 `value` 不处理变化，输入框会变成只读；只处理变化但不绑定 `value`，React 就不能完全控制显示值。

```tsx
function EmailField() {
  const [email, setEmail] = React.useState("");
  const valid = email.includes("@");

  return (
    <label>
      邮箱
      <input
        value={email}
        onChange={(event) => setEmail(event.target.value)}
        aria-invalid={!valid}
      />
      {!valid && <span role="alert">请输入有效邮箱</span>}
    </label>
  );
}
```

如果输入状态用于即时提示、按钮禁用、联动字段或接口参数，受控方式更容易保持 UI 和数据一致。它的成本是状态更新更频繁，所以超大表单要注意拆分组件和减少无关渲染。

## 表单提交

表单提交应该优先用 `onSubmit` 统一接管，而不是只监听按钮点击。

```tsx
function LoginForm() {
  const [username, setUsername] = React.useState("");

  async function handleSubmit(event: React.FormEvent<HTMLFormElement>) {
    event.preventDefault();
    await login({ username });
  }

  return (
    <form onSubmit={handleSubmit}>
      <input value={username} onChange={(event) => setUsername(event.target.value)} />
      <button type="submit">登录</button>
    </form>
  );
}
```

这样既支持回车提交，也能统一处理校验、禁用、错误提示和异步状态。

表单按钮要明确 `type`。在表单内部，`button` 默认可能是提交按钮，如果一个“取消”“获取验证码”按钮忘记写 `type="button"`，可能意外触发表单提交。

```tsx
<button type="button" onClick={sendCode}>
  获取验证码
</button>
<button type="submit">
  登录
</button>
```

`onSubmit` 还可以让浏览器原生校验、键盘交互和辅助技术更自然地工作。不要为了图省事把表单写成一堆 `div` 加点击事件，否则可访问性和键盘体验都会变差。

## 多字段状态

字段多时，可以继续拆多个 state，也可以用对象统一管理。

```tsx
const [form, setForm] = React.useState({
  name: "",
  email: "",
});

setForm((current) => ({ ...current, name: nextValue }));
```

如果字段之间强关联、还要统一校验，表单对象通常更自然。如果字段完全独立，拆成多个 state 反而更简单。

多字段更新时要避免直接修改旧对象。React 依赖新引用判断状态变化，直接改原对象可能导致 UI 不更新或状态污染。

```tsx
function updateField(name: keyof FormValues, value: string) {
  setForm((current) => ({
    ...current,
    [name]: value,
  }));
}
```

对于字段数量很多、规则复杂的表单，可以用 `useReducer` 表达状态转移。这样“字段变化、校验失败、提交开始、提交成功、提交失败”都变成明确事件，逻辑比多个分散的 `useState` 更集中。

```tsx
type Action =
  | { type: "change"; name: keyof FormValues; value: string }
  | { type: "submitStart" }
  | { type: "submitError"; message: string };
```

## 校验状态

表单不只有值，还有错误、触碰状态、提交中、成功和失败。

```tsx
type FormState = {
  value: string;
  error?: string;
  touched: boolean;
  submitting: boolean;
};
```

不要把“输入校验失败”和“接口提交失败”混成一种错误。前者是用户输入问题，后者是服务端或网络结果，反馈方式不同。

表单状态至少可以拆成四类：字段值、字段级错误、表单级错误、提交状态。字段级错误贴近输入框展示，表单级错误适合展示“账号或密码错误”“网络异常”“权限不足”这类整体结果。

```tsx
type LoginFormState = {
  values: {
    username: string;
    password: string;
  };
  fieldErrors: Partial<Record<"username" | "password", string>>;
  formError: string | null;
  submitting: boolean;
};
```

校验触发时机也要区分：输入中实时校验适合格式简单的字段，比如邮箱、长度；失焦校验适合减少打扰；提交时校验适合全局规则。不要每按一个键就向服务端校验复杂规则，除非做了防抖、取消和加载提示。

## 非受控输入

非受控组件把值交给 DOM 自己维护，提交时再读取。

```tsx
function FileForm() {
  const inputRef = React.useRef<HTMLInputElement | null>(null);

  function handleSubmit() {
    const file = inputRef.current?.files?.[0];
    console.log(file);
  }

  return <input ref={inputRef} type="file" />;
}
```

文件上传、简单表单、第三方控件集成，经常更适合非受控方式。它省心，但不适合复杂联动和实时校验。

非受控并不等于“不受管理”。它只是把当前值保存在 DOM 或第三方控件内部，React 在需要时通过 ref 读取。文件输入就是典型场景，因为浏览器不允许脚本随意设置文件路径。

```tsx
function UploadAvatar() {
  const inputRef = React.useRef<HTMLInputElement | null>(null);

  function clearFile() {
    if (inputRef.current) {
      inputRef.current.value = "";
    }
  }

  return (
    <>
      <input ref={inputRef} type="file" accept="image/png,image/jpeg" />
      <button type="button" onClick={clearFile}>清空</button>
    </>
  );
}
```

第三方富文本编辑器、地图选点、验证码控件也经常用非受控方式接入。接入时要明确两个边界：组件什么时候初始化和销毁，最终值什么时候同步回 React。

## 选择边界

| 场景 | 推荐 |
| --- | --- |
| 实时校验 | 受控 |
| 复杂联动 | 受控 |
| 文件选择 | 非受控 |
| 简单收集 | 两者都可 |
| 第三方控件 | 视控件 API |

判断标准是：React 是否需要实时知道这个值。如果需要，就受控；如果只在提交时读取，非受控也可以。

受控和非受控不要在同一个输入上来回切换。比如初始 `value` 是 `undefined`，后面变成字符串，React 会提示组件从非受控变成受控。解决方式是给受控输入明确默认值。

```tsx
const [name, setName] = React.useState("");

return <input value={name} onChange={(event) => setName(event.target.value)} />;
```

如果只是想设置初始值，但后续由 DOM 自己维护，应使用 `defaultValue` 或 `defaultChecked`。

```tsx
<input defaultValue="Ada" />
<input type="checkbox" defaultChecked />
```

`value` 表示 React 持续控制，`defaultValue` 表示只给初始值。这个差别是理解 React 表单的关键。

## 异步提交

异步提交要处理重复点击、错误回退和完成态。

```tsx
async function handleSubmit(event: React.FormEvent<HTMLFormElement>) {
  event.preventDefault();
  if (submitting) return;

  setSubmitting(true);
  try {
    await submitForm(form);
  } finally {
    setSubmitting(false);
  }
}
```

表单状态和 [[2.1.10 状态管理|状态管理]] 关系很近：字段值是局部状态，提交结果可能会影响页面级状态或服务端缓存。

异步提交还要处理服务端校验错误。前端本地校验只能拦截明显问题，真正的唯一性、权限、库存、风控规则仍然来自服务端。

```tsx
async function handleSubmit(event: React.FormEvent<HTMLFormElement>) {
  event.preventDefault();
  setSubmitting(true);
  setFormError(null);

  try {
    await submitForm(form);
  } catch (error) {
    setFormError("提交失败，请稍后重试");
  } finally {
    setSubmitting(false);
  }
}
```

提交中要禁用提交按钮，但不要盲目禁用所有输入。登录、支付、注册这类场景通常要阻止重复提交；搜索筛选、草稿保存这类场景则可能允许用户继续编辑，并取消或覆盖上一次请求。

大型项目里，表单库的价值不只是少写几行代码，而是统一字段注册、校验时机、错误展示、脏状态、嵌套字段和性能优化。是否引入表单库，要看表单复杂度和团队一致性，而不是看到两个输入框就上工具。
