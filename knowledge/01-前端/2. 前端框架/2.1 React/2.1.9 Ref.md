## 引用能力

Ref 用来保存不会因为变化而触发重渲染的值，最常见的用途是 DOM 引用、计时器 ID、上一次值和第三方实例。

```tsx
const timerRef = React.useRef<number | null>(null);
```

和 state 不同，ref 更适合保存“只给代码用、不直接展示在 UI 上”的数据。它像一个稳定的小盒子，内容可以变，但组件不会因为它变化而重画。

Ref 的核心特征是“稳定对象 + 可变 current”。组件重新渲染时，`useRef` 返回的仍然是同一个对象，所以它适合保存跨渲染存在、但不参与 UI 输出的值。

```tsx
function Stopwatch() {
  const startTimeRef = React.useRef<number | null>(null);

  function start() {
    startTimeRef.current = performance.now();
  }

  return <button onClick={start}>开始</button>;
}
```

如果页面需要展示经过的时间，仅仅更新 ref 不会让 UI 变化，还需要 state 或外部订阅触发渲染。Ref 保存事实，state 驱动界面，这条边界要分清。

## `useRef`

`useRef` 返回一个稳定对象，修改 `current` 不会触发渲染。

```tsx
function Counter() {
  const clicks = React.useRef(0);

  function handleClick() {
    clicks.current += 1;
    alert(`clicked ${clicks.current} times`);
  }

  return <button onClick={handleClick}>Click</button>;
}
```

如果这个值需要直接展示到界面上，就应该用 state，而不是 ref。

不要在渲染阶段读写会影响输出的 ref。虽然技术上能读 `ref.current`，但它的变化不会触发渲染，容易让 UI 和内部值不一致。

```tsx
function BadCounter() {
  const countRef = React.useRef(0);

  return (
    <button onClick={() => { countRef.current += 1; }}>
      {countRef.current}
    </button>
  );
}
```

按钮点击后 `current` 变了，但组件不一定重新渲染，界面可能仍然显示旧值。需要展示计数时，应该用 `useState`。

## DOM 引用

Ref 最常见的用途是直接拿到 DOM 节点。

```tsx
function SearchBox() {
  const inputRef = React.useRef<HTMLInputElement | null>(null);

  return (
    <>
      <input ref={inputRef} />
      <button onClick={() => inputRef.current?.focus()}>聚焦</button>
    </>
  );
}
```

DOM 引用适合聚焦、滚动、测量尺寸、播放控制这类需要直接操作原生元素的场景。

DOM ref 最好在事件处理器或 effect 中使用，而不是假设渲染期间它一定存在。首次渲染时，DOM 节点还没有挂载完成，`ref.current` 可能是 `null`。

```tsx
function AutoFocusInput() {
  const inputRef = React.useRef<HTMLInputElement | null>(null);

  React.useEffect(() => {
    inputRef.current?.focus();
  }, []);

  return <input ref={inputRef} />;
}
```

测量布局时也要注意时机。如果要在浏览器绘制前同步测量并更新布局，可能需要 `useLayoutEffect`；普通副作用和数据同步通常用 `useEffect` 就够了。

## `forwardRef`

`forwardRef` 可以把外部传下来的 ref 透传给内部元素。

```tsx
const Input = React.forwardRef<HTMLInputElement, { label: string }>(
  function Input({ label }, ref) {
    return (
      <label>
        {label}
        <input ref={ref} />
      </label>
    );
  },
);
```

它常用于组件库和基础交互组件，让外部还能获得输入框、按钮或容器节点。

`forwardRef` 会把组件从“纯 props 输入”扩展成“props + ref 输入”。这对组件库很重要，因为调用方可能需要聚焦输入框、测量容器、控制滚动位置。但业务组件不要随便暴露内部 DOM，否则内部结构一改，外部依赖就会断。

```tsx
const Button = React.forwardRef<HTMLButtonElement, React.ComponentProps<"button">>(
  function Button(props, ref) {
    return <button ref={ref} className="button" {...props} />;
  },
);
```

基础组件透传 ref 时，也要谨慎处理 props 展开顺序，避免调用方传入的属性覆盖组件必要的可访问性或安全属性。

## `useImperativeHandle`

`useImperativeHandle` 允许自定义暴露给父组件的命令式 API。

```tsx
type SearchHandle = {
  focus: () => void;
  clear: () => void;
};

const Search = React.forwardRef<SearchHandle, {}>(function Search(_, ref) {
  const inputRef = React.useRef<HTMLInputElement | null>(null);

  React.useImperativeHandle(ref, () => ({
    focus() {
      inputRef.current?.focus();
    },
    clear() {
      if (inputRef.current) {
        inputRef.current.value = "";
      }
    },
  }));

  return <input ref={inputRef} />;
});
```

这属于“逃生口”级别能力，适合确实需要命令式控制的场景，不适合把本来能用 props 解决的逻辑都改成命令式。

`useImperativeHandle` 暴露的 API 应该小而稳定，只暴露父组件确实需要的动作，而不是把内部 DOM 或完整实例直接暴露出去。

```tsx
type DialogHandle = {
  focusCloseButton: () => void;
};
```

如果父组件只是想控制弹窗开关，更好的 API 通常是 `open` 和 `onOpenChange`，而不是 `ref.current.open()`。命令式 API 适合聚焦、滚动、播放、清空这类本来就接近 DOM 或外部实例的动作。

## 适用边界

| 场景 | 更适合 |
| --- | --- |
| DOM 节点 | `ref` |
| 计时器 ID | `ref` |
| 实时输入展示 | `state` |
| 上一次 props | `ref` |
| 表单提交状态 | `state` |

一个简单判断是：值变了以后 UI 需不需要跟着变。需要就用 state，不需要就考虑 ref。

Ref 还适合保存上一次值，用于比较变化。

```tsx
function usePrevious<T>(value: T) {
  const ref = React.useRef<T | undefined>(undefined);

  React.useEffect(() => {
    ref.current = value;
  }, [value]);

  return ref.current;
}
```

这种 Hook 不会触发额外渲染，只是在渲染之间保存上一轮数据。它适合调试变化、动画过渡、比较 props，但不要用它绕过正常数据流。

定时器 ID、请求控制器、外部实例都适合放 ref，因为它们需要跨事件和 effect 保存，但变化本身不应该直接驱动 UI。

## 与副作用关系

ref 常和 [[2.1.8 副作用|副作用]] 一起使用。effect 负责同步外部系统，ref 负责保存不会触发渲染的对象或节点。两者分工清楚，组件更稳。

第三方库接入时，ref 通常承担两个角色：DOM 容器引用和实例引用。DOM 容器给第三方库挂载，实例引用用于后续更新和销毁。

```tsx
function MapView({ center }: { center: [number, number] }) {
  const containerRef = React.useRef<HTMLDivElement | null>(null);
  const mapRef = React.useRef<MapInstance | null>(null);

  React.useEffect(() => {
    if (!containerRef.current) return;

    mapRef.current = createMap(containerRef.current);
    return () => {
      mapRef.current?.destroy();
      mapRef.current = null;
    };
  }, []);

  React.useEffect(() => {
    mapRef.current?.setCenter(center);
  }, [center]);

  return <div ref={containerRef} />;
}
```

这个模式比把第三方实例塞进 state 更合适，因为实例变化不需要触发 React 渲染。React 负责声明 UI 边界，ref 负责连接命令式世界。
