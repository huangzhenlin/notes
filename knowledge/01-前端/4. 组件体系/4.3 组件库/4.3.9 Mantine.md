## 库概况

Mantine 是面向 React 的现代组件库，强调开发体验、主题系统、Hook 生态和较强的定制能力。它更适合想要快速搭建产品界面，同时又不想被非常强势的企业视觉风格锁死的团队。

Mantine 的优势在于组件体验相对现代、样式和主题可控、和 React 组合顺手。它适合 SaaS、后台、管理界面、工作台类项目，也适合需要较强二次设计的产品。

Mantine 在 React 社区里经常被拿来作为“比传统企业组件库更灵活、比手写 UI 基础设施更省事”的中间选项。它很适合团队希望控制视觉，又不想从零处理大量底层交互细节的场景。

Mantine 的整体气质比较“产品型”，既没有太重的设计包袱，也没有完全放任你自己造轮子。对于希望快速稳定出界面的 React 团队，它是很平衡的一类选择。

Mantine 的另一个特点，是它比较强调可组合和可定制，这对希望在统一基座上继续长出业务组件的团队很友好。它不太像那种“默认长相极强”的库，因此适合做品牌化定制或产品视觉统一。

但它也意味着团队要自己更主动地定义设计边界。如果没有先约定主题、按钮层级、表单间距和交互反馈，Mantine 的灵活性会让页面风格逐渐分散。

## 组件清单

#### 基础与布局

| 组件 | 作用 | 基础用法 |
| --- | --- | --- |
| Button | 操作按钮 | `variant`、`size` |
| Group | 元素横向排列 | `gap`、`justify` |
| Stack | 元素纵向排列 | `gap` |
| Center | 居中布局 | `inline`、`w` |
| Container | 宽度控制 | `size` |
| Paper | 内容容器 | `shadow`、`radius` |

```tsx
import { Button, Group, Paper, Stack, Text } from "@mantine/core";

export function Toolbar() {
  return (
    <Paper p="md" radius="md" shadow="sm">
      <Group justify="space-between">
        <Text fw={600}>用户管理</Text>
        <Button>新建用户</Button>
      </Group>
    </Paper>
  );
}
```

布局组件适合搭建控制台、卡片区、工具栏和设置页。`Group` 与 `Stack` 能明显减少手写 flex 的样板，让页面结构读起来更像组件语义。

Mantine 的基础能力通常先从这些开始比较顺手：

```text
布局：Group / Stack / Center / Container / Paper
表单：TextInput / Select / NumberInput / PasswordInput / DatePicker
反馈：Modal / Drawer / Popover / Tooltip / Notification / Alert
展示：Table / Badge / Tabs / Pagination / Progress / Avatar
```

它的很多组件 API 比较现代，和 React Hook Form、Zod、表单草稿、主题切换这些场景组合起来很自然。

#### 表单输入

| 组件 | 作用 | 基础用法 |
| --- | --- | --- |
| TextInput | 文本输入 | `label`、`placeholder` |
| PasswordInput | 密码输入 | `visible`、`label` |
| NumberInput | 数字输入 | `min`、`max` |
| Select | 下拉选择 | `data`、`value` |
| Checkbox | 勾选 | `checked` |
| Radio | 单选 | `Radio.Group` |
| Switch | 开关 | `checked` |
| DatePicker | 日期选择 | `value`、`onChange` |
| FileInput | 文件输入 | `accept` |

```tsx
import { TextInput, Select, Stack } from "@mantine/core";

export function UserForm() {
  return (
    <Stack>
      <TextInput label="用户名" placeholder="请输入用户名" />
      <Select label="角色" data={["admin", "member"]} />
    </Stack>
  );
}
```

Mantine 的表单输入组件适合和它自己的 form 能力或 React Hook Form 一起使用。组件库负责视觉和交互，表单工具负责值管理、校验和提交。

#### 覆盖层与反馈

| 组件 | 作用 | 基础用法 |
| --- | --- | --- |
| Modal | 模态弹窗 | `opened`、`onClose` |
| Drawer | 抽屉 | `opened`、`position` |
| Popover | 浮层 | `opened` |
| Tooltip | 提示 | `label` |
| Notification | 通知 | `notifications.show()` |
| Alert | 内联提示 | `color`、`title` |
| LoadingOverlay | 加载遮罩 | `visible` |

覆盖层和反馈组件适合处理“用户动作后的即时响应”，例如保存成功、提交失败、抽屉编辑、弹窗确认。项目里最好统一封装通知和确认入口，避免每个页面自己定义反馈风格。

#### 数据与工具

| 组件 | 作用 | 基础用法 |
| --- | --- | --- |
| Table | 表格 | `data`、`columns` |
| Badge | 状态标签 | `color` |
| Tabs | 分页切换 | `value` |
| Pagination | 分页器 | `value`、`onChange` |
| Progress | 进度条 | `value` |
| Avatar | 头像 | `src`、`name` |

数据展示组件覆盖的是常见产品页面的基础需求。若项目需要复杂表格、列拖拽、虚拟滚动和服务端筛选，通常还要搭配 TanStack Table 或自研业务表格。

Mantine 的组件清单不只是“有这些组件”，更重要的是它把常见布局、反馈和表单能力组合得比较顺手。对于 React 项目来说，这能显著减少自己拼 flex、间距和状态反馈的时间。

如果项目高度依赖中后台模板、复杂表格和企业级统一视觉，Mantine 适合做快速起步；如果项目要求和现有 Ant Design 生态兼容，就要额外评估替换成本。它的优势是灵活，不是天然兼容一切既有后台体系。

Mantine 很适合做“产品视觉统一 + 业务组件二次封装”的底座。比如你可以先封装 `AppButton`、`AppField`、`AppModal`、`AppEmpty`，再把项目里的视觉和交互习惯统一起来。

## 适用与使用

Mantine 适合 React 项目中想要较强可定制性、现代 API 和较完整基础组件的团队。它比一些强风格化组件库更灵活，也比手写 UI 基础设施更省时。

如果项目需要自己控制品牌视觉、希望快速封装业务组件，Mantine 很合适。若项目已经被 Ant Design 的后台语义或 MUI 的 Material 体系强绑定，则未必值得迁移。

它也比较适合希望逐步建立自己的设计语言，而不是完全套用某个强视觉体系的团队。只要前期把主题、空间、字体和状态规范定住，Mantine 的灵活度会更有帮助。

Mantine 更适合新项目或想要较强视觉自由度的团队。它既能做通用后台，也能往更产品化、更轻量的界面风格上走。

使用 Mantine 时，建议先定好主题、颜色和间距规则，再逐步封装业务组件。这样既能保留灵活性，也不至于让页面样式过度发散。 

如果团队成员会频繁写自定义样式，Mantine 的主题和组件属性约定会比散写 CSS 更容易收口。它的价值在于让你保持“灵活但不混乱”。

使用时最好把它和自己的业务组件体系一起规划，而不是直接把页面都散落在组件库 API 上。比如按钮、表单项、状态标签、空态、通知这些高频能力，先在业务层封装一层，后续换主题、改视觉、做埋点会更轻松。

Mantine 也适合和 TanStack Table、React Hook Form、Zod 这类工具组合。它本身提供的是比较完整的 UI 基础，真正的复杂行为可以交给更专门的工具去做。
