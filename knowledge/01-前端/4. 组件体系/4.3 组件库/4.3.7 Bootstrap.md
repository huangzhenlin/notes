## 库概况

Bootstrap 是历史非常悠久的前端 UI 框架，由 Bootstrap 团队和社区维护。它不绑定 React 或 Vue，核心能力是响应式栅格、工具类、基础样式、组件样式和少量 JavaScript 插件。

它的优势是简单、稳定、文档成熟、上手快。很多传统服务端渲染页面、官网、后台原型和低复杂度业务页面都会使用 Bootstrap 或受它影响的栅格/工具类模式。

Bootstrap 的设计思路很直接：先把排版、间距、栅格、按钮、表单和常见反馈做成通用方案，再让开发者通过类名快速拼出页面。它更像一套“页面搭建语言”，而不是一套重型组件运行时。

这也是 Bootstrap 经久不衰的原因之一。它不要求你完全接受某种框架心智，而是直接给你一套能工作的布局和样式基础。

Bootstrap 的现代版本还提供了比较完整的 JavaScript 插件和组件样式体系，但它最强的地方仍然是布局、工具类和快速成型。如果团队想要的是稳定、简单、传统 Web 页面快速落地，它仍然很有价值。

```text
Bootstrap 的核心价值：
1. 快速成型
2. 响应式布局
3. 统一基础样式
4. 不强绑定框架
```

## 组件清单

#### 布局与排版

| 能力 | 作用 | 基础用法 |
| --- | --- | --- |
| Container | 内容宽度约束 | `container`、`container-fluid` |
| Grid | 响应式栅格 | `row`、`col-*` |
| Columns | 列宽分配 | `col-md-6` |
| Gutters | 控制列间距 | `g-3` |
| Flex | 弹性布局 | `d-flex`、`justify-content-between` |
| Spacing | 间距控制 | `mt-3`、`py-4` |
| Display | 显示控制 | `d-none`、`d-md-block` |
| Position | 定位 | `position-relative` |

```html
<div class="container py-4">
  <div class="row g-3 align-items-center">
    <div class="col-12 col-md-8">
      <h2 class="mb-0">订单列表</h2>
    </div>
    <div class="col-12 col-md-4 text-md-end">
      <button class="btn btn-primary">新建订单</button>
    </div>
  </div>
</div>
```

Grid 是 Bootstrap 的基础能力。只要布局诉求清晰，很多页面根本不需要写复杂自定义 CSS。

栅格适合快速处理响应式骨架，例如桌面三栏、平板两栏、手机单栏。对内容型网站和传统后台来说，它的收益非常直接。

Bootstrap 里最常用、最值得先掌握的能力基本就是：

```text
布局：Container / Grid / Flex / Spacing / Display
表单：Form Control / Input Group / Floating Labels
反馈：Button / Badge / Alert / Modal / Toast / Offcanvas
```

只要把这些基础能力吃透，大部分模板页面就能很快拼出来。

#### 表单与输入

| 组件 | 作用 | 基础用法 |
| --- | --- | --- |
| Form Control | 文本输入 | `form-control` |
| Input Group | 输入组合 | `input-group` |
| Select | 下拉选择 | `form-select` |
| Checks | 复选/单选 | `form-check` |
| Range | 滑杆输入 | `form-range` |
| Floating Labels | 漂浮标签 | `form-floating` |

```html
<div class="mb-3">
  <label class="form-label">关键词</label>
  <input class="form-control" placeholder="请输入关键词" />
</div>

<div class="input-group">
  <span class="input-group-text">@</span>
  <input class="form-control" placeholder="用户名" />
</div>
```

Bootstrap 的表单更偏静态结构和视觉统一。如果要做复杂校验、联动和受控表单，通常还是要配合框架层状态管理。

所以 Bootstrap 表单适合“样式统一”，不负责“状态建模”。表单值、校验、提交和错误回填，仍然应该交给框架、表单库或服务端模板逻辑。

#### 反馈与组件

| 组件 | 作用 | 基础用法 |
| --- | --- | --- |
| Button | 操作按钮 | `btn`、`btn-primary` |
| Badge | 标记数量或状态 | `badge` |
| Alert | 警告和提示 | `alert` |
| Card | 内容卡片 | `card` |
| Navbar | 顶部导航 | `navbar` |
| Dropdown | 下拉菜单 | `dropdown-menu` |
| Modal | 对话框 | `modal` |
| Offcanvas | 侧滑面板 | `offcanvas` |
| Toast | 提示消息 | `toast` |
| Accordion | 折叠面板 | `accordion` |
| Tabs | 标签页 | `nav-tabs` |

```html
<div class="alert alert-warning" role="alert">
  当前配置尚未保存。
</div>

<button class="btn btn-outline-secondary" data-bs-toggle="modal" data-bs-target="#demoModal">
  打开弹窗
</button>
```

如果项目使用 React/Vue，Modal、Dropdown、Tabs 这类依赖 DOM 状态的插件要特别谨慎。框架组件状态和 Bootstrap 插件状态如果同时管理一个弹层，很容易互相打架。

使用 Bootstrap 时，一个常见实践是把它当作样式与布局底盘，而不是所有交互都交给插件。尤其在 React/Vue 中，Modal、Dropdown、Tabs 这种组件更适合由框架状态控制显示隐藏，Bootstrap 只负责样式和基础结构。

```text
适合：栅格、间距、排版、基础按钮、表单样式
谨慎：复杂受控弹层、深度联动菜单、状态频繁变化的组件
```

#### 工具类

| 类别 | 作用 | 常见类名 |
| --- | --- | --- |
| 间距 | 快速调整留白 | `mt-3`、`px-2` |
| 字体 | 文本强调和对齐 | `fw-bold`、`text-center` |
| 颜色 | 状态与语义色 | `text-muted`、`bg-primary` |
| 圆角阴影 | 容器修饰 | `rounded`、`shadow` |
| 响应式 | 断点控制 | `d-md-none`、`col-lg-4` |

```html
<div class="d-flex gap-2 justify-content-end">
  <button class="btn btn-secondary">取消</button>
  <button class="btn btn-primary">保存</button>
</div>
```

Bootstrap 的工具类是它最强的部分之一。很多页面如果只是需要“快速排版”，甚至只靠工具类就能完成大部分工作。

工具类的价值在于让很多样式意图变成可读类名，而不是散落在 CSS 文件里。对原型、活动页和传统模板项目来说，这种效率非常高。

## 适用与使用

Bootstrap 适合快速原型、传统模板页面、内容型网站、响应式布局和低复杂度后台。它也适合后端同学参与页面开发，因为不需要完整掌握 React/Vue 组件模型。

如果团队需要的是“快做出来、样式稳定、维护成本低”，Bootstrap 依然很有竞争力。它尤其适合服务器渲染页面和 HTML 模板驱动的项目。

如果在 React/Vue 项目里使用 Bootstrap，要特别注意 JavaScript 插件和框架状态的关系。推荐优先使用它的布局和样式能力，谨慎把 DOM 状态交给插件直接操作。

如果项目需要复杂表单联动、受控弹窗、重型表格和统一业务组件体系，Ant Design、Element Plus、MUI 这类框架绑定组件库会更合适。

Bootstrap 更适合“页面快速成型”，不是“深度定制 UI 体系”的首选。 

如果项目后期要建立强设计系统、统一组件语义和复杂交互，Bootstrap 往往只适合作为基础排版层，而不是最终的业务组件体系。 

它更像一个稳定的起点，而不是终点。如果团队后期逐渐走向更强的前端应用化、组件化和业务状态管理，Bootstrap 常常会从页面样式底盘演进成项目早期加速器，而不是长期主库。
