## 库概况

MUI 是 React 生态里最有代表性的 Material Design 组件库。官方展示页里能看到 QuintoAndar、OpenClassrooms、Bethesda.net、GovX 等公开应用案例。它的核心优势是设计体系成熟、主题能力完整、国际化和企业级场景适配较好。

和很多“组件集合”不同，MUI 更像一套完整的视觉语言实现。如果项目接受 Material 风格，MUI 往往能很快搭出统一产品界面。

MUI 的生态还包含 Material UI、Joy UI、Base UI 和 MUI X 等不同层次。Material UI 适合直接使用 Material 风格组件；Base UI 更偏无样式原语；MUI X 则覆盖 Data Grid、Date Pickers 等更复杂的企业组件。选用时要先判断自己是要完整视觉体系，还是要可自定义原语。

```text
Material UI：默认视觉完整，适合快速搭建产品
Base UI：更少样式约束，适合自定义设计体系
MUI X：复杂表格、日期、图表等企业级扩展
```

## 组件清单

#### 基础与布局

| 组件 | 作用 | 基础用法 |
| --- | --- | --- |
| Button | 发起操作 | `variant`、`color` |
| Typography | 文本层级 | `variant`、`component` |
| Box | 通用容器 | `sx`、布局包裹 |
| Stack | 一维布局 | `direction`、`spacing` |
| Grid | 响应式布局 | `container`、`item` |
| Container | 内容宽度约束 | `maxWidth` |
| Paper | 浮层/卡片底板 | `elevation` |
| Divider | 区块分隔 | `orientation` |

```tsx
import { Button, Stack, Typography } from "@mui/material";

export default function Header() {
  return (
    <Stack direction="row" justifyContent="space-between" alignItems="center">
      <Typography variant="h6">订单列表</Typography>
      <Button variant="contained">新建订单</Button>
    </Stack>
  );
}
```

#### 表单输入

| 组件 | 作用 | 基础用法 |
| --- | --- | --- |
| TextField | 输入与标签的基础封装 | `label`、`helperText` |
| Select | 下拉选择 | `value`、`onChange` |
| Checkbox | 勾选 | `checked` |
| Radio | 单选 | `RadioGroup` |
| Switch | 开关 | `checked` |
| Slider | 数值滑块 | `value` |
| Autocomplete | 搜索选择 | `options`、`renderInput` |
| FormControl | 表单结构 | `error`、`fullWidth` |
| InputLabel | 输入标签 | `shrink` |

```tsx
import { Button, MenuItem, Stack, TextField } from "@mui/material";

export default function SearchForm() {
  return (
    <Stack spacing={2}>
      <TextField label="关键词" placeholder="请输入关键词" />
      <TextField label="状态" select defaultValue="enabled">
        <MenuItem value="enabled">启用</MenuItem>
        <MenuItem value="disabled">禁用</MenuItem>
      </TextField>
      <Button variant="contained">查询</Button>
    </Stack>
  );
}
```

#### 数据展示

| 组件 | 作用 | 基础用法 |
| --- | --- | --- |
| Table | 表格展示 | `TableHead`、`TableBody` |
| Card | 卡片容器 | `CardContent` |
| Chip | 标签/状态 | `label`、`color` |
| Avatar | 头像 | `src`、`alt` |
| List | 列表 | `ListItem` |
| Badge | 数量提醒 | `badgeContent` |
| Skeleton | 占位加载 | `variant` |
| Tooltip | 说明提示 | `title` |

```tsx
import { Chip, Table, TableBody, TableCell, TableRow } from "@mui/material";

export default function UserTable() {
  return (
    <Table>
      <TableBody>
        <TableRow>
          <TableCell>Alice</TableCell>
          <TableCell><Chip label="启用" color="success" /></TableCell>
        </TableRow>
      </TableBody>
    </Table>
  );
}
```

#### 导航与反馈

| 组件 | 作用 | 基础用法 |
| --- | --- | --- |
| AppBar | 顶部栏 | `position` |
| Tabs | 内容切换 | `value`、`onChange` |
| Drawer | 侧栏抽屉 | `open`、`onClose` |
| Menu | 菜单 | `anchorEl`、`open` |
| Breadcrumbs | 路径导航 | 子项组合 |
| Pagination | 分页 | `page` |
| Dialog | 对话框 | `open`、`onClose` |
| Snackbar | 消息提示 | `open`、`autoHideDuration` |
| Alert | 内联提示 | `severity` |
| Backdrop | 遮罩 | `open` |
| CircularProgress | 加载 | `size` |

```tsx
import { Alert, Snackbar } from "@mui/material";

<Snackbar open={open} autoHideDuration={3000}>
  <Alert severity="success">保存成功</Alert>
</Snackbar>
```

MUI 项目里最常被优先掌握的组件通常是 `Box`、`Stack`、`Typography`、`Button`、`TextField`、`Dialog`、`Snackbar` 和 `Table`。其中 `Box` 和 `sx` 是它的日常布局与局部样式入口，理解它们能明显提高开发效率。

```text
高频能力：
1. Box + sx
2. Stack / Grid / Container
3. TextField / Dialog / Snackbar
4. Table / Autocomplete / Menu
```

`sx` 很方便，但也要控制使用范围。高频样式应该进入主题或封装组件，不要让每个页面都用 `sx` 手写一套视觉规范。

```tsx
<Box
  sx={{
    display: "grid",
    gap: 2,
    p: 3,
    bgcolor: "background.paper",
    borderRadius: 2,
  }}
>
  <Typography variant="h6">账户设置</Typography>
  <TextField label="邮箱" />
</Box>
```

## 适用与使用

MUI 适合 React 项目、国际化产品、Material Design 风格应用，以及需要较成熟主题系统的企业软件。它也适合团队希望在“默认好看”和“可定制”之间取得平衡。

推荐的落地方式是先统一主题，再少量使用 `sx` 做局部调整：

```tsx
const theme = createTheme({
  palette: { primary: { main: "#0f766e" } },
  shape: { borderRadius: 8 },
});
```

如果项目不想要 Material 风格，或者追求极轻包体和纯无样式原语，MUI 就不一定合适。它更适合接受完整体系、并愿意围绕主题做长期建设的团队。

落地 MUI 时，推荐先配置主题，再封装项目级组件。比如统一按钮大小、表单间距、对话框宽度和 Snackbar 出现位置。这样业务页面不用每次都写 `sx`，视觉也不容易漂。

```tsx
const theme = createTheme({
  palette: {
    primary: { main: "#0f766e" },
    error: { main: "#dc2626" },
  },
  components: {
    MuiButton: {
      defaultProps: { disableElevation: true },
    },
  },
});
```

如果项目需要非常强的中国式中后台表格、筛选和密集表单，MUI 也能做，但默认风格和交互密度可能需要调整。选型时要同时评估“设计语言是否匹配”和“团队是否愿意维护主题体系”。

MUI 适合的项目通常是国际化产品、SaaS、全球化后台、Material 风格应用以及愿意围绕主题长期演进的团队。它的价值在于完整，但也意味着你要接受一套比较明确的设计语言。
