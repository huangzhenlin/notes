## 库概况

Vant 是一个轻量、可靠的移动端组件库，官方最早在 2017 年开源，支持 Vue 2、Vue 3 和微信小程序版本，社区也有 React 与支付宝小程序相关实现。它的定位非常明确：服务移动端 H5 和小程序。

它的优势不是桌面端通用性，而是移动体验天然更顺手，包含触控、弹层、列表、选择器、输入等一整套移动端常用组件。

Vant 的设计思路很偏“移动端业务落地”。它不会刻意追求桌面复杂布局，而是把手机上最常见的入口、表单、列表、动作面板和反馈交互做得非常顺。

它的典型使用场景包括电商 H5、活动页、订单页、会员中心、移动端表单、WebView 内嵌页和小程序页面。和桌面中后台组件库相比，Vant 更关注触控、底部弹层、下拉刷新、滚动加载、安全区和移动端输入体验。

```text
桌面中后台：表格、筛选、侧边栏、复杂表单
移动端 H5：卡片、列表、底部操作、弹层、选择器、Toast
```

如果页面主要运行在手机上，直接使用桌面组件库会显得笨重；Vant 这类移动端库能让交互更贴近用户习惯。

## 组件清单

#### 基础与布局

| 组件 | 作用 | 基础用法 |
| --- | --- | --- |
| Button | 触发操作 | `block`、`type` |
| Icon | 图标 | `name` |
| Cell | 移动端列表项 | `title`、`value`、`is-link` |
| ConfigProvider | 全局配置 | 主题和尺寸控制 |
| Layout | 页面布局 | 适合和导航组合 |
| Grid | 九宫格入口 | `column-num` |
| Space | 间距控制 | `direction` |
| Image | 图片展示 | `fit`、`lazy-load` |
| Popup | 弹层基础 | `position`、`round` |

```vue
<template>
  <van-cell title="收货地址" value="北京市" is-link />
  <van-button block type="primary">提交订单</van-button>
</template>
```

像 `Cell`、`Popup`、`Tabbar`、`NavBar` 这类组件，往往比桌面库里的对应组件更贴近手机交互。移动端页面如果能复用这些语义，很多布局和操作就会自然很多。

#### 表单输入

| 组件 | 作用 | 基础用法 |
| --- | --- | --- |
| Form | 表单容器 | `@submit` |
| Field | 输入框封装 | `label`、`placeholder` |
| Picker | 选择器 | `columns` |
| Calendar | 日历选择 | `v-model` |
| Checkbox | 多选 | `v-model` |
| Radio | 单选 | `v-model` |
| Switch | 开关 | `v-model` |
| Stepper | 数量输入 | `v-model` |
| Uploader | 文件上传 | `after-read` |
| Rate | 评分 | `v-model` |

```vue
<template>
  <van-form @submit="onSubmit">
    <van-cell-group inset>
      <van-field
        v-model="name"
        name="name"
        label="姓名"
        placeholder="请输入姓名"
        :rules="[{ required: true, message: '请填写姓名' }]"
      />
    </van-cell-group>
    <van-button block type="primary" native-type="submit">提交</van-button>
  </van-form>
</template>
```

表单类组件在移动端尤其要注意键盘、滚动和焦点。Vant 的输入组件通常已经为手机上的输入体验做了不少收口，比手写原生表单更稳。

#### 数据展示

| 组件 | 作用 | 基础用法 |
| --- | --- | --- |
| List | 滚动加载列表 | `v-model:loading`、`finished` |
| Card | 内容卡片 | `title`、`desc` |
| Tag | 状态标签 | `type` |
| Badge | 数量角标 | `content` |
| NoticeBar | 顶部通知 | `text` |
| Skeleton | 骨架屏 | `row` |
| Empty | 空状态 | 插槽 |
| Progress | 进度条 | `percentage` |
| Circle | 环形进度 | `percentage` |
| CountDown | 倒计时 | `time` |

```vue
<template>
  <van-list v-model:loading="loading" :finished="finished" @load="loadMore">
    <van-cell v-for="item in list" :key="item.id" :title="item.title" />
  </van-list>
</template>
```

`List`、`Skeleton`、`Empty` 这类组件对移动端尤其关键，因为 H5 页面常常要面对弱网和长列表。把加载、空态、继续加载写清楚，页面体感会好很多。

#### 导航与反馈

| 组件 | 作用 | 基础用法 |
| --- | --- | --- |
| NavBar | 顶部导航栏 | `title`、`left-arrow` |
| Tabbar | 底部导航 | `route`、`v-model` |
| Tabs | 内容切换 | `v-model` |
| DropdownMenu | 下拉菜单 | `v-model`、`options` |
| Sidebar | 侧边导航 | `v-model` |
| Dialog | 对话框 | `v-model:show` |
| Toast | 轻提示 | `showToast()` |
| Notify | 顶部通知 | `showNotify()` |
| ActionSheet | 底部动作面板 | `actions` |
| Loading | 加载提示 | `type` |
| PullRefresh | 下拉刷新 | `v-model` |

```vue
<template>
  <van-nav-bar title="订单详情" left-arrow />
  <van-popup v-model:show="show" position="bottom">
    <van-picker :columns="columns" />
  </van-popup>
</template>
```

Vant 里最值得优先掌握的组件通常是 `Cell`、`Button`、`Field`、`Form`、`Popup`、`Picker`、`List`、`PullRefresh`、`Tabbar`、`Toast`、`Dialog` 和 `ActionSheet`。这些组件基本覆盖了移动端业务页面的骨架。

```vue
<template>
  <van-pull-refresh v-model="refreshing" @refresh="refresh">
    <van-list v-model:loading="loading" :finished="finished" @load="loadMore">
      <van-cell v-for="item in list" :key="item.id" :title="item.title" />
    </van-list>
  </van-pull-refresh>
</template>
```

移动端列表最好把刷新、加载更多、空态和失败重试一起设计。只做正常列表，弱网或分页失败时体验会很脆。

Vant 的导航和反馈组件往往会和移动端壳层一起用，比如底部 Tabbar、顶部 NavBar、弹窗、动作面板和 Toast。它们最适合放进项目统一封装层，而不是每个页面自己拼。

## 适用与使用

Vant 适合移动 Web、H5 活动页、WebView 内嵌页、微信小程序和轻量业务系统。它不适合桌面中后台，也不适合重表格、重导航的管理平台。

如果项目主要面向手机用户，且页面以列表、表单、详情、弹层、底部操作为主，Vant 往往是很顺手的默认选择。它的价值就在于把“移动端常见 UI”快速标准化。

使用时要特别注意移动端的几个点：

```text
触控区域是否足够
弹层是否挡住键盘
滚动是否穿透
是否适配安全区
```

推荐把它和项目级移动组件一起封装，例如统一导航栏、统一表单壳、统一底部操作区。这样既能保持移动端体验，又能把业务默认值和主题控制住。

如果项目后续还会接微信小程序或 WebView 容器，Vant 的语义也更容易迁移，因为它本身就偏向移动端通用表达，而不是桌面端重型结构。

使用 Vant 时要特别注意容器环境。H5 在浏览器、App WebView、微信内置浏览器、小程序 WebView 中的表现可能不同，尤其是安全区、键盘顶起、滚动穿透、固定底部按钮和弹层层级。

```css
.safe-footer {
  padding-bottom: calc(12px + env(safe-area-inset-bottom));
}
```

如果项目既有 H5 又有小程序，建议把导航栏、底部操作栏、表单壳、列表页骨架这些高频结构再封一层项目组件。这样底层库变化或平台差异不会直接散落到每个页面。
