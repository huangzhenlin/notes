## 库概况

Element Plus 是 Vue 3 里最常见的中后台组件库之一，延续了 Element 系列在企业后台里的使用习惯。它的目标很明确：让 Vue 团队快速搭建稳定、熟悉、可维护的后台界面。

它的优势在于成熟度高、组件覆盖完整、中文生态熟、文档和约定比较统一，特别适合传统后台、表单密集、列表密集的项目。

它的使用体验很“后台友好”：表单、表格、弹窗、分页、树、选择器这些高频场景都很完整，适合需要快速搭建管理界面的团队。对于 Vue 团队来说，它最大的价值往往不是“最漂亮”，而是“最省沟通成本”。

Element Plus 也很适合和项目自己的封装层一起用。很多团队会在其上再包一层 `BaseButton`、`BaseForm`、`PageTable`，把权限、埋点、默认布局和统一文案收口。

## 组件清单

#### 基础与布局

| 组件 | 作用 | 基础用法 |
| --- | --- | --- |
| Button | 触发操作，区分主次和危险操作 | `type="primary"`、`plain`、`disabled` |
| Text | 承载普通文本或状态文本 | 直接包裹内容 |
| Link | 表达跳转或外链 | `type="primary"`、`href` |
| Space | 统一控制元素间距 | `align`、`direction` |
| Layout | 页面骨架布局 | `el-container`、`el-aside`、`el-main` |
| Container | 约束内容宽度 | 搭配 Layout 使用 |

```vue
<template>
  <el-space>
    <el-button>默认</el-button>
    <el-button type="primary">保存</el-button>
    <el-button type="danger" plain>删除</el-button>
  </el-space>
</template>
```

```vue
<template>
  <el-container>
    <el-aside width="220px">侧边栏</el-aside>
    <el-main>页面内容</el-main>
  </el-container>
</template>
```

#### 表单输入

| 组件 | 作用 | 基础用法 |
| --- | --- | --- |
| Form | 表单布局和校验容器 | `:model`、`label-width`、`prop` |
| Input | 单行文本输入 | `v-model`、`placeholder` |
| Select | 下拉选择 | `el-option`、`multiple` |
| DatePicker | 日期与时间选择 | `type`、`value-format` |
| Checkbox | 单选/多选切换 | `v-model`、`label` |
| Radio | 单选项组 | `el-radio-group` |
| Switch | 开关状态 | `active-text`、`inactive-text` |
| Upload | 文件上传 | `action`、`multiple`、`before-upload` |
| Cascader | 级联选择 | `:options`、`show-all-levels` |
| TreeSelect | 树形下拉选择 | `multiple`、`check-strictly` |

```vue
<template>
  <el-form :model="form" label-width="80px">
    <el-form-item label="名称" prop="name">
      <el-input v-model="form.name" placeholder="请输入名称" />
    </el-form-item>
    <el-form-item label="状态">
      <el-select v-model="form.status" placeholder="请选择">
        <el-option label="启用" value="enabled" />
        <el-option label="禁用" value="disabled" />
      </el-select>
    </el-form-item>
  </el-form>
</template>
```

#### 数据展示

| 组件 | 作用 | 基础用法 |
| --- | --- | --- |
| Table | 表格列表和列渲染 | `:data`、`el-table-column` |
| Pagination | 分页控制 | `:total`、`current-page` |
| Tree | 树形数据展示 | `node-key`、`show-checkbox` |
| Descriptions | 详情字段展示 | `:column`、`el-descriptions-item` |
| Tag | 状态标签 | `type`、`effect` |
| Card | 内容卡片容器 | `header`、默认插槽 |
| Empty | 空状态 | `description`、插槽 |
| Skeleton | 加载骨架屏 | `rows`、`animated` |
| Progress | 进度展示 | `percentage`、`status` |

```vue
<template>
  <el-table :data="users">
    <el-table-column prop="name" label="姓名" />
    <el-table-column prop="role" label="角色" />
    <el-table-column label="状态">
      <template #default="{ row }">
        <el-tag :type="row.enabled ? 'success' : 'info'">
          {{ row.enabled ? "启用" : "禁用" }}
        </el-tag>
      </template>
    </el-table-column>
  </el-table>
  <el-pagination :total="100" layout="prev, pager, next" />
</template>
```

#### 导航与反馈

| 组件 | 作用 | 基础用法 |
| --- | --- | --- |
| Menu | 侧边或顶部导航 | `:default-active`、`router` |
| Tabs | 内容分区切换 | `v-model`、`el-tab-pane` |
| Breadcrumb | 层级路径 | `el-breadcrumb-item` |
| Dropdown | 下拉菜单 | `el-dropdown-item` |
| Steps | 流程步骤 | `:active` |
| Dialog | 模态对话框 | `v-model`、`title` |
| Drawer | 侧边抽屉 | `size`、`direction` |
| Message | 全局提示 | `ElMessage.success()` |
| Notification | 通知提醒 | `ElNotification` |
| Tooltip | 悬浮提示 | `content`、`placement` |
| Popconfirm | 二次确认 | `title`、`confirm-button-text` |

```vue
<template>
  <el-tabs v-model="activeName">
    <el-tab-pane label="概览" name="overview" />
    <el-tab-pane label="明细" name="detail" />
  </el-tabs>

  <el-dialog v-model="open" title="编辑用户">
    <span>表单内容</span>
  </el-dialog>
</template>
```

下面这些组件通常是 Element Plus 项目里最常用、也最值得先掌握的：

```text
按钮与布局：Button / Space / Container / Layout
表单输入：Form / Input / Select / DatePicker / Upload
数据展示：Table / Pagination / Tag / Card / Descriptions
交互反馈：Dialog / Drawer / Message / Notification / Tooltip
```

这些组件覆盖了大多数后台系统的主流程：筛选、编辑、提交、确认、列表展示和状态反馈。

## 适用与使用

Element Plus 适合 Vue 3 中后台、管理系统、内部平台、表单密集型应用。尤其适合团队希望减少视觉分歧、直接使用成熟后台组件语义的情况。

它特别适合“业务比视觉更重要”的项目。也就是说，当团队更在意表单填写、权限控制、列表查询、弹窗确认和流程稳定，而不是极强的品牌视觉表达时，Element Plus 往往是高性价比答案。

使用时建议先做三层封装：

```text
Element Plus 基础组件
  -> 项目统一封装组件
  -> 页面级业务组件
```

这样可以把权限、埋点、默认尺寸、主题覆盖和业务默认值收口，不让每个页面都直接碰底层组件。真正需要深度定制时，优先用全局配置、CSS 变量和组件级扩展点，而不是覆盖内部 DOM。

如果项目需要做品牌化改造，Element Plus 也比较适合通过主题变量和局部封装慢慢改，而不是一次性推翻重来。它的风险在于风格偏“企业后台标准化”，如果你追求极强的个性化设计，后期改造成本会明显上升。
