## 绝对单位

CSS 中最常用的长度单位是 `px`。它不是物理像素，而是 CSS 像素。

```css
.button {
  height: 40px;
  padding-inline: 16px;
}
```

`px` 适合边框、图标、固定间距、精确控制的 UI 元素。响应式布局中也会大量使用 `px`，关键是不要把整体布局宽度写死。

```css
.icon {
  width: 24px;
  height: 24px;
}
```

别把 `px` 理解成“不能响应式”。问题不在单位本身，而在是否把所有尺寸都锁死。

`px` 更像“精确控制”的单位，不是“绝对不可变化”的单位。边框、图标、阴影、细分间距、对齐修正这些地方，`px` 仍然是最清楚的表达；真正不建议的是把页面骨架、正文行宽、整页容器都写成死宽度。

## 相对字体单位

`em` 相对于当前元素字体大小，`rem` 相对于根元素字体大小。

```css
html {
  font-size: 16px;
}

.title {
  font-size: 1.5rem;
  margin-bottom: 0.75em;
}
```

`rem` 适合全局字号和间距系统，`em` 适合跟随当前文字大小变化的局部间距。嵌套中滥用 `em` 容易出现层层放大。

`em` 和 `rem` 的差别不只是“相对谁”，还决定了设计系统的稳定性。全局 token、页面基础字号、模块级间距通常更适合 `rem`，因为它不会随着嵌套层级一路放大；按钮内部 padding、徽标、与当前字体强相关的细节则更适合 `em`。

```css
.button {
  font-size: 1rem;
  padding: 0.625em 1em;
}
```

这里按钮 padding 跟随按钮文字大小变化，适合不同字号按钮场景。系统级间距通常还是更适合用 `rem` 统一管理。

## 视口单位

`vw`、`vh` 基于视口尺寸。

```css
.hero {
  min-height: 100vh;
  padding-inline: 5vw;
}
```

移动端使用 `vh` 要谨慎，因为浏览器地址栏、底部工具栏、软键盘都会影响可视区域。现代浏览器提供 `svh`、`lvh`、`dvh` 用于更精确地表达视口高度。

```css
.screen {
  min-height: 100dvh;
}
```

`dvh` 更适合移动端动态视口场景。`svh`、`lvh` 则更适合明确区分最小/最大视口时使用。

视口单位最需要小心的是移动端浏览器 UI。地址栏、底部栏、软键盘会让传统 `vh` 的感知和实际可见区域不完全一致，所以需要根据是否要追随动态视口来选 `dvh`、`svh` 或 `lvh`。如果页面是全屏模块、落地页首屏或弹窗容器，这个差异会直接影响布局是否抖动。

## 百分比

百分比相对于包含块或相关属性的参考值。

```css
.card {
  width: 50%;
}

.box {
  padding-top: 56.25%;
}
```

`width: 50%` 相对父容器宽度。百分比 padding 在很多情况下相对包含块宽度，这也是早期比例盒子的基础。

```css
.panel {
  max-width: 100%;
}
```

百分比最常用的地方是宽度、图片、布局列宽和响应式容器。它表达的是“相对父级变化”，不是“自动适配所有场景”。

百分比的参照系必须提前想清楚。宽度百分比相对包含块宽度，padding 的百分比在很多场景里也会跟宽度走，绝对定位下的百分比又可能相对定位祖先。很多布局误差不是百分比不好，而是开发者忘了它到底在相对于谁计算。

## fr

`fr` 是 Grid 布局中的剩余空间单位。

```css
.layout {
  display: grid;
  grid-template-columns: 240px 1fr;
}
```

`1fr` 表示占据剩余空间的一份。它只在 Grid 上下文中生效，不是通用长度单位。

```css
.layout {
  display: grid;
  grid-template-columns: 2fr 1fr;
}
```

和 Flex 的 `flex-grow` 类似，`fr` 也是在分配空间，但它分配的是网格轨道。做页面骨架时，`fr` 往往比百分比更直观。

`fr` 最适合页面结构的“剩余列”表达，而不是精确数值控制。固定导航、主内容、侧栏这类布局，用 `px + fr` 的混合通常最自然；如果所有列都写成百分比，列与列之间的空隙、最小宽度和剩余空间分配反而更难算。

## ch

`ch` 大致表示字符 `0` 的宽度，适合控制文本行宽。

```css
.article {
  max-width: 68ch;
}
```

正文行宽过长会影响阅读。用 `ch` 限制文章宽度，比固定 `px` 更贴近文本内容。

```css
.code-block {
  max-width: 80ch;
}
```

`ch` 对等宽数字、代码、表单输入宽度尤其有帮助。它不是所有字体都完全一致，但在文本排版里通常足够实用。

`ch` 很适合文档、代码和表单。比如正文宽度、验证码输入框、代码块最大宽度，都可以借助 `ch` 更贴近“可读长度”而不是物理像素。它的价值在于直接把“这个区域大概能容纳多少字符”表达出来。

## clamp 组合

现代响应式尺寸常通过 `clamp` 组合单位。

```css
.page {
  padding-inline: clamp(16px, 4vw, 40px);
}

.heading {
  font-size: clamp(24px, 6vw, 56px);
}
```

这种写法同时约束最小值和最大值，避免在小屏过小、大屏过大。

```css
.section {
  margin-block: clamp(24px, 5vw, 64px);
}
```

`clamp()` 的价值是把响应式变化变成连续且有边界的变化，特别适合字号、内边距和模块间距。

`clamp()` 通常是现代响应式里最实用的组合单位之一，因为它避免了“一个断点跳一次”的生硬变化。字号、内边距、模块间距、卡片标题都可以使用它，让页面在窄屏和宽屏之间过渡更自然。

## 选择原则

| 单位 | 适合场景 |
| --- | --- |
| `px` | 精确 UI 尺寸、边框、图标 |
| `rem` | 全局字号、间距体系 |
| `em` | 跟随当前字体的局部尺寸 |
| `%` | 相对父容器布局 |
| `vw/vh` | 视口相关视觉区域 |
| `dvh/svh/lvh` | 移动端视口高度 |
| `fr` | Grid 剩余空间 |
| `ch` | 文本行宽 |
| `clamp()` | 有上下限的响应式尺寸 |

单位选择没有绝对答案。判断时看它应该相对谁变化：父容器、字体、视口、网格剩余空间，还是固定 UI 尺寸。把“变化参照系”想清楚，单位就不容易用错。

一个很实用的经验是：如果你想要的是设计系统里的固定刻度，优先考虑 `px` 或 `rem`；如果你想跟着文字变化，考虑 `em`；如果你想跟着容器或屏幕变化，考虑 `%`、`vw/vh`、`dvh` 或 `fr`；如果你想表达可读边界，考虑 `ch`；如果你想让变化有上下限，考虑 `clamp()`。单位本身不是复杂，复杂的是没先想清参照系。
