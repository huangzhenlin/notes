## 内容盒

CSS 盒模型把每个元素看成一个矩形盒子，由 content、padding、border、margin 组成。浏览器布局时计算的不是“文字本身”，而是一个个盒子如何占据空间、如何相互影响。

```text
margin
  border
    padding
      content
```

默认情况下，`width` 和 `height` 设置的是 content 区域，不包含 padding 和 border。

```css
.box {
  width: 200px;
  padding: 16px;
  border: 2px solid #ddd;
}
```

在默认 `content-box` 下，这个盒子的可见宽度不是 `200px`，而是：

```text
content 200px
+ padding-left 16px
+ padding-right 16px
+ border-left 2px
+ border-right 2px
= 236px
```

这就是很多布局“明明写了 200px 却撑开父容器”的根源。理解盒模型后，再看 [[1.2.7 Flex|Flex]] 和 [[1.2.8 Grid|Grid]] 的子项尺寸会更顺。

## box-sizing

`box-sizing` 决定宽高计算方式。现代项目通常把所有元素设置为 `border-box`，让声明的宽高包含 content、padding 和 border。

```css
.box {
  box-sizing: border-box;
  width: 200px;
  padding: 16px;
  border: 1px solid #ddd;
}
```

`border-box` 下，元素最终宽度仍是 `200px`，padding 和 border 会算在里面。内容区域会自动变小。

```css
*,
*::before,
*::after {
  box-sizing: border-box;
}
```

这种全局设置能让布局尺寸更符合直觉，尤其是栅格、表单和卡片布局。

| 模式 | `width` 表示 | 最终可见宽度 |
|---|---|---|
| `content-box` | content 宽度 | content + padding + border |
| `border-box` | border 外沿宽度 | 声明的 width |

注意 `box-sizing` 不包含 `margin`。margin 永远是盒子外部空间，不会被算进 `width`。

## margin

`margin` 控制盒子外部间距。它不属于可点击内容，也不属于背景绘制区域。垂直方向普通块级元素的 margin 可能发生折叠。

```css
.title {
  margin-bottom: 16px;
}

.content {
  margin-top: 20px;
}
```

两个相邻块的垂直 margin 不一定相加，可能取较大值。这个例子最终间距可能是 `20px`，不是 `36px`。

```html
<h2 class="title">标题</h2>
<p class="content">正文内容</p>
```

margin 适合表达元素之间的外部关系，例如标题和段落之间、卡片和卡片之间。组件内部的呼吸空间更适合用 padding 表达，因为 padding 属于组件本身。

```css
/* 卡片内部空间 */
.card {
  padding: 16px;
}

/* 卡片之间的距离 */
.card + .card {
  margin-top: 16px;
}
```

在 Flex、Grid 或创建 BFC 的容器中，margin 折叠规则会不同。排查垂直间距异常时，要先确认元素是否还处在普通文档流中。

## padding

`padding` 控制内容与边框之间的内边距，会撑开盒子的内部空间。背景色会覆盖 padding 区域，所以 padding 常用于按钮、卡片、输入框这类组件的可点击区域和视觉呼吸感。

```css
.card {
  padding: 16px;
  border: 1px solid #e5e7eb;
  border-radius: 8px;
}

.button {
  padding: 8px 16px;
}
```

点击目标太小通常不是字体问题，而是 padding 和最小尺寸不足。移动端按钮、复选框、列表项尤其要关注可点击区域。

```css
.tap-target {
  min-height: 44px;
  padding-inline: 12px;
}
```

百分比 padding 有一个容易混淆的规则：在很多布局场景中，垂直方向百分比 padding 也会参考包含块宽度。这也是早期等比例盒子的实现基础。

```css
.ratio-box {
  width: 100%;
  padding-top: 56.25%;
}
```

现代项目更推荐使用 `aspect-ratio` 表达比例，它比 padding hack 更直观。

```css
.video-cover {
  aspect-ratio: 16 / 9;
}
```

## border

`border` 会占据盒子尺寸，除非使用 `box-sizing: border-box` 把它纳入声明宽高。

```css
.input {
  border: 1px solid #d1d5db;
  border-radius: 6px;
}
```

如果默认是 `content-box`，输入框聚焦时加粗边框可能造成布局抖动。

```css
/* 可能造成尺寸变化 */
.input:focus {
  border-width: 2px;
}
```

更稳的方式是保持边框宽度不变，改颜色或用 outline 表达焦点。

```css
.input:focus-visible {
  border-color: #1677ff;
  outline: 2px solid rgb(22 119 255 / 20%);
  outline-offset: 2px;
}
```

高分屏上的细线可以用 `1px`，真实视觉由设备像素比决定。不要为了所谓“物理 1 像素”过度复杂化，除非设计确实要求。

边框还常常承担“状态反馈”的职责。输入框的聚焦态、错误态、选中态，很多时候不一定需要改变背景色，改 border 或 outline 就足够。如果状态变化导致布局抖动，通常是边框宽度在不同状态下不一致；这时更稳的方案是保持边框宽度固定，再改颜色、阴影或外部轮廓。

## overflow

内容超出盒子时，由 `overflow` 决定处理方式。

```css
.panel {
  max-height: 320px;
  overflow: auto;
}
```

`overflow: hidden` 会裁剪内容，也可能影响 sticky、阴影、焦点轮廓等效果。使用它解决布局溢出前，要确认不会隐藏重要内容。

```css
/* 可能裁掉焦点轮廓或阴影 */
.card-list {
  overflow: hidden;
}
```

常见值可以这样判断：

| 值 | 行为 | 适合场景 |
|---|---|---|
| `visible` | 默认可溢出 | 普通内容流 |
| `hidden` | 裁剪溢出内容 | 装饰裁剪、圆角遮罩 |
| `auto` | 必要时出现滚动 | 面板、表格容器 |
| `scroll` | 始终保留滚动机制 | 特殊固定滚动区域 |
| `clip` | 裁剪且不创建滚动容器 | 纯裁剪场景 |

如果只是长单词、URL 或代码撑破容器，应优先处理文本换行，而不是直接 `overflow: hidden`。

```css
.content {
  overflow-wrap: break-word;
}
```

## 尺寸约束

现代布局常结合 `min-width`、`max-width`、`min-height`、`max-height` 控制边界。响应式布局中，不是所有元素都应该固定宽高，更常见的是设置最大宽度、最小高度，让内容在合理范围内自适应。

```css
.article {
  width: min(100%, 720px);
  min-height: 100dvh;
}
```

`min-width: 0` 是 Flex 布局里非常常见的“救命属性”。Flex 子项默认可能不愿意比内容更窄，导致文本省略不生效或容器被撑开。

```css
.media-card {
  display: flex;
  gap: 12px;
}

.media-card-content {
  min-width: 0;
}

.media-card-title {
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}
```

尺寸约束通常要回答“它最多多大、至少多大、在可用空间变化时怎么伸缩”。写死宽高只适合图标、头像、固定控件等场景；内容容器更适合用 `max-width`、`min-height`、`clamp()`、`min()`、`max()` 这类约束表达。

在响应式页面里，尺寸约束和内容密度通常要一起看。比如文章正文可以用 `max-width` 控制阅读宽度，卡片可以用 `minmax()` 或栅格自适应，表单输入可以给出合理最小宽度而不是无限拉伸。尺寸不是越确定越好，而是要让盒子在不同屏幕上仍然保持可读、可点、可比较。

```css
.article {
  width: min(100%, 720px);
  margin-inline: auto;
}

.card-title {
  display: -webkit-box;
  -webkit-line-clamp: 2;
  -webkit-box-orient: vertical;
  overflow: hidden;
}
```

虽然这里用了截断，但应把截断当成展示策略，不是内容策略。标题被截断后，完整内容往往还要在详情页、标题属性或其他可访问路径里补回来。

## 调试方法

盒模型问题可以直接用浏览器 DevTools 查看。布局错位时，先看盒模型，再看定位、Flex/Grid 和响应式规则。很多问题只是 padding、border、width 的计算方式不一致。

排查盒模型时，浏览器开发者工具里最有价值的信息通常不是 CSS 源码，而是最终计算后的宽高、内外边距和盒子边界。尤其是组件接入第三方主题、字体变化、浏览器默认样式差异时，实际渲染值比你“以为写了什么”更重要。

```text
检查 computed 盒模型
  -> 确认 box-sizing
  -> 看 width/height 是否包含 padding 和 border
  -> 看 margin 是否折叠
  -> 看 overflow 是否裁剪
  -> 确认父容器尺寸约束
```

常见问题可以这样定位：

| 现象 | 可能原因 | 排查方向 |
|---|---|---|
| 元素比声明宽度更宽 | `content-box` 加 padding/border | 查 `box-sizing` |
| 两段间距没有相加 | 垂直 margin 折叠 | 查是否普通文档流 |
| 阴影或焦点被裁掉 | 父级 `overflow: hidden` | 查滚动和裁剪容器 |
| 文本撑破容器 | 子项最小宽度或换行规则 | 查 `min-width`、`overflow-wrap` |
| 聚焦时布局抖动 | border 宽度变化 | 改用 outline 或固定 border |

盒模型是 CSS 布局排查的第一层。先把每个盒子自己的尺寸算清楚，再去看它和父子、兄弟元素的关系，问题会少一半。

很多布局“看起来随机抖动”，其实都能回到盒模型上解释：按钮 hover 时边框变粗、卡片加阴影后宽度溢出、表单项因为 padding 和 border 叠加撑破列宽、图片在响应式布局里因为宽高约束不一致而错位。先问元素占据的外部空间是多少，再问内容区域到底剩多少，通常比直接盯着视觉结果更快。

`box-sizing: border-box` 之所以在工程里几乎是默认答案，是因为它更符合“声明宽度就是外层宽度”的直觉。但这不代表所有元素都一定要依赖它解决问题。图文容器、表单控件、卡片、按钮适合 `border-box`，纯内容排版区则要更关注文字换行、最小宽度和外部约束。

## 外边距折叠

外边距折叠主要发生在普通文档流中的垂直方向块级盒子之间。它不是 bug，而是 CSS 的历史规则。相邻兄弟、父子之间、空块自身都可能出现折叠。

```html
<section class="panel">
  <h2>标题</h2>
</section>
```

```css
.panel {
  background: #f9fafb;
}

.panel h2 {
  margin-top: 24px;
}
```

如果父元素没有 border、padding、行内内容或新的格式化上下文，子元素的 `margin-top` 可能“穿出”父元素，看起来像父元素自己被推开。常见处理方式是给父元素加 padding、border，或者创建新的格式化上下文。

```css
.panel {
  display: flow-root;
}
```

## 格式化上下文

BFC 可以影响浮动、margin 折叠、内部布局和溢出计算。现代 CSS 里，`display: flow-root` 是创建 BFC 的清晰方式。

```css
.media-object {
  display: flow-root;
}

.media-object img {
  float: left;
  margin-right: 12px;
}
```

过去常用 `overflow: hidden` 清除浮动，但它会裁剪阴影、焦点轮廓和溢出内容。只为了创建 BFC 时，`flow-root` 语义更明确。

## 逻辑属性

现代 CSS 可以使用逻辑属性表达与书写方向相关的尺寸和间距，例如 `margin-block`、`padding-inline`、`border-block-start`。

```css
.card {
  padding-block: 16px;
  padding-inline: 20px;
}

.title {
  margin-block-end: 12px;
}
```

逻辑属性比 `top/right/bottom/left` 更适合国际化页面。即使当前项目只做中文，也可以在组件库和基础样式里优先使用逻辑属性，让未来横向扩展更轻。

## min-content 与 max-content

CSS 尺寸不只有固定长度。`min-content` 表示内容能压缩到的最小尺寸，`max-content` 表示内容不换行时需要的最大尺寸，`fit-content` 则在可用空间内折中。

```css
.tag {
  width: max-content;
}

.sidebar {
  width: fit-content;
  max-width: 320px;
}
```

这些关键字常出现在 Grid、Flex、按钮、标签、弹层宽度里。理解它们后，很多“内容把布局撑开”的问题会更容易解释。

## aspect-ratio

`aspect-ratio` 用于声明盒子的宽高比例，适合视频封面、卡片图、头像裁剪、占位骨架。

```css
.video-cover {
  aspect-ratio: 16 / 9;
  object-fit: cover;
}
```

相比早期用 `padding-top` 做比例盒，`aspect-ratio` 更直观，也更容易和响应式布局、图片尺寸预留结合。它不能替代图片的 `width` / `height` 属性，但能让 CSS 布局阶段更清楚地表达比例意图。

## 实战判断

盒模型问题通常可以先问四个问题：

1. 当前宽高是 content-box 还是 border-box。
2. 间距是组件内部 padding，还是组件外部 margin。
3. 溢出是内容太长，还是父容器约束太小。
4. 尺寸应该固定、约束，还是随内容自适应。

如果答案不清楚，先不要急着写 `overflow: hidden` 或固定高度。很多布局问题不是“缺一条 CSS”，而是盒子的责任没有分清。
