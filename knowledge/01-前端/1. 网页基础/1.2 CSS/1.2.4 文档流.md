## 正常流

文档流是浏览器默认的布局规则。元素在没有浮动、定位、Flex、Grid 等特殊布局影响时，会按照 HTML 顺序从上到下、从左到右排列。

```html
<h1>标题</h1>
<p>第一段正文</p>
<p>第二段正文</p>
<button>提交</button>
```

正常流的价值是“内容天然可读”。如果 HTML 顺序本身合理，即使 CSS 加载失败，页面仍然能按内容顺序阅读；如果一开始就依赖绝对定位拼页面，样式稍微变化就可能出现覆盖、错位和键盘顺序混乱。

```text
HTML 顺序
  -> 生成盒子
  -> 按 display 类型进入正常流
  -> 计算块级、内联、行盒关系
  -> 再叠加定位、浮动、Flex、Grid 等规则
```

理解文档流，是理解 [[1.2.3 盒模型|盒模型]]、[[1.2.5 定位|定位]]、[[1.2.7 Flex|Flex]]、[[1.2.8 Grid|Grid]] 之前的基础。很多布局问题不是“CSS 玄学”，而是元素已经不在你以为的那条流里。

文档流还有一个容易被忽略的价值：它决定了无样式页面、键盘导航、读屏阅读和搜索抓取时的基础顺序。视觉上可以通过 CSS 改变排列，但 HTML 顺序仍然应该尽量符合阅读顺序。否则页面看起来没问题，键盘焦点、复制文本、屏幕阅读器和爬虫理解却可能全都不顺。

## 块级盒

块级元素通常独占一行，宽度默认填满父容器。常见块级元素包括 `div`、`p`、`section`、`article`、`h1`。

```css
.block {
  display: block;
}
```

```html
<section class="profile-card">
  <h2>用户信息</h2>
  <p>这里展示用户基础资料。</p>
</section>
```

块级盒会在垂直方向依次排列。它们的宽度默认是包含块可用宽度，高度由内容撑开。标题、段落、区块、列表天然适合块级流。

```css
.profile-card {
  padding: 16px;
  border: 1px solid #e5e7eb;
}

.profile-card + .profile-card {
  margin-top: 16px;
}
```

块级元素的垂直 margin 可能发生折叠，这一点在普通文档流里尤其常见。不要一看到间距“不相加”就以为 CSS 没生效。

块级流很适合构建文档、表单、文章、设置页这类纵向内容。越是内容驱动的页面，越应该先让正常流工作，再局部使用 Flex/Grid 做横向排布。这样页面在加载慢、样式失败、打印或阅读模式下也更稳。

## 内联盒

内联元素在一行内排列，不会独占一行。常见内联元素包括 `span`、`a`、`strong`、`em`。它们更适合包裹文本片段，而不是承担复杂布局。

```css
.inline {
  display: inline;
}
```

```html
<p>
  请阅读
  <a href="/terms">用户协议</a>
  和
  <a href="/privacy">隐私政策</a>
  后继续。
</p>
```

内联元素设置宽高通常不生效，垂直方向 padding 和 margin 对行盒影响也和块级元素不同。如果需要一个既能同行排列、又能设置尺寸的标签，就要考虑 `inline-block` 或 Flex。

```css
a {
  color: #1677ff;
  text-underline-offset: 0.15em;
}
```

内联内容会参与行盒计算，行高、基线、字体度量都会影响它的位置。这也是图标和文字垂直对齐经常出现微妙偏差的原因。

处理内联图标时，不要只靠 `top: 1px` 反复微调。更稳定的方式是统一字号、行高、图标尺寸和对齐方式，必要时让图标容器使用 `inline-flex` 并通过 `align-items: center` 对齐。内联排版的问题常常来自字体度量，而不是单个元素的位置错了。

## inline-block

`inline-block` 既像内联元素一样在一行排列，又能设置宽高。标签、徽章、小按钮、内联图标容器常用这种方式。

```css
.tag {
  display: inline-block;
  padding: 4px 8px;
  border-radius: 999px;
  background: #f3f4f6;
}
```

```html
<span class="tag">JavaScript</span>
<span class="tag">CSS</span>
```

多个 `inline-block` 之间可能受 HTML 空白字符影响产生间距。

```html
<span class="tag">HTML</span>
<span class="tag">CSS</span>
```

如果你需要严格控制一组元素的间距，现代项目更推荐用 Flex 的 `gap`：

```css
.tag-list {
  display: flex;
  flex-wrap: wrap;
  gap: 8px;
}
```

`inline-block` 适合文本流里的小块元素；完整布局则优先考虑 Flex 或 Grid。

`inline-block` 还常用于让元素既参与文本流，又有可控尺寸。例如文章中的标签、行内按钮、状态徽章，都可以保持在文字行内，同时拥有 padding 和圆角。它的边界是：一旦你开始关心多行对齐、自动换行间距、主轴交叉轴分布，就应该转向 Flex 或 Grid。

## 脱离文档流

浮动、绝对定位、固定定位会让元素部分或完全脱离正常文档流。脱离文档流后，元素不再按原位置占据空间，可能覆盖其他内容。

```css
.badge {
  position: absolute;
  right: 8px;
  top: 8px;
}
```

```css
.card {
  position: relative;
}
```

这个例子里，`.badge` 相对于最近的定位祖先 `.card` 放置。它不会撑开卡片高度。如果徽章内容变多，可能覆盖卡片正文。

| 方式 | 是否占据原空间 | 常见用途 |
|---|---|---|
| `float` | 部分脱离 | 图文环绕、旧式布局 |
| `position: absolute` | 不占据 | 角标、浮层内部定位 |
| `position: fixed` | 不占据 | 固定导航、全局浮层 |
| `position: sticky` | 占据原空间后粘滞 | 表头、侧边目录 |

使用定位时要确认父容器和周围元素的关系。能用正常流、Flex、Grid 解决的布局，不要优先使用绝对定位。定位更适合局部叠放，而不是页面整体排版。

脱离文档流最大的问题是“它不再为周围内容预留空间”。角标、Tooltip、浮层适合这样做；正文、表单、列表项主体通常不适合。只要内容长度、语言、屏幕尺寸会变化，用定位硬摆主内容就很容易覆盖或溢出。

## BFC

BFC 是块级格式化上下文，它会影响浮动、margin 折叠、内部布局隔离。可以把它理解成一个独立的块级布局环境：内部元素的布局不会随便影响外部，外部浮动也不容易侵入内部。

```css
.container {
  display: flow-root;
}
```

`display: flow-root` 可以创建 BFC，常用于清除浮动或隔离内部布局。

```html
<div class="media">
  <img class="media-cover" src="/cover.png" alt="" />
  <p>这段文字不会被外部浮动影响。</p>
</div>
```

```css
.media {
  display: flow-root;
}

.media-cover {
  float: left;
  width: 120px;
  margin-right: 12px;
}
```

常见创建 BFC 的方式包括：

| 方式 | 说明 |
|---|---|
| `display: flow-root` | 语义最明确 |
| `overflow: auto/hidden` | 会产生滚动或裁剪副作用 |
| `display: flex/grid` | 建立新的布局上下文 |
| `float` | 旧式布局行为 |
| `position: absolute/fixed` | 脱离正常流 |

现代项目中直接使用 Flex/Grid 后，很多传统浮动问题会减少。但理解 BFC 仍然有价值，因为 margin 折叠、浮动清除、overflow 副作用都绕不开它。

BFC 可以被理解成“这个块自己管理内部布局”。它能阻止某些 margin 折叠，包住浮动元素，也能避免外部浮动侵入。但创建 BFC 的方式不同，副作用不同：`flow-root` 最纯粹，`overflow: hidden` 会裁剪内容，Flex/Grid 会改变子项布局规则。不要为了一个效果引入更大的副作用。

## margin 折叠

普通文档流中，相邻块级元素的垂直 margin 可能折叠。折叠后的间距通常取较大的那个，而不是相加。

```css
.title {
  margin-bottom: 24px;
}

.paragraph {
  margin-top: 16px;
}
```

```html
<h2 class="title">标题</h2>
<p class="paragraph">正文</p>
```

最终间距可能是 `24px`，不是 `40px`。父子元素之间也可能出现 margin 折叠，例如子元素的 `margin-top` 穿出父元素。

```css
.panel {
  background: #f9fafb;
}

.panel-title {
  margin-top: 24px;
}
```

如果你希望间距属于父容器内部，应使用 padding；如果你希望阻止折叠，可以创建 BFC、添加 border/padding、使用 Flex/Grid，或调整间距归属。

```css
.panel {
  padding-top: 24px;
}

.panel-title {
  margin-top: 0;
}
```

## 现代布局关系

Flex 和 Grid 会建立新的布局上下文，子元素不再按普通块级流规则排列。

```css
.toolbar {
  display: flex;
  align-items: center;
  gap: 12px;
}
```

文档流仍然是默认基础；Flex/Grid 是在某个容器内改变子项布局规则。容器本身仍然会参与外部文档流，除非你再用定位、浮动等方式改变它。

```html
<header>页头</header>
<main class="layout">
  <aside>侧边栏</aside>
  <article>正文</article>
</main>
<footer>页脚</footer>
```

```css
.layout {
  display: grid;
  grid-template-columns: 240px 1fr;
  gap: 24px;
}
```

这里 `main.layout` 作为一个块级盒仍然在页头和页脚之间；只是它的子元素由 Grid 排列。理解这一点能避免把所有布局问题都归咎于“CSS 很乱”。

也就是说，现代布局不是替代文档流，而是在文档流的某个节点里开启新的布局规则。页面大结构仍然应该顺着 HTML 阅读顺序排列，局部工具栏用 Flex，二维页面骨架用 Grid，叠层和浮动提示再用定位。每个布局机制都有自己的职责，混用时先划清边界。

## 调试顺序

定位、浮动、Flex、Grid 都建立在文档流基础上。先看元素是否还在正常流里，很多布局问题会清楚很多。

```text
确认元素 display 类型
  -> 检查是否脱离文档流
  -> 检查父容器布局上下文
  -> 检查 margin 是否折叠
  -> 检查宽高是否受内容或父容器影响
```

常见现象可以这样排查：

| 现象 | 可能原因 | 排查方向 |
|---|---|---|
| 元素覆盖其他内容 | absolute/fixed 脱离流 | 查定位上下文 |
| 父容器高度塌陷 | 子元素浮动 | 创建 BFC 或清除浮动 |
| 垂直间距不相加 | margin 折叠 | 查普通块级流 |
| 内联元素宽高无效 | `display: inline` | 改为 `inline-block`、Flex |
| Flex 子项不按块级流排列 | 父级是 Flex 容器 | 按 Flex 规则排查 |

文档流是 CSS 布局的默认语言。先尊重正常流，再用 Flex、Grid、定位做局部增强，页面会更稳定，也更接近 HTML 内容本身的阅读顺序。

## 行内排版

正常流里除了块级盒，还有行内排版。文字、链接、强调、内联图标会共同组成一行内容，浏览器会根据字体、行高、基线和换行规则计算行盒。

```html
<p>
  这是一个包含
  <a href="/html">HTML</a>
  和
  <strong>强调文本</strong>
  的段落。
</p>
```

行内排版最容易出问题的地方是图标和文字对齐、行高过大、内联元素换行、长单词或 URL 撑破容器。处理长文本时，应优先用 `overflow-wrap`、`word-break`、`white-space`，而不是随意把元素改成绝对定位。

```css
.content {
  overflow-wrap: break-word;
}
```

## 替换元素

图片、视频、表单控件等属于替换元素。它们的尺寸和渲染方式不完全由 CSS 文本规则决定，而是由内容本身、固有尺寸和外部约束共同决定。

替换元素最常见的问题是“内容自带尺寸”和“布局期望尺寸”冲突。比如图片没有设置 `max-width: 100%` 时会撑破容器，视频没有比例约束时会出现黑边或布局跳动，输入框在不同浏览器下默认样式也可能不同。

```css
img,
video {
  max-width: 100%;
  height: auto;
}

input,
button,
textarea,
select {
  font: inherit;
}
```

这类基础规则不是为了抹平所有差异，而是把替换元素拉回更可控的布局基线。真正的组件样式仍然应该在具体组件里定义。

```html
<img src="/cover.jpg" alt="课程封面" />
<input type="text" />
```

替换元素在布局上经常和普通文本盒不一样。例如 `img` 的尺寸可能来自资源本身，`input` 的默认大小也不是普通块级盒。布局时不要假设所有元素都按同一种盒子规则工作。

## 内容顺序

文档流最大的价值之一，是让内容顺序和阅读顺序一致。屏幕阅读器、键盘 Tab 顺序、搜索引擎抓取和无样式回退都更容易沿着 HTML 顺序理解页面。

```text
推荐顺序：
1. 先写 HTML 内容顺序
2. 再用 CSS 调整视觉排版
3. 最后才考虑局部定位增强
```

如果视觉顺序和 DOM 顺序差异很大，用户会出现“看到的和读到的不是一回事”的问题。尤其在移动端和辅助技术场景中，这种差异会让导航和交互都变得别扭。

## 断流判断

判断一个元素是否还在正常流里，可以看它是否还参与文档的占位、是否会影响兄弟元素、是否受父容器排布控制。

| 现象 | 说明 | 处理方向 |
| --- | --- | --- |
| 元素占位正常 | 仍在正常流 | 继续用文档流或布局容器 |
| 元素不占位 | 可能脱离流 | 检查定位或浮动 |
| 内容把容器撑高 | 正常流行为 | 检查高度、边距、盒模型 |
| 文本换行异常 | 行内排版问题 | 检查字号、宽度、换行规则 |

文档流不是“最简单的布局方式”，而是所有布局方式的默认参考系。只要还在正常流里，很多内容和间距问题就更容易解释。
