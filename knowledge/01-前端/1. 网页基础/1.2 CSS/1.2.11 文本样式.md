## 字体族

`font-family` 定义文本使用的字体栈。

```css
body {
  font-family: "Inter", "PingFang SC", "Microsoft YaHei", sans-serif;
}
```

字体栈应包含兜底字体。中文字体、英文字体、系统字体的表现不同，实际项目要验证中英文混排效果。不要只在自己电脑上看起来正常就当成“字体没问题”。

```css
code, pre {
  font-family: "SFMono-Regular", Consolas, "Liberation Mono", monospace;
}
```

正文和代码最好使用不同字体栈。排版目标不同，字体选择也不同。

字体栈的顺序也很重要。通常先放品牌或指定字体，再放系统中文字体和英文字体，最后放通用族名。中英文混排时，要特别关注英文字母高度、中文标点、数字宽度和代码片段是否协调。一个字体在标题里好看，不代表适合长正文。

## 字号与行高

字号决定文本大小，行高决定行盒高度。

```css
.article {
  font-size: 16px;
  line-height: 1.7;
}
```

正文行高通常使用无单位数值，这样会随字体大小缩放。行高过小影响阅读，过大则降低信息密度。

```css
h1 {
  font-size: clamp(28px, 4vw, 44px);
  line-height: 1.2;
}
```

标题的行高通常比正文更紧凑，便于形成层级感。长文档里，字号、行高和段前后间距最好一起设计，而不是单独调某一个属性。

行高建议使用无单位值，比如 `line-height: 1.6`，这样子元素继承时会按自身字号计算，更不容易出现大字号标题继承过高像素行高的问题。正文行高通常更宽松，标题行高通常更紧凑，按钮和输入框则要兼顾垂直居中和可点击区域。

## 字重

`font-weight` 控制字重。

```css
.title {
  font-weight: 700;
}

.meta {
  font-weight: 400;
}
```

不是所有字体都支持所有字重。浏览器可能合成粗体，效果和真实字重不同。自定义字体要只加载实际使用的字重，避免字体包过大。

```css
.label {
  font-weight: 500;
}
```

字重适合表达信息层级，但不要仅靠字重区分状态。必要时还应配合颜色、间距、图标或布局变化。

如果使用可变字体，`font-weight` 可以在一个字体文件里覆盖更连续的字重范围，但这不代表可以随意增加层级。视觉层级太多会让页面像调色盘一样嘈杂。正文、标题、强调、元信息、按钮通常有稳定几档就足够了。

## 文本对齐

```css
.center {
  text-align: center;
}

.price {
  text-align: right;
}
```

标题、按钮文字可以居中；长正文通常不适合居中。数字、金额、表格列常用右对齐，便于比较。

```css
.article {
  text-align: start;
}
```

对阅读型内容，通常用逻辑方向的 `start/end` 比左/右更稳，尤其在多语言页面里。

文本对齐还要看内容类型。长正文居中会降低连续阅读效率；数字右对齐更利于比较；表单标签在不同语言下可能长度差异大，常需要和 Grid/Flex 结合处理。不要把 `text-align: center` 当成“显得正式”的默认选项。

## 文本溢出

单行省略常见写法：

```css
.title {
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}
```

在 Flex 容器中，可能还需要 `min-width: 0`。

```css
.title {
  min-width: 0;
}
```

多行省略可以使用 `line-clamp`。

```css
.summary {
  display: -webkit-box;
  -webkit-line-clamp: 2;
  -webkit-box-orient: vertical;
  overflow: hidden;
}
```

省略会隐藏内容，重要信息不应只靠省略展示。必要时提供详情入口或 tooltip。省略是信息折叠，不是内容消失的借口。

文本溢出经常和布局机制绑定。Flex 子项要考虑 `min-width: 0`，Grid 轨道要考虑 `minmax(0, 1fr)`，代码块要考虑横向滚动或换行策略。只写 `text-overflow: ellipsis` 不一定生效，因为省略需要元素真的发生可控溢出。

## 字间距与换行

```css
.code {
  word-break: break-all;
}

.paragraph {
  overflow-wrap: break-word;
}
```

长 URL、英文长词、代码片段容易撑破容器。普通正文优先用 `overflow-wrap: break-word`，不要随意对所有文本使用 `break-all`，中文阅读效果会变差。

```css
.url {
  word-break: normal;
  overflow-wrap: anywhere;
}
```

`overflow-wrap` 更适合“尽量不破坏阅读，但必要时可以断行”的场景；`word-break: break-all` 更激进，通常只适合极端内容，例如长串无空格字符串。

中文、英文、URL、代码的换行策略不应该完全一样。中文天然可在字符间换行，英文单词通常不希望被随意拆开，URL 可以在必要时断开，代码则要兼顾可读和复制。全站粗暴使用 `word-break: break-all` 会让英文和代码阅读体验变差。

## 可读宽度

正文行宽要控制在适合阅读的范围。

```css
.article {
  max-width: 68ch;
}
```

行宽过长，用户换行时容易丢失位置；行宽过短，阅读节奏会被频繁打断。技术文档、博客、说明页尤其要关注文本容器宽度。

```css
.prose {
  line-height: 1.75;
  letter-spacing: 0.01em;
}
```

可读宽度不是只有“宽度”一个维度，还包括行高、段间距、标题层级、列表缩进和字体对比。

技术文档尤其要控制行宽。正文太宽会让眼睛在换行时难以找到下一行，代码块太窄又会频繁横向滚动。比较稳的做法是正文使用 `ch` 或 `max-width` 控制阅读宽度，代码块单独提供横向滚动或更宽容器。

## 字体性能

Web Font 会影响加载性能和布局稳定性。

```css
@font-face {
  font-family: "Brand";
  src: url("/brand.woff2") format("woff2");
  font-display: swap;
}
```

字体优化包括使用 woff2、按字重加载、子集化、设置 `font-display`、预加载关键字体。不要为了视觉统一加载巨大字体包。

```html
<link rel="preload" href="/brand.woff2" as="font" type="font/woff2" crossorigin />
```

如果字体是品牌核心资产，可以预加载首屏关键字重；如果只是装饰性字体，优先接受系统字体回退。字体加载策略和 [[1.2.9 响应式|响应式]]、页面性能、首屏稳定性都有关。

字体加载还会影响 FOUT、FOIT 和布局偏移。`font-display: swap` 能让文字尽快显示，但字体替换时可能产生细微跳动；如果品牌字体与回退字体度量差异很大，就要通过字体选择、fallback 调整或减少首屏自定义字体来降低抖动。字体不是纯视觉问题，它会进入性能和稳定性链路。

## 信息层级

文本样式不只是“看起来舒服”，也要能帮助读者建立层级感。标题、正文、说明、脚注、元信息要用不同的字号、字重和间距表达。

```css
.title {
  font-size: 1.5rem;
  font-weight: 700;
  line-height: 1.25;
}

.meta {
  font-size: 0.875rem;
  color: #6b7280;
}
```

如果一个页面所有文本都用同样字号和颜色，用户就需要靠猜来理解结构。文本样式越清楚，内容越容易扫读。

信息层级最好稳定且克制。标题负责建立结构，正文负责承载内容，元信息负责弱化辅助说明，强调文本负责提示风险或关键条件。不要把颜色、字号、字重同时拉满，否则用户反而失去判断重点的线索。

## 数字与代码

数字、金额、百分比、代码片段都有自己的排版需求。数字常常需要对齐，代码需要等宽字体和清楚的背景边界。

```css
.amount {
  font-variant-numeric: tabular-nums;
  text-align: right;
}

code {
  font-family: "SFMono-Regular", Consolas, monospace;
  font-size: 0.875em;
}
```

`font-variant-numeric: tabular-nums` 可以让数字等宽，更适合表格、报表、价格和统计数据。代码样式要清楚，但不要让行内代码过度抢正文注意力。

数字排版在业务系统里非常重要。金额、百分比、库存、评分、性能指标都需要快速比较，等宽数字和右对齐能明显降低阅读成本。代码排版则要区分行内代码和代码块：行内代码是正文的一部分，代码块是独立阅读单元。

## 链接文本

链接文本既要有视觉区别，也要能和正文自然融合。不要只靠颜色表达链接，最好保留清楚的下划线或交互状态。

```css
.article a {
  color: #1677ff;
  text-decoration-thickness: 0.08em;
  text-underline-offset: 0.16em;
}

.article a:hover {
  text-decoration-thickness: 0.12em;
}
```

对长文来说，链接应该一眼可见，但不应该破坏阅读节奏。链接样式和 [[1.1.7 无障碍|无障碍]] 也有关，不能只依赖低对比颜色。

链接文本本身也要有意义。样式能让链接可见，文字能让链接可理解。如果一篇文章里全是“点击这里”，读者和辅助技术都很难判断跳转目标。文本样式和 HTML 语义需要一起工作，视觉可见只是第一步。

## 多语言排版

中英文混排、数字、标点和代码会让文本排版更复杂。中文正文通常不需要过大的字间距，英文长词则要考虑换行。

```css
.article {
  line-height: 1.75;
  overflow-wrap: break-word;
}

.article code {
  word-break: break-word;
}
```

多语言页面更适合使用逻辑属性和 `text-align: start`，而不是写死 left/right。这样在不同书写方向下更稳定。

多语言排版还要考虑字体 fallback 和行高。中文、日文、韩文、英文、阿拉伯语的字形高度和标点习惯不同，同一套行高和间距不一定都舒服。国际化页面最好用真实内容测试，不要只用短英文占位符判断排版。

## 可读性检查

文字排版可以按这几个问题检查：

1. 正文是否有合理行宽。
2. 行高是否足够阅读。
3. 标题和正文是否有明显层级。
4. 长文本是否会把容器撑破。
5. 数字、代码、链接是否便于识别。

文本样式的目标不是让所有内容都“显得高级”，而是让内容更容易被看、被扫、被搜索、被复制。

检查文本样式时，可以临时把页面缩窄、放大到 200%、切换深色模式、换成长英文和长中文内容。只要这些情况下仍然能读、能扫、能复制，文本样式才算真的稳定。
