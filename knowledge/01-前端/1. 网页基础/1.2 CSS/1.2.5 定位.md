## static

元素默认是 `position: static`，按正常文档流排列。它不会创建定位上下文，`top`、`right`、`bottom`、`left`、`z-index` 对普通 static 元素通常没有效果。

```css
.box {
  position: static;
  top: 20px;
}
```

这里 `top: 20px` 不会让元素下移。需要偏移时，要使用 `relative`、`absolute`、`fixed` 或 `sticky`。但不要因为“想移动一点”就立刻定位；如果只是普通布局间距，优先用 margin、padding、Flex、Grid。

```css
/* 普通布局间距 */
.card + .card {
  margin-top: 16px;
}
```

定位是对正常流的增强，而不是普通排版的默认选择。先判断元素是否应该保留原本占位，再选择定位方式。

这句话在工程里尤其重要，因为很多定位问题不是“不会写”，而是“本来不该用定位”。如果只是让两个元素拉开一点距离，用 margin 和 gap 更稳；如果只是让局部模块横向排列，用 Flex 更自然；如果要建立页面骨架，用 Grid 更清晰。定位更适合“要脱离占位、要叠层、要贴边、要跟随滚动”的场景。

## relative

`relative` 会保留元素原本占位，再相对自身原位置偏移。偏移只影响视觉位置，不会影响周围元素的布局计算。

```css
.badge {
  position: relative;
  top: -2px;
}
```

如果一个元素用 `relative` 向上移动，后面的元素仍然认为它在原位置。这适合微调图标、角标、装饰元素，不适合大范围布局。

`relative` 更常见的用途是为 `absolute` 子元素建立定位包含块。

它还常用于微调而不破坏文档流。例如图标与文字的垂直关系、徽标与按钮的对齐、局部装饰元素的轻微偏移。只要偏移幅度很小，`relative` 通常比改 line-height、padding 或绝对定位更轻。

```css
.card {
  position: relative;
}

.card-badge {
  position: absolute;
  right: 8px;
  top: 8px;
}
```

```html
<article class="card">
  <span class="card-badge">New</span>
  <h2>CSS 定位</h2>
  <p>理解定位上下文和堆叠关系。</p>
</article>
```

这里 `.card-badge` 会相对 `.card` 定位，而不是相对页面。给父元素加 `position: relative` 是 absolute 布局里最常见的配套动作。

## absolute

`absolute` 脱离普通文档流，相对最近的非 static 定位祖先定位。如果找不到定位祖先，就会相对初始包含块定位。使用 absolute 时，通常要给父容器设置 `position: relative`。

```css
.tooltip-wrapper {
  position: relative;
  display: inline-block;
}

.tooltip {
  position: absolute;
  left: 0;
  top: calc(100% + 8px);
}
```

absolute 不会撑开父元素高度，所以它适合浮层、角标、装饰元素，不适合主要内容流。

```html
<span class="tooltip-wrapper">
  说明
  <span class="tooltip">这里是补充信息</span>
</span>
```

absolute 常见问题是“为什么跑到页面左上角”。通常是因为祖先没有定位上下文，子元素找不到参考点。

`absolute` 还常被用在需要局部叠放的场景：卡片角标、输入框内的清除按钮、头像上的在线状态点、下拉菜单、Tooltip。它们都依赖“父元素提供定位参考系”这个前提，所以组件封装时经常要先把根元素设成 `position: relative`。

```css
/* 修复参考点 */
.tooltip-wrapper {
  position: relative;
}
```

如果浮层需要脱离某个组件边界、覆盖全页面、避免被父级 `overflow: hidden` 裁剪，通常更适合渲染到页面顶层容器，或者使用组件库的 Portal/Teleport 机制。

## fixed

`fixed` 相对视口定位，常用于顶部栏、底部操作区、悬浮按钮、全屏遮罩。

```css
.bottom-bar {
  position: fixed;
  left: 0;
  right: 0;
  bottom: 0;
  padding-bottom: env(safe-area-inset-bottom);
}
```

移动端 fixed 要考虑安全区和软键盘。WebView、iOS Safari 中 fixed 表现也可能受滚动容器、输入框聚焦、视口变化影响。

```css
.modal-backdrop {
  position: fixed;
  inset: 0;
  background: rgb(0 0 0 / 45%);
}
```

全屏遮罩常用 `inset: 0` 同时设置四个方向。fixed 不占据文档流空间，所以底部固定栏可能遮挡正文，需要给主内容留出安全空间。

fixed 最常见的工程问题不是位置，而是“它把页面盖住了”。顶部吸顶栏、底部操作条、悬浮客服按钮都可能挡住内容或点击区域，所以需要配合主内容的内边距、滚动区域和安全区处理。移动端还要考虑软键盘弹出时视口变化，不要默认桌面浏览器的行为会完全一致。

```css
.page {
  padding-bottom: calc(64px + env(safe-area-inset-bottom));
}
```

## sticky

`sticky` 在普通流和固定定位之间切换，常用于吸顶标题、表头、侧边目录。它在到达阈值前仍占据原位置，到达阈值后像固定定位一样粘住。

```css
.section-title {
  position: sticky;
  top: 0;
  z-index: 10;
  background: white;
}
```

sticky 生效需要滚动祖先和阈值。父级 `overflow`、高度不足、缺少 `top` 都可能让 sticky 看起来无效。

| 失效现象 | 常见原因 | 排查方向 |
|---|---|---|
| 完全不吸顶 | 没有设置 `top` | 添加阈值 |
| 在局部容器内吸顶 | 祖先是滚动容器 | 确认期望滚动区域 |
| 提前消失 | 父容器高度太短 | 检查 sticky 所在块 |
| 被内容盖住 | 堆叠层级不足 | 设置背景和 z-index |

sticky 比 fixed 更适合“属于某段内容的吸顶元素”，例如文章目录、表格表头、分组标题。全局导航则更适合 fixed 或页面顶层 sticky。

sticky 的设计感很强，但也最容易被祖先样式破坏。只要父级 `overflow`、高度、滚动容器、背景层级有一点不对，sticky 就会看起来“不灵”。因此它适合内容相关的吸顶，而不是把整个页面都做成“随便哪里都吸住”的效果。

## z-index

`z-index` 控制堆叠顺序，但只在定位元素或特定上下文中生效。它不是全局数字竞赛。

```css
.modal {
  position: fixed;
  z-index: 1000;
}
```

如果两个元素处在不同堆叠上下文里，子元素的 `z-index` 再大，也可能盖不过外部上下文里的元素。

```css
.panel {
  position: relative;
  z-index: 1;
}

.panel-tooltip {
  position: absolute;
  z-index: 9999;
}

.modal {
  position: fixed;
  z-index: 10;
}
```

如果 `.panel` 自己所在的堆叠上下文低于 `.modal`，`.panel-tooltip` 不会因为 `9999` 就盖过弹窗。排查遮挡问题时，要从当前元素一路往上查祖先是否创建了堆叠上下文。

## 堆叠上下文

堆叠上下文是独立的层级比较范围。常见创建堆叠上下文的条件包括：

| 条件 | 示例 |
|---|---|
| positioned + z-index | `position: relative; z-index: 1` |
| opacity 小于 1 | `opacity: 0.9` |
| transform | `transform: translateZ(0)` |
| filter | `filter: blur(4px)` |
| isolation | `isolation: isolate` |
| contain | `contain: paint` |
| will-change | `will-change: transform` |

弹窗、下拉框、Tooltip 被遮挡时，不要只加大 `z-index`，还要检查祖先堆叠上下文、父级 `overflow`、Portal/Teleport 挂载位置。

```css
.app-shell {
  isolation: isolate;
}

.modal-layer {
  position: fixed;
  inset: 0;
  z-index: 1000;
}
```

大型项目可以建立 z-index 分层约定，例如 dropdown、sticky、drawer、modal、toast 分别使用不同层级。关键不是数字多大，而是所有组件遵循同一套层级模型。

一旦项目里出现多个团队、多个组件库、多个浮层系统，`z-index` 治理比单个元素的层级值更重要。建议把层级和组件职责绑定，而不是和页面局部体验绑定，否则一个弹窗改动就可能影响整站浮层。

## 使用边界

定位适合脱离普通流的局部需求，不要用 absolute 拼整个页面布局。大结构优先用 Grid/Flex，局部叠放再用定位。

| 需求 | 推荐方式 |
|---|---|
| 普通页面结构 | 文档流、Flex、Grid |
| 卡片角标 | `absolute` + `relative` 父级 |
| 顶部固定导航 | `sticky` 或 `fixed` |
| 弹窗遮罩 | `fixed` |
| 表头吸顶 | `sticky` |
| Tooltip/Dropdown | `absolute` 或 Portal |

定位排查可以按这个顺序走：

```text
确认元素是否脱离文档流
  -> 找定位参考祖先
  -> 检查 inset/top/right/bottom/left
  -> 检查 overflow 是否裁剪
  -> 检查堆叠上下文和 z-index
```

定位的难点通常不是语法，而是参考系和层级。先确认元素相对谁定位，再确认它和谁比较层级，问题会更快收敛。

如果你在调试时发现“看起来没定位，但位置就是不对”，优先检查祖先是否创建了新的定位上下文、是否被裁剪、是否进入了新的堆叠上下文。很多时候不是元素没动，而是它参考的坐标系变了。

## 参考系

定位最核心的是参考系。`absolute` 通常相对最近的非 static 祖先定位，`fixed` 相对视口，`sticky` 则在普通流和固定态之间切换。

```css
.card {
  position: relative;
}

.card-badge {
  position: absolute;
  right: 8px;
  top: 8px;
}
```

如果绝对定位元素跑偏了，先沿着 DOM 向上找谁创建了定位上下文。没有合适的祖先时，它就会退回到初始包含块，看起来像“飞到页面左上角”。

参考系这个概念在浮层组件里特别重要。Dropdown、Popover、Tooltip、日期选择器、下拉建议都可能因为挂载位置不同而定位失真。框架里常见的 Portal/Teleport，本质上就是把浮层渲染到更合适的参考系里。

## 偏移方式

定位偏移不是只有 `top` 和 `left`。现代 CSS 推荐尽量使用逻辑属性和更明确的偏移表达。

```css
.toast {
  position: fixed;
  inset-block-end: 24px;
  inset-inline-end: 24px;
}
```

`inset` 系列比单独写四个方向更清楚，也更适合国际化和书写方向变化。它表达的是“距离容器边缘多少”，比“左上角偏多少”更稳定。

在国际化页面里，尽量使用逻辑属性而不是死记 `left/right`。这样从左到右和从右到左的布局转换时，浮层、提示和固定按钮会更少出问题。

## 定位上下文

定位上下文不只影响位置，也影响层叠和裁剪。父级 `overflow`、`transform`、`filter`、`contain` 都可能改变浮层行为。

```css
.panel {
  overflow: hidden;
}

.tooltip {
  position: absolute;
}
```

如果 tooltip 被父级裁掉，问题不一定在 `z-index`，而可能是父容器裁剪了溢出。此时应该考虑把浮层挂到更高层容器，或者避免用裁剪容器承载弹层。

这也是很多项目里“浮层统一挂到 body 下”的原因。它并不是架构习惯，而是定位、裁剪和层级的综合取舍。把浮层从业务容器中抽离出来，通常更容易避免被 `overflow`、`transform` 和局部层叠上下文影响。

## sticky 失效

`sticky` 常被误以为“写了就会吸顶”。它失效通常有几个原因：没有设置阈值、父级滚动容器不对、祖先元素 overflow 干扰、可用滚动空间不够。

```css
.sidebar-title {
  position: sticky;
  top: 0;
}
```

```text
sticky 排查：
1. 是否设置了 top / inset-block-start
2. 父级是否真的是滚动容器
3. 祖先是否有 overflow 干扰
4. sticky 所在区域是否足够高
```

sticky 最适合“属于某段内容的局部吸顶”，例如目录、表头、分组标题。全局导航吸顶则要看页面结构和滚动容器设计。

如果 sticky 区域里有高层级内容，要额外给它背景色和层级，避免滚动时文字被后面内容透出来。吸顶元素看起来简单，实际上往往和遮罩、滚动条、边界阴影一起工作。

## 层级治理

`z-index` 不是越大越好。更重要的是建立层级体系，让弹窗、抽屉、下拉、提示、固定栏各自处在约定层。

```css
:root {
  --z-dropdown: 100;
  --z-sticky: 200;
  --z-modal: 1000;
  --z-toast: 1100;
}
```

层级治理的目标是避免“谁先写谁赢”。如果项目里每个组件都喜欢写一个很大的数字，后面排查遮挡会越来越难。

## 定位建议

定位适合局部叠放、角标、浮层和固定区域，不适合整页排版。页面级布局优先文档流、Flex、Grid；定位只负责补充那些“必须脱离流”的局部需求。

```text
优先顺序：
1. 正常流
2. Flex / Grid
3. 定位
4. 必要时 Portal 或顶层浮层
```

当某个元素的目标只是“看起来偏一点”，先考虑 margin 或 padding；当它需要脱离流程、覆盖内容、粘住视口，再考虑定位。
