## 自定义属性

CSS 自定义属性常被称为 CSS 变量，使用 `--name` 声明，通过 `var()` 读取。

```css
:root {
  --color-brand: #1677ff;
  --space-md: 16px;
}

.button {
  padding: var(--space-md);
  background: var(--color-brand);
}
```

自定义属性参与级联，会继承，也会受到选择器作用域影响。它不是预处理器变量，而是浏览器运行时可解析的 CSS 属性。

```css
.card {
  --card-bg: #fff;
  background: var(--card-bg);
}
```

变量的价值不是“写得短”，而是把设计系统里的 token 和组件实现连接起来。

CSS 自定义属性最大的特点是运行时参与层叠。Sass 变量在构建后就变成固定值，而 CSS 变量会随着 DOM 作用域、主题节点、组件状态实时变化。正因为如此，它非常适合主题切换、组件定制、运行时配置，不只是“少写几遍颜色”。

## 作用域与继承

自定义属性可以定义在局部容器中，让不同区域使用不同主题。

```css
.theme-dark {
  --surface: #111;
  --text: #fff;
}

.card {
  background: var(--surface);
  color: var(--text);
}
```

`.card` 会从最近的祖先中查找变量。这个特性非常适合主题、组件局部配置、设计系统 token。

```css
.sidebar {
  --space-md: 12px;
}
```

这表示同一个组件在不同容器里可以表现不同，只要变量命名和职责保持清晰。它和 [[1.2.9 响应式|响应式]]、[[1.2.6 层叠|层叠]] 都有关系，因为最终值既受作用域影响，也受后续规则覆盖。

作用域越局部，变量影响越可控。全站品牌色、基础字号这类 token 适合放在 `:root` 或主题节点；只影响卡片、按钮、图表的变量，最好放在组件根节点。不要把所有变量都塞到全局，否则后期很难判断某个值到底被谁覆盖。

## var 回退

`var()` 可以提供回退值。

```css
.tag {
  color: var(--tag-color, #666);
  background: var(--tag-bg, #f5f5f5);
}
```

当变量未定义或无效时，浏览器会使用回退值。组件库中常用这种方式提供默认样式，同时允许外部覆盖。

```css
.alert {
  padding: var(--alert-padding, 12px 16px);
}
```

回退值不是“兜底写法就完事”，而是给组件提供清晰默认值。若多个层级都依赖回退，说明 token 设计还不够完整。

回退值也适合做组件的默认 API。组件内部可以写 `var(--button-bg, var(--color-primary))`，表示外部可以覆盖按钮背景，否则使用语义色。这样既保留默认设计，又暴露了明确的定制入口，比外部强行覆盖 `.button` 更稳定。

## calc

`calc()` 可以在 CSS 中做长度计算，并且能和自定义属性组合。

```css
.layout {
  --sidebar-width: 240px;
  display: grid;
  grid-template-columns: var(--sidebar-width) calc(100% - var(--sidebar-width));
}
```

`calc()` 适合表达与容器、视口、固定区域相关的尺寸关系。注意运算符两边需要空格，例如 `calc(100% - 240px)`。

```css
.toolbar {
  width: calc(100% - 32px);
}
```

它的价值在于把“固定值 + 相对值”的关系表达清楚，而不是用 JS 先算再塞回样式里。

`calc()` 特别适合表达“减去固定区域后的剩余空间”，例如顶部栏高度、侧边栏宽度、表单标签宽度、视口安全区。只要关系属于布局本身，就应优先放在 CSS 里；只有关系来自业务数据或复杂测量时，才考虑 JS 计算。

## min max clamp

`min()`、`max()`、`clamp()` 常用于响应式尺寸。

```css
.page {
  width: min(100%, 960px);
  padding-inline: clamp(16px, 4vw, 40px);
}

.title {
  font-size: clamp(24px, 5vw, 48px);
}
```

`clamp(最小值, 理想值, 最大值)` 很适合控制移动端和桌面端之间的平滑变化，避免纯 `vw` 在极端屏幕上过大或过小。

```css
.sidebar {
  width: max(240px, 20vw);
}
```

这些函数常和 [[1.2.10 单位|单位]] 一起使用。单位负责“怎么表达”，函数负责“怎么限制边界”。

`min()`、`max()`、`clamp()` 的价值是把边界写进声明里。响应式页面里最怕“无限变大”和“无限变小”，而这些函数能让字号、间距、宽度在合理范围内连续变化。它们不是炫技语法，而是减少断点和魔法数字的工具。

## 主题切换

CSS 变量可以配合属性选择器实现主题切换。

```css
:root {
  --surface: #ffffff;
  --text: #1f2937;
}

[data-theme="dark"] {
  --surface: #111827;
  --text: #f9fafb;
}

body {
  background: var(--surface);
  color: var(--text);
}
```

```js
document.documentElement.dataset.theme = "dark";
```

这种方案的优势是切换主题时不需要重新生成 CSS，也不需要大量切换 class。浏览器会重新计算受变量影响的样式。

```css
:root {
  --radius-md: 8px;
  --shadow-sm: 0 1px 2px rgb(0 0 0 / 8%);
}
```

设计系统里常见的做法是把颜色、间距、圆角、阴影、字号等都变成 token，这样组件样式只关心 token，不关心每个主题的具体值。

主题切换时要注意首屏闪烁。用户偏好通常可以从系统 `prefers-color-scheme`、本地存储或服务端配置获得。如果页面先按浅色渲染，再由 JS 切到深色，就可能出现闪一下的问题。更稳的方式是在 HTML 初始阶段尽早写入主题属性，或让服务端直接输出正确主题。

## 与预处理器变量

Sass/Less 变量在构建期处理，CSS 自定义属性在运行时生效。

| 能力 | Sass/Less 变量 | CSS 自定义属性 |
|---|---|---|
| 生效时机 | 构建期 | 运行时 |
| 是否参与级联 | 否 | 是 |
| 是否可被 JS 修改 | 间接 | 可以 |
| 是否适合主题 | 一般 | 很适合 |
| 是否可做复杂编译逻辑 | 强 | 弱 |

设计系统中常见做法是：构建期 token 负责生成基础样式，运行时 CSS 变量负责主题和组件定制。

```css
/* 构建期可能输出 */
.button {
  border-radius: var(--radius-md);
}
```

如果变量需要在运行时动态切换，就优先用 CSS 自定义属性；如果需要编译期运算、循环、条件分支，再考虑 Sass/Less。

两者也可以配合使用：预处理器负责生成大量 token、循环输出工具类、管理设计配置；CSS 自定义属性负责运行时主题、组件局部覆盖和用户偏好。不要把运行时问题硬塞给 Sass，也不要用 CSS 变量模拟复杂编译逻辑。

## 无效值

变量存在不代表值一定合法。

```css
.box {
  --gap: red;
  margin-top: var(--gap);
}
```

`red` 对 `margin-top` 无效，最终声明会失效。变量命名和用途要保持清晰，例如 `--color-*`、`--space-*`、`--radius-*`，避免把颜色变量用到尺寸属性里。

```css
.card {
  --space-md: 16px;
  gap: var(--space-md);
}
```

写变量时要考虑三件事：它代表什么、应该在哪一层定义、允许被谁覆盖。变量函数不是“魔法糖”，它的核心价值是把设计约束变成可维护的 CSS 数据。

变量命名最好表达用途，而不只是表达值。`--color-blue-600` 是基础色，`--color-primary` 是语义色，`--button-bg` 是组件槽位。三者都可能指向同一个颜色，但维护意义完全不同。直接在组件里使用基础色，会让主题切换和品牌调整更困难。

## token 分层

CSS 变量最适合承接设计 token。token 可以粗略分成基础 token、语义 token 和组件 token。

```css
:root {
  --color-blue-600: #1677ff;
  --color-red-600: #dc2626;

  --color-primary: var(--color-blue-600);
  --color-danger: var(--color-red-600);

  --button-bg: var(--color-primary);
  --button-text: #fff;
}
```

基础 token 表示原始设计值，语义 token 表示用途，组件 token 表示组件内部消费的值。这样主题切换时可以改语义 token，组件改版时可以改组件 token，不必到处替换具体颜色。

token 分层越清楚，组件越不容易被具体设计值绑死。比如危险按钮不应该直接写 `#dc2626`，而应使用 `--color-danger` 或 `--button-danger-bg`。当品牌色、深色模式、高对比模式发生变化时，只需要调整 token 映射，而不是搜索替换所有组件样式。

## 组件覆盖

组件使用变量时，要明确哪些变量允许外部覆盖，哪些只服务内部实现。

```css
.button {
  --button-padding: 8px 16px;
  --button-radius: 8px;
  padding: var(--button-padding);
  border-radius: var(--button-radius);
}

.toolbar .button {
  --button-padding: 6px 12px;
}
```

这类写法比直接覆盖 `.button` 的 padding 更柔和，因为它提供的是“定制入口”，而不是强行覆盖组件内部声明。

组件覆盖要控制入口数量。变量暴露太少，外部只能强覆盖；变量暴露太多，组件 API 会变得混乱。通常应该暴露颜色、尺寸、圆角、间距这类稳定定制点，不要把每一条内部样式都变成公共变量。

## @property

普通自定义属性默认继承，类型也不受约束。`@property` 可以注册自定义属性，声明语法类型、是否继承和初始值。

```css
@property --progress {
  syntax: "<number>";
  inherits: false;
  initial-value: 0;
}

.progress {
  --progress: 0.6;
  transform: scaleX(var(--progress));
}
```

`@property` 适合需要动画、类型约束或默认值更明确的变量。比如颜色、长度、数字进度，如果注册了类型，浏览器就能更可靠地插值和校验。

```css
@property --brand-color {
  syntax: "<color>";
  inherits: true;
  initial-value: #1677ff;
}
```

不是所有变量都需要注册。普通 token 和组件定制入口通常直接用自定义属性即可；需要动画或类型控制时再使用 `@property`。

`@property` 的一个重要价值是让自定义属性可以更可靠地动画。未注册的自定义属性通常按字符串处理，浏览器不知道如何在两个值之间插值；注册语法类型后，颜色、长度、数字这些值才更适合参与动画和校验。

## 函数组合

CSS 函数可以组合使用。`var()` 可以进入 `calc()`，`min()`、`max()`、`clamp()` 中也可以直接写计算表达式。

```css
.layout {
  --sidebar: 240px;
  grid-template-columns: var(--sidebar) minmax(0, 1fr);
}

.title {
  font-size: clamp(1.5rem, 1rem + 3vw, 3rem);
}
```

`clamp()` 的第二个值通常是“理想值”，可以是视口单位、百分比和相对单位的组合。它适合字号、间距、容器宽度这些需要平滑变化又不能失控的值。

```css
.article {
  width: min(100%, 72ch);
  padding-inline: max(16px, 4vw);
}
```

函数组合的重点不是写得复杂，而是把尺寸关系直接写在 CSS 里，减少 JS 计算和魔法数字。

函数组合要保持可读。`clamp(1rem, 0.5rem + 2vw, 2rem)` 这种表达还比较清楚；如果一条声明里嵌套多层 `calc()`、`min()`、`var()`，就要考虑拆成中间变量。CSS 也需要可维护性，不是能写在一行就一定更好。

## 运行时更新

CSS 变量可以被 JavaScript 修改，因此适合主题、用户配置、可视化参数、拖拽尺寸这类运行时样式。

```js
document.documentElement.style.setProperty("--accent", "#10b981");
```

```css
.chart {
  color: var(--accent);
}
```

但不要把所有动态样式都塞进全局变量。只影响一个组件的值，应设置在组件容器上；影响全站主题的值，才适合设置在 `:root` 或顶层主题节点上。

运行时更新还要注意频率。主题色、布局尺寸、拖拽进度这类低频或明确范围的值适合用变量；如果每一帧都大量修改全局变量，会触发大范围样式重算。动态范围越小，变量设置的位置就应该越靠近组件。

## 调试方法

变量问题可以直接在 DevTools 的 Computed 面板里查看最终值。排查时先看变量定义在哪一层，再看是否被覆盖、是否继承、是否值无效。

```text
变量排查：
1. 变量是否定义
2. 是否在当前元素可继承范围内
3. 是否被更近作用域覆盖
4. var() 是否有回退值
5. 变量值对当前属性是否合法
```

最常见的问题不是“变量没生效”，而是“变量生效了，但值对这个属性无效”。比如把颜色 token 用到长度属性里，声明会直接失效。

DevTools 里查看变量时，要同时看声明来源和最终计算值。某个变量可能在 `:root`、主题节点、组件根节点和局部状态上都定义过，最终生效的是离当前元素更近、层叠更高的那个。变量调试本质上也是层叠调试。

## 使用边界

CSS 变量适合表达设计值、主题值、组件可配置项和运行时样式参数；不适合承载复杂业务逻辑。

| 场景 | 适合程度 |
| --- | --- |
| 主题颜色 | 很适合 |
| 间距、圆角、阴影 token | 很适合 |
| 组件变体参数 | 适合 |
| JS 运行时可视化参数 | 适合 |
| 媒体查询断点 | 不直接适合 |
| 复杂条件分支 | 不适合 |

变量函数的价值在于把 CSS 的“值”管理起来。它不能替代组件设计，也不能替代样式分层；变量越多，命名和边界越要清楚。

如果项目里变量数量越来越多，可以定期检查三类问题：是否有变量没人使用，是否有多个变量表达同一个含义，是否有组件变量泄漏成全局约定。变量系统和代码一样，也需要治理，否则会从“统一设计”变成“另一种全局混乱”。
