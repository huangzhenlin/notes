## 一维布局

Flexbox 适合一维布局：要么沿横向排列，要么沿纵向排列。它解决的是一条轴上的分布、对齐、收缩和伸展问题。

```css
.toolbar {
  display: flex;
  align-items: center;
  gap: 12px;
}
```

按钮组、导航栏、卡片内部排列、左右对齐，通常都适合用 Flex。复杂二维网格更适合 Grid。

```html
<header class="toolbar">
  <h1 class="brand">前端笔记</h1>
  <nav class="menu">
    <a href="/">首页</a>
    <a href="/articles">文章</a>
  </nav>
</header>
```

Flex 最擅长的是“内容长度不固定，但要沿某个方向稳定排布”的场景。它比用 `float`、`inline-block` 拼布局更直接，也更容易配合 `gap` 和对齐规则。

Flex 在真实项目里最常见的价值，不是把东西摆成一排，而是让一排里的内容可以自然适应。按钮文案会变长，导航项会增减，标题可能一行也可能两行，Flex 适合这种“沿一个方向变化，但整体关系不能乱”的情况。

## 主轴与交叉轴

`flex-direction` 决定主轴方向。`row` 是默认横向，`column` 是纵向，`row-reverse` 和 `column-reverse` 会改变视觉顺序，但不会改变 DOM 顺序。

```css
.row {
  display: flex;
  flex-direction: row;
}

.column {
  display: flex;
  flex-direction: column;
}
```

`justify-content` 控制主轴分布，`align-items` 控制交叉轴对齐。

```css
.header {
  display: flex;
  justify-content: space-between;
  align-items: center;
}
```

Flex 问题里最常见的误解，就是把主轴和交叉轴弄反。可以先记住：`justify-*` 处理“沿着排布方向怎么分”，`align-*` 处理“垂直于排布方向怎么对齐”。

| 属性 | 作用方向 | 常见用途 |
| --- | --- | --- |
| `justify-content` | 主轴 | 两端分布、居中、间距分配 |
| `align-items` | 交叉轴 | 垂直居中、顶部对齐、基线对齐 |
| `align-self` | 单个子项交叉轴 | 局部覆盖对齐 |
| `align-content` | 多行交叉轴 | 多行对齐 |

如果视觉顺序和阅读顺序不同，要特别小心键盘顺序和辅助技术顺序。反向布局适合少量视觉排列，不适合大段内容结构。

在复杂页面里，主轴和交叉轴往往还要和 `gap`、`align-content`、`flex-wrap` 一起考虑。只盯着居中与分布，很容易忽略换行后的对齐和第二行的间距。Flex 很适合做工具栏、标签组、按钮组，但如果开始关心“多行之间怎么排”，就要确认它是不是已经接近 Grid 的职责边界。

## flex-grow

`flex-grow` 控制剩余空间如何分配。

```css
.search-input {
  flex: 1;
}
```

`flex: 1` 常用于让某个元素占据剩余空间，例如导航栏中的搜索框。

```css
.layout {
  display: flex;
}

.sidebar {
  width: 240px;
}

.main {
  flex: 1;
}
```

`flex-grow` 的本质是“空间有多余时分给谁、分多少”。它适合主内容扩展、输入框拉伸、表单列自适应。

很多人把 `flex: 1` 当成“自动撑满”，但它其实是在一组兄弟里参与剩余空间分配。也就是说，谁有 `flex-grow`、谁有固定宽度、谁允许收缩，决定了最终布局。理解这一点后，侧边栏 + 主内容 + 辅助栏这类页面就容易很多。

```css
.field {
  display: flex;
  gap: 12px;
}

.field-label {
  flex: 0 0 120px;
}

.field-control {
  flex: 1;
}
```

这种写法在表单中很常见：标签固定宽度，输入区域吃掉剩余空间。它比手写百分比更容易在不同容器宽度下保持稳定。和 [[1.2.8 Grid|Grid]] 相比，Flex 更适合这种单行对齐。

## flex-shrink

`flex-shrink` 控制空间不足时是否收缩。

```css
.avatar {
  flex-shrink: 0;
  width: 40px;
  height: 40px;
}
```

头像、图标、固定按钮通常不希望被压缩；文本区域可以收缩并配合省略。

```css
.title {
  min-width: 0;
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}
```

`flex-shrink` 和 `min-width: 0` 经常一起出现。Flex 子项默认可能不愿意比内容更窄，导致文本省略不生效或容器被撑开。

`min-width: 0` 在 Flex 里几乎是最容易被忽略的小属性之一。很多“标题省略不生效”“内容把布局撑爆”的问题，都不是 `overflow` 写错，而是子项最小宽度默认限制了收缩。只要确认哪个子项应该真正缩小，通常就能更快修好。

```html
<div class="row">
  <img class="avatar" src="/avatar.png" alt="" />
  <div class="content">
    <h3 class="title">一个很长很长很长的标题</h3>
  </div>
</div>
```

如果某个子项被压缩得太狠，先想想它是否应该禁用 shrink，或者给内容层加 `min-width: 0`。

## flex-basis

`flex-basis` 表示元素在主轴上的基础尺寸。它决定在分配剩余空间前，这个项目先按多大参与计算。

```css
.card {
  flex: 0 0 280px;
}
```

`flex: 0 0 280px` 表示不放大、不缩小、基础宽度 280px。横向滚动卡片常用这种写法。

```css
.cards {
  display: flex;
  gap: 16px;
  overflow-x: auto;
}

.card {
  flex: 0 0 280px;
}
```

`flex-basis` 不是单纯“宽度别名”，它会参与 Flex 的伸缩计算。写卡片流、票据流、横向列表时，用它比单纯 `width` 更符合 Flex 语义。

如果一个横向列表里的卡片有固定起点尺寸，但又要允许容器空间变化，`flex-basis` 往往比 `width` 更准确。它表达的是“先按这个基础尺寸开始算，再参与剩余空间分配”，这比单纯写死宽度更适合可伸缩布局。

## 换行

默认 Flex 子项不换行。需要换行时使用 `flex-wrap`。

```css
.tags {
  display: flex;
  flex-wrap: wrap;
  gap: 8px;
}
```

多行标签、按钮组可以用 wrap。真正的卡片网格通常 Grid 更清楚，因为 Grid 能同时管理行和列。

```css
.actions {
  display: flex;
  flex-wrap: wrap;
  justify-content: flex-end;
  gap: 8px;
}
```

如果一行内按钮太多，wrap 比硬压缩更稳。但要注意换行后的视觉顺序和键盘顺序仍然必须合理。

换行布局里最常出现的问题是最后一行空洞、按钮对齐不齐、卡片宽度变化导致视觉断层。此时如果布局开始依赖“每个子项多宽”的精确控制，可能就已经该换 Grid 了。Flex 的强项是顺流排列，不是行列编舞。

## gap

`gap` 是 Flex 中最推荐的间距方式之一。它直接表达子项之间的空隙，不需要给每个子项手写 margin。

```css
.tag-list {
  display: flex;
  flex-wrap: wrap;
  gap: 8px;
}
```

`gap` 的好处是不会产生首尾多余间距，也不会和子项边距叠加。它很适合按钮组、标签组、工具栏、卡片内部组件排列。

在旧项目里常见的“子项加 margin，最后一个再清掉”的写法，通常都可以被 `gap` 简化。只要浏览器支持范围满足，优先用 `gap` 会让组件组合更干净，也更不容易出现首尾间距不一致。

## 基线对齐

`align-items: baseline` 适合图标和文字、表单项标题、价格和单位这种需要对齐文字基线的组合。

```css
.price-row {
  display: flex;
  align-items: baseline;
  gap: 4px;
}
```

如果元素字体大小差异大，基线对齐会比居中更自然。很多“看起来歪一点”的问题，其实不是高度问题，而是基线没有对齐。

文字和图标混排时，`align-items: center` 看起来简单，但并不总是最佳。价格、单位、标签、说明文字这些元素经常更适合基线对齐，因为视觉感受上它们本来就属于同一行文本语境。

## 文本省略

Flex 子项里的文本省略经常需要设置 `min-width: 0`。

```css
.item {
  display: flex;
  gap: 8px;
}

.title {
  min-width: 0;
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}
```

`text-overflow` 只有在元素真的发生溢出时才生效，它需要配合 `overflow` 和 `white-space` 一起使用。

```html
<div class="item">
  <span class="title">非常非常长的标题文本</span>
</div>
```

多行截断通常比单行省略更容易引起信息丢失，关键内容最好提供完整查看入口，而不是只靠省略。

如果文本是主标题，省略后最好仍能通过 `title`、详情页或展开区域看到完整内容。Flex 布局里的省略不是终点，而是一个展示策略。只要内容对用户很重要，就不能把“省略后看不全”当成最终方案。

## 常见模式

Flex 常见的布局模式可以直接套用：

```css
/* 左右分布 */
.header {
  display: flex;
  justify-content: space-between;
  align-items: center;
}

/* 垂直堆叠 */
.stack {
  display: flex;
  flex-direction: column;
  gap: 12px;
}

/* 标签包裹 */
.chip-row {
  display: flex;
  flex-wrap: wrap;
  gap: 8px;
}
```

这些模式本质上都是：一条轴上的排列、对齐和伸缩。模式越稳定，越适合封装成组件层样式。

## 使用边界

| 场景 | 推荐 |
| --- | --- |
| 单行水平对齐 | Flex |
| 垂直居中 | Flex |
| 标签换行 | Flex wrap |
| 复杂卡片网格 | Grid |
| 页面大结构 | Grid 或 Flex |
| 两列自适应表单 | Flex 或 Grid |

Flex 解决的是一条轴上的分布问题。写 Flex 前先问：这个布局主要沿一个方向排列吗？如果答案是肯定的，Flex 通常比表格或绝对定位更自然。如果同时要管行和列，优先考虑 Grid。

Flex 和 Grid 不是谁替代谁，而是不同颗粒度的问题。组件内部一维排列、按钮组、导航条、表单行，Flex 更顺手；页面级骨架、内容区 + 侧栏、卡片墙、仪表盘，Grid 更自然。选对布局机制，后续维护会省很多力气。
