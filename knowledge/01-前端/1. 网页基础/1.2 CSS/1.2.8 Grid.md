## 二维布局

CSS Grid 适合二维布局，可以同时控制行和列。它和 Flex 的区别是：Flex 更适合一维排列，Grid 更适合页面结构和网格区域。

```css
.layout {
  display: grid;
  grid-template-columns: 240px 1fr;
  grid-template-rows: auto 1fr;
  min-height: 100vh;
}
```

侧边栏 + 内容区、卡片网格、仪表盘、复杂表单，都很适合用 Grid。

```html
<main class="layout">
  <aside>侧边栏</aside>
  <section>主内容</section>
</main>
```

如果布局需要同时关心“列怎么分”和“行怎么排”，Grid 往往比 Flex 更直接。和 [[1.2.7 Flex|Flex]] 相比，Grid 更像页面结构语言，Flex 更像组件排列语言。

Grid 的思维方式是先定义容器里的“轨道”，再把子项放进轨道中。它不像 Flex 那样主要依赖内容顺流分布，而是先建立布局骨架。页面壳、仪表盘、卡片墙、复杂表单之所以适合 Grid，就是因为它们的布局关系往往先于单个子项内容存在。

## 网格轨道

`grid-template-columns` 和 `grid-template-rows` 定义列轨道和行轨道。

```css
.grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 16px;
}
```

`repeat(3, 1fr)` 表示三列等分剩余空间。`gap` 控制行列间距，不需要给子项手写 margin。

```css
.dashboard {
  display: grid;
  grid-template-columns: 280px 1fr 320px;
  gap: 24px;
}
```

固定侧栏、主内容、信息侧栏的组合非常适合网格轨道。轨道不是元素本身，而是容器给子项预留的布局骨架。

轨道设计要避免过度固定。固定侧栏可以稳定导航，主内容区应该允许伸缩，辅助栏则要考虑在窄屏时是否折叠或下移。一个好的 Grid 布局通常会把“必须固定”和“可以自适应”的部分分得很清楚。

## fr 单位

`fr` 表示网格容器中的剩余空间份额。

```css
.layout {
  display: grid;
  grid-template-columns: 200px 1fr 280px;
}
```

固定侧栏用 `px`，主内容用 `fr`，能让页面既稳定又自适应。`fr` 的真正价值是把“剩余空间”表达得很清楚。

```css
.article-grid {
  display: grid;
  grid-template-columns: 2fr 1fr;
}
```

这里左侧内容占两份，右侧占一份，适合正文 + 侧栏的内容页。不要把 `fr` 当成 `flex-grow` 的直接替代，它属于 Grid 的轨道分配。

`fr` 分配的是网格容器剩余空间，不是元素自身随便长大。内容如果有很长单词、图片、表格或代码块，仍然可能撑开轨道，所以复杂布局里经常配合 `minmax(0, 1fr)` 使用，让轨道真正允许缩小。

## minmax

`minmax()` 可以限制轨道最小和最大尺寸。

```css
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(240px, 1fr));
  gap: 16px;
}
```

这段代码适合响应式卡片：空间足够时多列，不足时自动减少列数。它比手写多个媒体查询更简洁。

```css
.sidebar-layout {
  display: grid;
  grid-template-columns: minmax(180px, 240px) minmax(0, 1fr);
}
```

左侧栏有最小和最大宽度，右侧内容允许缩小到 0，避免内容区被撑破。`minmax(0, 1fr)` 在复杂布局里尤其常见。

这条规则在后台布局、文档布局、代码预览布局里都很实用。没有 `minmax(0, 1fr)` 时，主内容区可能会因为内部表格、代码块或长标题撑开整个页面，导致侧栏和视口一起被挤走。Grid 的轨道能伸缩，不代表内容一定会乖乖收缩。

## 显式网格

显式网格由 `grid-template-columns` 和 `grid-template-rows` 定义。它适合页面骨架、仪表盘、表单布局、内容分栏。

```css
.page-shell {
  display: grid;
  grid-template-columns: 240px minmax(0, 1fr);
  grid-template-rows: auto 1fr auto;
  min-height: 100vh;
}
```

显式网格的好处是结构清楚，适合页面级布局；坏处是轨道太死时，对内容变化的适应能力会变差。

显式网格更适合稳定区域，比如 header、sidebar、main、footer。它的优势是可读性强，团队一眼能看出页面结构；风险是如果把每个小模块都写成显式轨道，改版时会牵一发动全身。页面骨架显式，内容列表自动，通常是更平衡的做法。

## 隐式网格

当子项超出显式定义的网格时，Grid 会自动创建隐式轨道。

```css
.cards {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  grid-auto-rows: 200px;
}
```

隐式网格在卡片墙、消息流、图片墙里很常见。如果没控制好 `grid-auto-flow` 和 `grid-auto-rows`，布局很容易变得不均匀。

隐式网格的核心是“容器帮你继续生成轨道”。它适合数量不确定的列表，但要给自动生成的行列设定合理边界。否则内容高度差异、图片比例差异、卡片内文本长度都会让视觉节奏变得松散。

## 区域布局

`grid-template-areas` 可以让页面结构更直观。

```css
.page {
  display: grid;
  grid-template-areas:
    "header header"
    "sidebar main";
  grid-template-columns: 240px 1fr;
}

.header {
  grid-area: header;
}

.sidebar {
  grid-area: sidebar;
}

.main {
  grid-area: main;
}
```

区域布局适合大块页面结构，不适合特别细碎的局部排列。它的好处是结构一眼能看懂，坏处是改版时如果区域图写得太死，响应式切换会变麻烦。

```css
@media (max-width: 768px) {
  .page {
    grid-template-areas:
      "header"
      "main"
      "sidebar";
    grid-template-columns: 1fr;
  }
}
```

这也是 Grid 和响应式天然相连的地方：同一份结构在不同断点下可以换区域顺序。

区域布局虽然可读，但不要让视觉顺序严重背离 DOM 顺序。Grid 可以改变区域视觉位置，但键盘顺序和读屏顺序仍然主要来自文档顺序。如果移动端把侧栏放到正文之后，HTML 本身也最好按合理阅读顺序组织。

## 自动放置

Grid 会自动把未指定位置的子项放入网格。

```css
.gallery {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(160px, 1fr));
  grid-auto-rows: 160px;
  gap: 12px;
}
```

`auto-fill` 会尽可能创建列，`auto-fit` 会折叠空列。两者差异在响应式卡片中很常见，需要结合实际效果选择。

```html
<ul class="gallery">
  <li>1</li>
  <li>2</li>
  <li>3</li>
</ul>
```

自动放置适合相似内容的卡片墙、图片墙、标签墙。如果每个区域的内容类型差异很大，还是手动定义区域更清晰。

`auto-fill` 和 `auto-fit` 的区别可以从“空轨道是否保留”理解。`auto-fill` 更像先把可用槽位占出来，即使没有内容也保留列；`auto-fit` 会把空列折叠，让已有项目拉伸填满空间。多数自适应卡片列表先试 `auto-fit`，如果需要保留网格槽位感，再考虑 `auto-fill`。

## 自动适配

`repeat(auto-fit, minmax())` 和 `repeat(auto-fill, minmax())` 是响应式 Grid 的常用写法。

```css
.gallery {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
  gap: 16px;
}
```

`auto-fit` 更关注把可用列拉满，空列会折叠；`auto-fill` 更倾向保留可能的列槽。卡片墙通常优先试 `auto-fit`，看空白是否更自然。

自适应 Grid 不代表不需要设计断点。`minmax(220px, 1fr)` 能自动减少列数，但卡片内部图片比例、标题行数、按钮换行、操作区高度仍然需要组件自己处理。Grid 解决外部轨道，组件还要负责内部内容弹性。

## 子项放置

Grid 子项可以通过行列线、区域名或自动放置定位。

```css
.hero {
  grid-column: 1 / -1;
}
```

`-1` 表示最后一条网格线。很多全宽区块、横跨卡片、页头横幅都能用这种方式表达。

子项放置要克制使用。少量横跨、重点卡片、广告位可以手动指定位置；如果每个子项都写行列坐标，网格就会变成另一种绝对定位。自动放置和少量显式放置结合，通常更容易维护。

## 对齐方式

Grid 可以控制整体和单元格内部对齐。

```css
.grid {
  display: grid;
  place-items: center;
  justify-content: center;
  align-content: start;
}
```

`justify-*` 通常控制行内方向，`align-*` 控制块方向；`place-*` 是简写。遇到对齐问题时，先区分对齐的是网格轨道、网格项，还是网格容器内的整体网格。

```css
.card {
  display: grid;
  align-items: center;
  gap: 12px;
}
```

Grid 的对齐比 Flex 更适合二维场景，例如表单里标签和输入框的行列对齐。复杂对齐时，Grid 往往比大量 margin 更稳定。

表单是 Grid 很典型的场景：标签列、控件列、错误提示列可以形成稳定轨道。这样不同字段的标签长度不一样，输入框仍然能对齐；移动端再切换成单列，也比逐项写 margin 更清楚。

## 自适应卡片

`minmax()` 和 `fr` 的组合是卡片布局里最实用的写法之一。

```css
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(240px, 1fr));
  gap: 16px;
}
```

这类写法的核心不是“省代码”，而是把“卡片至少多宽、最多怎样分配空间”写清楚。对内容型页面来说，这比给几个固定断点更自然。

卡片网格还要关注“内容高度不一致”。如果卡片底部按钮需要对齐，可以让卡片本身也使用 Grid 或 Flex，把正文区域设为可伸缩，让操作区自然贴底。外层 Grid 管列，内层布局管卡片内容，不要把所有问题都塞给外层网格。

## 使用边界

| 场景 | 推荐 |
| --- | --- |
| 导航横向排列 | Flex |
| 卡片自适应网格 | Grid |
| 页面左右结构 | Grid |
| 表单标签和输入对齐 | Grid |
| 单行按钮组 | Flex |
| 复杂仪表盘 | Grid |

Grid 和 Flex 不是替代关系。页面结构常用 Grid，组件内部一维排列常用 Flex。写布局前先判断：你是在排一行内容，还是在组织一个二维页面骨架。

如果一个布局用 Flex 写起来需要大量宽度、换行、nth-child 和 margin 修补，通常说明它已经更像 Grid 问题；如果用 Grid 写一个简单按钮组，需要定义很多轨道，说明 Flex 更合适。布局选择的目标不是用高级语法，而是让代码表达真实结构。
