## 推断来源

TypeScript 会根据初始化值、函数返回值、上下文位置和控制流自动推断类型。类型推断的目标是减少重复标注，同时保留静态检查能力。

```typescript
const name = 'Ada'; // 推断为 'Ada'
let age = 28; // 推断为 number
const enabled = true; // 推断为 true
```

`const` 变量因为不会被重新赋值，字面量更容易被保留下来；`let` 变量可能变化，所以通常会被放宽成更通用的类型。

## 字面量放宽

字面量放宽是 TypeScript 为了让变量可继续赋值而做的推断策略。

```typescript
let status = 'idle';
status = 'loading';
```

这里 `status` 被推断为 `string`，而不是 `'idle'`。如果需要限定状态范围，应该显式声明联合类型。

```typescript
type Status = 'idle' | 'loading' | 'success' | 'error';

let status: Status = 'idle';
```

字面量推断和业务状态建模关系很近。字符串字面量适合普通文本，联合字面量适合有限枚举状态。

## `as const`

`as const` 会把对象或数组推断成更窄、更只读的类型。它常用于配置、路由表、枚举映射和字面量集合。

```typescript
const routes = {
  home: '/',
  detail: '/detail/:id',
} as const;

type RouteName = keyof typeof routes;
```

数组使用 `as const` 后会变成只读元组。

```typescript
const sizes = ['small', 'medium', 'large'] as const;
type Size = typeof sizes[number];
```

这种写法比手写重复联合类型更稳，因为类型直接来自数据本身。

## 最佳公共类型

数组中多个元素类型不完全一致时，TypeScript 会推断一个能覆盖所有元素的公共类型。

```typescript
const items = [1, '2', true]; // (string | number | boolean)[]
```

对象数组也会发生类似推断。

```typescript
const list = [
  { type: 'text', value: 'hello' },
  { type: 'image', src: '/cover.png' },
];
```

如果后续要按 `type` 做分支，最好显式声明可辨识联合，避免推断结果过宽或不符合业务语义。

```typescript
type Block =
  | { type: 'text'; value: string }
  | { type: 'image'; src: string };
```

## 上下文类型

上下文类型是指 TypeScript 根据“这个表达式被放在什么位置”来推断类型。事件回调、数组方法、组件 props、函数参数都很常见。

```typescript
const names = ['Ada', 'Grace'];

names.map((name) => name.toUpperCase());
```

这里 `name` 被推断为 `string`，因为 `names` 是 `string[]`。

```typescript
button.addEventListener('click', (event) => {
  event.preventDefault();
});
```

这里 `event` 会根据 `click` 推断为鼠标事件相关类型。上下文推断让很多回调不必手动标注，但前提是上游类型足够清楚。

## 返回值推断

函数返回值可以由 `return` 推断。局部工具函数通常可以省略返回类型，公共 API、库函数、复杂业务函数建议显式标注。

```typescript
function sum(a: number, b: number) {
  return a + b;
}
```

复杂函数如果不写返回类型，可能在重构中不小心改变对外契约。

```typescript
type LoginResult =
  | { ok: true; token: string }
  | { ok: false; reason: string };

async function login(email: string, password: string): Promise<LoginResult> {
  return { ok: false, reason: 'invalid_password' };
}
```

返回类型也是模块边界的一部分。对外函数显式写返回类型，可以防止实现细节泄漏成 API。

## 控制流收窄

TypeScript 会根据条件判断收窄类型。常见收窄方式包括 `typeof`、`instanceof`、`in`、判空和可辨识字面量。

```typescript
function format(value: string | number) {
  if (typeof value === 'string') {
    return value.toUpperCase();
  }

  return value.toFixed(2);
}
```

可辨识联合是控制流收窄最清晰的用法。

```typescript
type LoadState =
  | { status: 'loading' }
  | { status: 'success'; data: string[] }
  | { status: 'error'; error: string };

function render(state: LoadState) {
  if (state.status === 'success') {
    return state.data.join(',');
  }

  if (state.status === 'error') {
    return state.error;
  }

  return '加载中';
}
```

## 推断边界

推断也有边界。空数组、空对象、JSON 结果、第三方库、动态属性、复杂泛型经常需要显式标注。

```typescript
const users = []; // 可能推断为 never[] 或 any[]，取决于配置和上下文

type User = { id: string; name: string };
const typedUsers: User[] = [];
```

```typescript
const data: unknown = await response.json();
```

来自外部世界的数据，不应该直接相信推断。

## 标注策略

一个实用原则是：局部实现依赖推断，公共边界显式标注。

| 位置 | 建议 |
|---|---|
| 局部变量 | 优先推断 |
| 函数参数 | 通常标注 |
| 公共函数返回值 | 建议标注 |
| API 响应 | 显式建模 |
| 空数组和空对象 | 显式标注 |
| 配置常量 | 可用 `as const` |

类型推断和 [[1.5.1 基础类型|基础类型]] 互补：基础类型定义值的边界，推断帮助编译器在合理位置自动补全这些边界。
