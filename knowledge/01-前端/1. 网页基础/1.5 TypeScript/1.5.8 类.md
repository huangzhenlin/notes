## 类声明

TypeScript 的类建立在 JavaScript `class` 语法之上，并增加类型标注、访问修饰符、抽象类等能力。类既是运行时值，也是类型位置上的实例类型。

```typescript
class User {
  name: string;

  constructor(name: string) {
    this.name = name;
  }

  sayHello() {
    return `Hello, ${this.name}`;
  }
}

const user = new User('Ada');
```

类适合需要封装状态和行为的场景，例如服务对象、存储适配器、UI 控制器、领域对象。

## 构造函数

构造函数用于初始化实例。参数属性可以减少重复声明。

```typescript
class Product {
  constructor(
    public id: string,
    public title: string,
    private price: number,
  ) {}

  getPrice() {
    return this.price;
  }
}
```

构造参数属性适合“构造时就要注入并保存”的字段。构造函数不适合塞太多副作用，复杂初始化可以拆成静态工厂方法。

```typescript
class UserService {
  constructor(private readonly baseURL: string) {}
}
```

## 访问修饰符

TypeScript 提供 `public`、`private`、`protected`。

```typescript
class BaseService {
  public name = 'base';
  protected baseURL = '/api';
  private token = '';
}
```

| 修饰符 | 可访问范围 |
|---|---|
| `public` | 类内、子类、外部 |
| `protected` | 类内、子类 |
| `private` | 当前类内部 |

`private` 主要是类型检查层面的限制。如果需要运行时私有字段，可以用 JavaScript 的 `#field`。

```typescript
class Counter {
  #count = 0;

  increment() {
    this.#count += 1;
  }
}
```

## `readonly`

`readonly` 表示属性只能在声明时或构造函数中赋值。

```typescript
class Config {
  readonly appId: string;

  constructor(appId: string) {
    this.appId = appId;
  }
}
```

它适合标识、配置、只读元信息。它不是深冻结，对象内部的引用内容仍然可能被修改。

## 继承

类可以通过 `extends` 继承父类，并通过 `super` 调用父类构造函数或方法。

```typescript
class Animal {
  constructor(public name: string) {}

  move() {
    return `${this.name} is moving`;
  }
}

class Dog extends Animal {
  bark() {
    return `${this.name} says woof`;
  }
}
```

继承适合明确的“是一种”关系。普通业务里更多时候应该用组合，把能力拆成独立函数或对象。

## 实现接口

类可以通过 `implements` 声明自己满足某个接口。

```typescript
interface Repository<T> {
  findById(id: string): Promise<T | null>;
  save(entity: T): Promise<void>;
}

class UserRepository implements Repository<User> {
  async findById(id: string) {
    return request<User>(`/users/${id}`);
  }

  async save(user: User) {
    await request('/users', {
      method: 'POST',
      body: JSON.stringify(user),
    });
  }
}
```

`implements` 只检查实例侧结构，不会改变运行时代码。它适合服务类、仓储、适配器、策略对象。

## 抽象类

抽象类不能直接实例化，可以定义子类必须实现的方法，也可以提供共享实现。

```typescript
abstract class ViewModel {
  loading = false;

  abstract load(): Promise<void>;

  setLoading(value: boolean) {
    this.loading = value;
  }
}

class UserViewModel extends ViewModel {
  async load() {
    this.setLoading(true);
    await fetchUser();
    this.setLoading(false);
  }
}
```

抽象类适合“既要约束，又要共享实现”的场景。如果只是想约束结构，接口通常更轻。

## 静态成员

`static` 成员属于类本身，不属于实例。

```typescript
class DateFormatter {
  static format(date: Date) {
    return date.toISOString().slice(0, 10);
  }
}
```

静态成员适合与类语义强相关的工厂方法、常量和纯工具方法。若只是通用函数，放在普通函数里通常更清楚。

## 结构化类型

TypeScript 是结构化类型系统。两个类只要实例结构兼容，就可以互相赋值。

```typescript
class Point2D {
  constructor(public x: number, public y: number) {}
}

class Vector2D {
  constructor(public x: number, public y: number) {}
}

const point: Point2D = new Vector2D(1, 2);
```

如果类包含 `private` 或 `protected` 成员，兼容性会更严格。理解这一点能解释为什么“两个不同类也能互相赋值”。

## 使用边界

类适合状态和行为都比较稳定的场景。

| 场景 | 是否适合 |
|---|---|
| 服务对象 | 适合 |
| 存储适配器 | 适合 |
| UI 控制器 | 适合 |
| 大量纯函数工具 | 不一定 |
| 简单数据结构 | 不一定 |
| 需要频繁拆分组合的业务 | 不一定 |

如果只是表达一组无状态函数，模块函数往往更简单。类的价值在于把实例状态、方法共享和契约约束放在一起。
