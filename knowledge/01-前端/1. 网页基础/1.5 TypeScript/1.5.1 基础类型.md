## 类型系统边界

TypeScript 的类型只在编译阶段生效，不会改变 JavaScript 的运行时行为。它的价值是提前描述值的形状、约束调用方式、暴露潜在错误。

```typescript
const title: string = 'TypeScript';
const count: number = 10;
const visible: boolean = false;
```

编译后类型会被擦除，运行时仍然是普通 JavaScript。因此外部数据、接口响应、用户输入仍然需要运行时校验。

```typescript
const value: unknown = JSON.parse('{"name":"Ada"}');
```

类型不是数据验证器。TypeScript 能约束“你写出来的代码”，不能保证“外部传进来的数据一定正确”。

## 原始类型

TypeScript 的基础类型建立在 JavaScript 运行时类型之上：`string`、`number`、`boolean`、`bigint`、`symbol`、`null`、`undefined` 都对应真实的 JavaScript 值。

```typescript
const name: string = 'Ada';
const age: number = 32;
const enabled: boolean = true;
const id: bigint = 100n;
const key: symbol = Symbol('cache');
```

`number` 同时表示整数和浮点数，没有 `int`、`float` 这类细分类型。金额、像素、毫秒这类语义不同但同为数字的值，可以用类型别名提升可读性。

```typescript
type Milliseconds = number;
type Pixel = number;

function delay(ms: Milliseconds) {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

function setWidth(width: Pixel) {
  document.body.style.width = `${width}px`;
}
```

这些别名不会带来真正的运行时隔离，但能让业务含义更清楚。

## 空值

`null` 和 `undefined` 是否能赋给其他类型，取决于 `strictNullChecks`。工程项目应尽量开启严格空值检查，让“值可能缺失”成为显式类型。

```typescript
let name: string | undefined;

function greet(value: string | undefined) {
  if (value === undefined) {
    return '匿名用户';
  }

  return value.toUpperCase();
}
```

可选属性不等于属性一定存在且值为 `undefined`。读取可选属性时，要处理缺失路径。

```typescript
type User = {
  id: string;
  profile?: {
    city?: string;
  };
};

function getCity(user: User) {
  return user.profile?.city ?? '未知';
}
```

## 数组类型

数组可以写成 `T[]` 或 `Array<T>`，两者语义相同。

```typescript
const names: string[] = ['Ada', 'Grace'];
const scores: Array<number> = [98, 95, 90];

names.push('Linus');
// names.push(123); // 类型错误
```

数组类型只约束元素类型，不约束长度。普通列表、接口数组、表格数据通常使用数组。

```typescript
type User = {
  id: string;
  name: string;
};

function getUserNames(users: User[]) {
  return users.map((user) => user.name);
}
```

如果调用方不应该修改数组，可以使用只读数组。

```typescript
function sum(values: readonly number[]) {
  return values.reduce((total, value) => total + value, 0);
}
```

`readonly` 是类型视角下的限制，不代表运行时对象被冻结。

## 元组类型

元组用于表示长度固定、位置有明确含义的数组。

```typescript
const point: [number, number] = [120, 30];
const response: [number, string] = [200, 'OK'];

type RGB = [red: number, green: number, blue: number];

const color: RGB = [255, 128, 0];
```

命名元组元素能提升可读性，但元组仍然靠位置表达语义。字段一多，通常应该改成对象。

```typescript
type UserTuple = [string, string, number, boolean];

type UserProfile = {
  id: string;
  name: string;
  age: number;
  enabled: boolean;
};
```

## 对象类型

对象类型描述属性名、属性值、可选属性、只读属性和方法签名。

```typescript
type User = {
  readonly id: string;
  name: string;
  age?: number;
  updateName: (name: string) => void;
};
```

`readonly` 限制的是类型层面的赋值，不是运行时不可变。

```typescript
function rename(user: User) {
  user.name = 'Grace';
  // user.id = 'u_2'; // 类型错误
}
```

`object` 只能表示非原始值，不能安全读取具体属性。未知字典更适合写成 `Record<string, unknown>`。

```typescript
function readDictionary(value: Record<string, unknown>) {
  return value['id'];
}
```

## 字面量类型

字面量类型把值限定在具体选项里，适合状态、尺寸、主题、权限码、接口枚举。

```typescript
type Status = 'idle' | 'loading' | 'success' | 'error';

let status: Status = 'idle';
status = 'loading';
// status = 'done'; // 类型错误
```

它比裸 `string` 更适合有限业务状态，因为拼写错误和未设计选项会在编译期暴露。

## `any` 与 `unknown`

`any` 会关闭类型检查，`unknown` 表示“目前不知道类型，使用前必须检查”。面对外部输入时，优先使用 `unknown`。

```typescript
function parseJson(input: string): unknown {
  return JSON.parse(input);
}

const value = parseJson('{"name":"Ada"}');

if (
  typeof value === 'object' &&
  value !== null &&
  'name' in value &&
  typeof value.name === 'string'
) {
  console.log(value.name.toUpperCase());
}
```

`any` 的危险在于会沿着赋值、参数和返回值传播。

```typescript
function parseAny(input: string): any {
  return JSON.parse(input);
}

const user = parseAny('{}');
user.profile.address.city.toUpperCase(); // 编译通过，运行时可能崩溃
```

可以把 `any` 限制在极小边界，尽快转换成明确类型。

## `void` 与 `never`

`void` 表示函数没有有意义的返回值，常见于事件处理、日志、命令式操作。

```typescript
function log(message: string): void {
  console.log(message);
}
```

`never` 表示函数永远不会正常返回，或某个分支理论上不可能出现。

```typescript
function fail(message: string): never {
  throw new Error(message);
}
```

`never` 常用于穷尽检查。

```typescript
type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'rect'; width: number; height: number };

function area(shape: Shape) {
  switch (shape.kind) {
    case 'circle':
      return Math.PI * shape.radius ** 2;
    case 'rect':
      return shape.width * shape.height;
    default: {
      const exhaustive: never = shape;
      return exhaustive;
    }
  }
}
```

基础类型和 [[1.5.2 类型推断|类型推断]] 要一起理解：让编译器能可靠推断的地方保持简洁，让函数参数、模块导出、接口响应、公共组件 props 这类协作边界保持显式。
