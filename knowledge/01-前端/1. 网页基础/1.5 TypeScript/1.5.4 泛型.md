## 类型参数

泛型把类型变成参数，让函数、接口、类和工具类型可以保留类型关系，而不是提前写死某个具体类型。

```typescript
function identity<T>(value: T): T {
  return value;
}

const name = identity('Ada'); // string
const count = identity(1); // number
```

`T` 不是特殊关键字，只是常见命名。简单泛型常用 `T`、`K`、`V`，业务语义明显时可以写成 `TData`、`TError`。

```typescript
type ApiResult<TData, TError = string> =
  | { ok: true; data: TData }
  | { ok: false; error: TError };
```

泛型的核心不是尖括号，而是类型之间存在真实关系：输入影响输出、容器包装不同数据、配置项决定返回结构。

## 泛型函数

当函数输入和输出存在同一类型关系时，应该用泛型保留调用方信息。

```typescript
function first<T>(items: T[]): T | undefined {
  return items[0];
}

const user = first([
  { id: 'u_1', name: 'Ada' },
  { id: 'u_2', name: 'Grace' },
]);

if (user) {
  user.name.toUpperCase();
}
```

如果写成 `unknown[]` 或 `any[]`，要么调用方无法安全使用返回值，要么完全失去检查。

```typescript
function firstUnknown(items: unknown[]) {
  return items[0];
}

const value = firstUnknown([{ id: 'u_1', name: 'Ada' }]);
// value.name; // unknown 不能直接访问
```

## 泛型接口

泛型接口适合描述“结构稳定，但内部数据可变”的容器。接口返回、分页列表、表单状态、表格列配置都属于这类场景。

```typescript
interface ApiResponse<T> {
  code: number;
  message: string;
  data: T;
}

interface PageResult<T> {
  list: T[];
  page: number;
  pageSize: number;
  total: number;
}

type User = {
  id: string;
  name: string;
};

type UserPage = ApiResponse<PageResult<User>>;
```

泛型接口能避免为每种实体复制一套相似结构。

```typescript
type Product = {
  id: string;
  title: string;
};

type UserList = PageResult<User>;
type ProductList = PageResult<Product>;
```

## 泛型约束

默认情况下，`T` 可以是任何类型。要访问某个属性或调用某个方法，就必须通过 `extends` 约束它的最小结构。

```typescript
function getId<T extends { id: string }>(entity: T) {
  return entity.id;
}

getId({ id: 'u_1', name: 'Ada' });
// getId({ name: 'Ada' }); // 类型错误
```

约束不是把 `T` 固定成 `{ id: string }`，而是要求传入类型至少包含这个结构。返回值仍然保留原对象的完整类型。

```typescript
function attachSelected<T extends { id: string }>(
  item: T,
  selectedId: string,
): T & { selected: boolean } {
  return {
    ...item,
    selected: item.id === selectedId,
  };
}

const selectedUser = attachSelected({ id: 'u_1', name: 'Ada' }, 'u_1');
selectedUser.name;
selectedUser.selected;
```

泛型约束和 [[1.5.3 联合交叉|交叉类型]] 经常一起出现：约束保证输入具备基础能力，交叉表达输出新增能力。

## `keyof`

`keyof` 会得到对象类型的键名联合。它和泛型组合后，可以让对象属性访问同时检查 key 和返回值类型。

```typescript
function getValue<T, K extends keyof T>(object: T, key: K): T[K] {
  return object[key];
}

const user = {
  id: 'u_1',
  name: 'Ada',
  age: 32,
};

const userName = getValue(user, 'name'); // string
const age = getValue(user, 'age'); // number
// getValue(user, 'email'); // 类型错误
```

`T[K]` 表示对象类型 `T` 中键 `K` 对应的值类型。这让工具函数不仅知道“拿了某个属性”，还知道拿到的是什么类型。

```typescript
function updateField<T, K extends keyof T>(
  object: T,
  key: K,
  value: T[K],
): T {
  return {
    ...object,
    [key]: value,
  };
}

const nextUser = updateField(user, 'age', 33);
// updateField(user, 'age', '33'); // 类型错误
```

这个模式在表单、状态更新、配置编辑器里很常见。

## 表格列配置

表格列是泛型常见工程场景：列的 `key` 必须来自行数据，渲染函数的值类型也应该跟随 `key`。

```typescript
type Column<T, K extends keyof T = keyof T> = {
  key: K;
  title: string;
  render?: (value: T[K], row: T) => string;
};

const columns: Column<User>[] = [
  { key: 'id', title: '用户 ID' },
  {
    key: 'name',
    title: '姓名',
    render: (value) => value.toUpperCase(),
  },
  // { key: 'email', title: '邮箱' }, // 类型错误
];
```

这比 `key: string` 更安全，因为字段改名时，列配置会同步报错。

## 默认类型参数

泛型可以设置默认类型，让简单场景不必传类型，复杂场景仍然能覆盖。

```typescript
interface RequestOptions<TData = unknown, TError = Error> {
  url: string;
  method?: 'GET' | 'POST';
  transform?: (raw: unknown) => TData;
  onError?: (error: TError) => void;
}

const options: RequestOptions = {
  url: '/api/users',
};
```

默认类型常用 `unknown`，因为它安全地表达“调用方没有指定时，我不知道”。不建议默认成 `any`。

## 泛型组件

前端组件里，泛型常用于选择器、列表、表格、表单字段等“组件行为固定，但数据结构由业务决定”的场景。

```tsx
type SelectProps<T> = {
  options: T[];
  value?: T;
  getKey: (option: T) => string;
  getLabel: (option: T) => string;
  onChange: (option: T) => void;
};

function Select<T>({
  options,
  value,
  getKey,
  getLabel,
  onChange,
}: SelectProps<T>) {
  return (
    <ul>
      {options.map((option) => {
        const key = getKey(option);
        const active = value ? getKey(value) === key : false;

        return (
          <li key={key}>
            <button
              type="button"
              aria-pressed={active}
              onClick={() => onChange(option)}
            >
              {getLabel(option)}
            </button>
          </li>
        );
      })}
    </ul>
  );
}
```

调用时，组件会从 `options` 推断出 `T`。

```tsx
<Select
  options={[
    { id: 'u_1', name: 'Ada' },
    { id: 'u_2', name: 'Grace' },
  ]}
  getKey={(user) => user.id}
  getLabel={(user) => user.name}
  onChange={(user) => {
    console.log(user.id, user.name);
  }}
/>;
```

泛型组件的关键，是让调用方传入的数据类型能一路传到回调和渲染函数。

## 使用边界

泛型不是越抽象越好。只有类型之间存在真实关系时，泛型才有价值。

| 场景 | 是否适合 | 判断 |
|---|---|---|
| 输入什么类型，输出同类类型 | 适合 | `identity<T>(value: T): T` |
| 容器结构一致，内部数据不同 | 适合 | `ApiResponse<T>`、`PageResult<T>` |
| 字段名决定字段值类型 | 适合 | `K extends keyof T` |
| 固定业务对象只用一次 | 不适合 | 直接写业务类型更清楚 |
| 只是为了少写几个类型名 | 不适合 | 会增加阅读成本 |

设计泛型时可以问三件事：调用方传入的类型是否影响返回值，类型参数是否能被推断出来，删除泛型后是否会损失有价值的类型信息。答案不明确时，先不要抽象。
