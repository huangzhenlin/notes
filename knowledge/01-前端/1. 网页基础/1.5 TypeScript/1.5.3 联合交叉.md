## 联合类型

联合类型用 `|` 表示“一个值可能是几种类型之一”。它最重要的价值不是少写重载，而是把业务中的可选形态显式写进类型系统。

```typescript
type ID = string | number;

function normalizeId(id: ID) {
  return String(id).trim();
}

normalizeId('u_001');
normalizeId(1001);
// normalizeId(true); // 类型错误
```

联合类型不是“同时拥有所有成员”，而是“运行时只会落在其中一个成员”。因此只能直接访问所有成员共有的能力。

```typescript
function formatValue(value: string | number) {
  return value.toString();
}

function upper(value: string | number) {
  if (typeof value === 'string') {
    return value.toUpperCase();
  }

  return value.toFixed(2);
}
```

联合类型通常会和 [[1.5.5 类型收窄|类型收窄]] 一起使用：先判断，再访问分支专属能力。

## 字面量联合

字面量联合把值限定在一组明确选项内，适合描述状态、尺寸、主题、权限码、排序方式、接口枚举等固定取值字段。

```typescript
type ButtonVariant = 'primary' | 'secondary' | 'danger';
type ButtonSize = 'small' | 'medium' | 'large';

type ButtonProps = {
  variant: ButtonVariant;
  size?: ButtonSize;
  disabled?: boolean;
};

function createButtonClass(props: ButtonProps) {
  const size = props.size ?? 'medium';
  return `btn btn-${props.variant} btn-${size}`;
}
```

比起把 `variant` 写成 `string`，字面量联合能直接拒绝拼写错误和未设计过的值。

```typescript
createButtonClass({ variant: 'primary' });
// createButtonClass({ variant: 'main' }); // 类型错误
```

## 可辨识联合

可辨识联合使用一个共同字段区分不同分支，常见字段名有 `type`、`kind`、`status`、`state`。它适合表达请求状态、表单步骤、组件变体、消息协议和领域事件。

```typescript
type RequestState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; error: string; retryable: boolean };

type User = {
  id: string;
  name: string;
};

function renderUser(state: RequestState<User>) {
  switch (state.status) {
    case 'idle':
      return '等待加载';
    case 'loading':
      return '加载中';
    case 'success':
      return state.data.name;
    case 'error':
      return state.retryable ? `可重试：${state.error}` : state.error;
  }
}
```

不要把同样的模型写成一堆可选字段。

```typescript
type LooseState<T> = {
  status: 'idle' | 'loading' | 'success' | 'error';
  data?: T;
  error?: string;
};
```

`LooseState` 无法表达“success 一定有 data，error 一定有 error”。调用方仍然要反复判断 `undefined`，类型系统没有真正承担建模责任。

## 穷尽检查

当可辨识联合用于核心状态机时，应使用 `never` 做穷尽检查。以后新增分支时，相关渲染、转换、埋点代码会被编译器提醒。

```typescript
function assertNever(value: never): never {
  throw new Error(`Unexpected value: ${JSON.stringify(value)}`);
}

function getStatusText<T>(state: RequestState<T>) {
  switch (state.status) {
    case 'idle':
      return '未开始';
    case 'loading':
      return '加载中';
    case 'success':
      return '成功';
    case 'error':
      return '失败';
    default:
      return assertNever(state);
  }
}
```

`never` 把“不应该发生”的分支变成编译期约束。

## 交叉类型

交叉类型用 `&` 表示“同时满足多个类型”。它常用于给一个对象组合多个能力或公共字段。

```typescript
type Entity = {
  id: string;
};

type Timestamped = {
  createdAt: string;
  updatedAt: string;
};

type UserProfile = Entity & Timestamped & {
  name: string;
  avatarUrl?: string;
};
```

交叉类型适合横向组合，例如实体基础字段、分页参数、排序参数、链路追踪信息。

```typescript
type PaginationParams = {
  page: number;
  pageSize: number;
};

type SortParams = {
  sortBy: string;
  order: 'asc' | 'desc';
};

type ListParams = PaginationParams & SortParams;
```

## 联合与交叉

联合表达“选择”，交叉表达“组合”。

| 写法 | 语义 | 能直接访问什么 | 常见场景 |
|---|---|---|---|
| `A | B` | A 或 B | A 和 B 的公共成员 | 状态分支、输入参数、返回结果 |
| `A & B` | A 且 B | A 和 B 的全部成员 | 字段组合、能力叠加、配置合并 |

```typescript
type Success<T> = { ok: true; data: T };
type Failure = { ok: false; error: string };

type ApiResult<T> = Success<T> | Failure;

type WithRequestId = {
  requestId: string;
};

type TracedApiResult<T> = ApiResult<T> & WithRequestId;
```

`ApiResult<T>` 是联合，因为一次请求结果只能成功或失败；`TracedApiResult<T>` 是交叉，因为无论成功还是失败，都额外带上 `requestId`。

## 交叉冲突

交叉类型合并同名字段时，字段类型也会被交叉。如果两个字段类型互斥，结果可能变成 `never`。

```typescript
type FromRoute = {
  id: string;
};

type FromDatabase = {
  id: number;
};

type Broken = FromRoute & FromDatabase;
// Broken['id'] 是 never
```

这类冲突通常说明类型片段的语义没有对齐。不要靠断言绕过，而应该重命名或在边界处转换。

```typescript
type RouteParams = {
  routeId: string;
};

type DatabaseEntity = {
  id: number;
};

type PageContext = RouteParams & {
  entity: DatabaseEntity;
};
```

## 使用边界

联合和交叉真正好用的前提，是业务状态本身被拆清楚。不要把所有字段塞进一个大对象，再用可选字段和布尔值补丁式描述状态。

```typescript
type UploadState =
  | { status: 'waiting'; file: File }
  | { status: 'uploading'; file: File; progress: number }
  | { status: 'done'; file: File; url: string }
  | { status: 'failed'; file: File; reason: string };
```

这个模型让每个分支只保存合法字段，UI 渲染也能顺着 `status` 自然拆开。

```typescript
function renderUpload(state: UploadState) {
  if (state.status === 'uploading') {
    return `上传中：${state.progress}%`;
  }

  if (state.status === 'done') {
    return `已完成：${state.url}`;
  }

  if (state.status === 'failed') {
    return `失败：${state.reason}`;
  }

  return `等待上传：${state.file.name}`;
}
```

选择类型建模方式时，先判断运行时语义：互斥形态用联合，能力叠加用交叉，稳定对象层级再考虑接口继承。
