## 控制流分支

类型收窄是 TypeScript 根据控制流把一个较宽的类型缩小成更具体类型的过程。它依赖真实的 JavaScript 判断语句，例如 `if`、`switch`、`return`、`throw`、三元表达式和逻辑运算。

```typescript
function format(value: string | number) {
  if (typeof value === 'string') {
    return value.toUpperCase();
  }

  return value.toFixed(2);
}
```

进入 `if` 分支后，`value` 被收窄为 `string`；因为这个分支已经 `return`，剩余路径里 `value` 就只能是 `number`。

```typescript
function getLength(value: string | string[] | null) {
  if (value === null) {
    return 0;
  }

  return value.length;
}
```

收窄不是单个语法技巧，而是 TypeScript 对代码执行路径的理解。清晰的早返回和分支拆分，通常比堆很多断言更容易得到正确类型。

## `typeof`

`typeof` 适合判断基础类型，包括 `string`、`number`、`boolean`、`undefined`、`object`、`function`、`symbol`、`bigint`。

```typescript
function printId(id: string | number) {
  if (typeof id === 'number') {
    console.log(id.toFixed(0));
    return;
  }

  console.log(id.toUpperCase());
}
```

`typeof null` 结果是 `"object"`，数组结果也是 `"object"`，因此判断对象时要排除 `null`。

```typescript
function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null && !Array.isArray(value);
}
```

`typeof value === 'function'` 能把值收窄成可调用类型，但如果要保留参数和返回值信息，仍然应该配合更明确的函数类型。

## `instanceof`

`instanceof` 适合判断类实例、内置对象和错误对象。

```typescript
function handleError(error: Error | string) {
  if (error instanceof Error) {
    return error.message;
  }

  return error;
}
```

它依赖运行时原型链，所以只能用于真实存在的构造函数。接口、类型别名、泛型参数在编译后都会消失，不能写成 `value instanceof User`。

```typescript
class ApiError extends Error {
  constructor(
    message: string,
    public statusCode: number,
  ) {
    super(message);
  }
}
```

跨 `iframe` 或跨 realm 的对象可能让 `instanceof Array` 之类的判断不稳定。数组判断优先用 `Array.isArray`。

## `in` 操作符

`in` 判断对象是否拥有某个属性，适合区分对象联合类型。

```typescript
type Fish = { swim: () => void };
type Bird = { fly: () => void };

function move(animal: Fish | Bird) {
  if ('swim' in animal) {
    animal.swim();
  } else {
    animal.fly();
  }
}
```

字面量键名要选择稳定且能区分分支的属性。如果多个分支都可能拥有同名可选字段，`in` 的收窄效果会变差。

```typescript
type Admin = {
  role: 'admin';
  permissions: string[];
};

type Guest = {
  role: 'guest';
  expiresAt?: string;
};

function describeUser(user: Admin | Guest) {
  if ('permissions' in user) {
    return `权限数：${user.permissions.length}`;
  }

  return user.expiresAt ? `过期时间：${user.expiresAt}` : '访客';
}
```

## 字面量判别

可辨识联合是最稳定、最推荐的对象收窄方式。它用一个共同字段表示不同分支，每个分支只携带自己合法的数据。

```typescript
type RequestState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; error: string };

type User = {
  id: string;
  name: string;
};

function render(state: RequestState<User>) {
  if (state.status === 'success') {
    return state.data.name;
  }

  if (state.status === 'error') {
    return state.error;
  }

  return '加载中';
}
```

判别字段应该满足三个条件：

1. 每个分支都有这个字段。
2. 每个分支的字段值是互斥字面量。
3. 字段含义稳定，不会被业务随意复用。

组件变体也适合这样建模。

```typescript
type DialogProps =
  | { mode: 'alert'; message: string; onConfirm: () => void }
  | { mode: 'confirm'; message: string; onConfirm: () => void; onCancel: () => void }
  | { mode: 'custom'; renderContent: () => string };
```

## 自定义守卫

类型守卫函数返回 `value is Type`，用于把运行时判断封装成可复用的收窄逻辑。

```typescript
type User = {
  id: string;
  name: string;
};

function isUser(value: unknown): value is User {
  return (
    typeof value === 'object' &&
    value !== null &&
    'id' in value &&
    'name' in value &&
    typeof value.id === 'string' &&
    typeof value.name === 'string'
  );
}
```

类型守卫适合处理不可信边界：接口响应、`localStorage`、URL 参数、跨窗口消息、第三方 SDK 返回值。它和 [[1.5.1 基础类型|unknown]] 的关系很近：外部输入先进入 `unknown`，再通过守卫变成业务类型。

```typescript
function isUserList(value: unknown): value is User[] {
  return Array.isArray(value) && value.every(isUser);
}
```

## 穷尽检查

`never` 可用于保证联合类型所有分支都被处理。它常和 `switch` 配合，用在状态机、变体、协议消息、接口结果等核心分支。

```typescript
function assertNever(value: never): never {
  throw new Error(`Unexpected value: ${JSON.stringify(value)}`);
}
```

如果以后新增 `{ status: 'empty' }`，却没加处理，`assertNever(state)` 会报错。这个提醒比线上空白 UI 更早。

## 非空断言

非空断言 `!` 可以告诉 TypeScript “这里一定不是空”。它不会产生运行时检查。

```typescript
const button = document.querySelector('#submit')!;
button.addEventListener('click', () => {});
```

如果 DOM 结构可能变化、选择器来自配置、代码运行在不同页面，优先使用显式判断。

```typescript
const element = document.querySelector('#submit');
if (element === null) {
  throw new Error('Missing submit button');
}
```

`!` 适合初始化顺序由框架保证、但编译器无法推断的少数场景，不适合用来跳过真实风险。

## 谨慎断言

类型断言是告诉编译器“把这个值当成某种类型”，它不是运行时校验，也不是严格意义上的收窄。

```typescript
const user = value as User;
```

对外部输入，优先校验；对内部已知数据，谨慎断言；对不确定来源，别直接断言。

```typescript
function safeParseUser(input: string) {
  const value: unknown = JSON.parse(input);

  if (!isUser(value)) {
    throw new Error('Invalid user');
  }

  return value;
}
```

类型收窄的目标，是让编译器和运行时判断尽量一致，而不是用更多 `as` 把错误推迟到后面。
