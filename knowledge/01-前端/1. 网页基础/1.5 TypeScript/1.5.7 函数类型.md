## 函数形状

函数类型描述的是“参数是什么、返回什么”。它适合回调、工具函数、事件处理器、策略函数等。

```typescript
type Formatter = (value: number) => string;

const formatPrice: Formatter = (value) => {
  return `￥${value.toFixed(2)}`;
};
```

如果函数只是执行一段简单逻辑，普通函数签名就够了；如果它会被当作参数复用，单独抽成类型更清楚。

函数类型最重要的不是“写一个箭头函数类型”，而是把调用协议固定下来。比如组件事件、请求拦截器、排序策略、权限判断这些位置，调用方和实现方往往不在同一个文件里，函数类型就是双方的契约。

```typescript
type Predicate<T> = (value: T, index: number) => boolean;

function findFirst<T>(items: T[], predicate: Predicate<T>): T | undefined {
  for (let index = 0; index < items.length; index += 1) {
    if (predicate(items[index], index)) {
      return items[index];
    }
  }

  return undefined;
}
```

这里的 `Predicate<T>` 让调用方知道能拿到元素和索引，也让实现方不能随意改变回调参数。函数类型一旦公开，就和接口一样属于 API 设计的一部分。

## 可选参数

参数后加 `?` 表示可选。它通常意味着调用方可以省略该参数，函数内部需要提供兜底行为。

```typescript
function createUser(name: string, age?: number) {
  return { name, age };
}

const finalAge = age ?? 18;
```

可选参数的位置必须在必选参数后面。多个“可能缺省”的参数很多时，更推荐对象参数。

```typescript
function createUserFromOptions(options: {
  name: string;
  age?: number;
  email?: string;
}) {
  return options;
}
```

对象参数的好处是可读性和可扩展性更好。三个以上可选参数连在一起时，调用处很容易出现 `undefined` 占位，后续新增参数也容易破坏顺序。

```typescript
function request(url: string, method?: string, timeout?: number, retry?: number) {}

request('/api/users', undefined, 5000, 2);
```

这种写法能跑，但可读性差。换成对象参数后，调用方只声明自己关心的选项，类型也更容易继续演进。

```typescript
function request(options: {
  url: string;
  method?: 'GET' | 'POST';
  timeout?: number;
  retry?: number;
}) {}

request({
  url: '/api/users',
  timeout: 5000,
  retry: 2,
});
```

## 默认参数

默认参数提供运行时默认值。它和可选参数都能让调用方省略参数，但默认参数会直接决定实际执行值。

```typescript
function request(url: string, retry = 3) {
  return fetchWithRetry(url, retry);
}
```

默认参数适合“没传就用这个值”的场景。可选参数适合“参数本身可能缺失，需要函数内部判断”的场景。

默认参数会参与类型推断。下面的 `retry` 会被推断为 `number`，调用方可以省略，但函数内部拿到的一定是数字。

```typescript
function fetchJson(url: string, retry = 2) {
  while (retry > 0) {
    retry -= 1;
  }
}
```

如果默认值依赖另一个参数，最好保持表达简单，避免在参数列表里藏复杂逻辑。

```typescript
function createLogger(namespace: string, prefix = `[${namespace}]`) {
  return (message: string) => {
    console.log(prefix, message);
  };
}
```

默认参数解决的是运行时兜底，不能替代类型设计。比如 `options = {}` 虽然常见，但如果内部马上访问深层字段，仍然要给每个字段定义默认值或做空值处理。

## 剩余参数

剩余参数用于接收数量不固定的输入。

```typescript
function sum(...numbers: number[]) {
  return numbers.reduce((total, value) => total + value, 0);
}
```

如果参数数量和位置固定，可以使用元组。

```typescript
function call(fn: (...args: [string, number]) => void) {
  fn('Ada', 28);
}
```

剩余参数常见于日志、埋点、工具函数、事件转发和包装器。

元组剩余参数可以保留参数名称和位置关系，很适合包装已有函数。

```typescript
function track(event: string, payload?: Record<string, unknown>) {}

function withSafeTrack(...args: Parameters<typeof track>) {
  try {
    track(...args);
  } catch {
    // 埋点失败不影响主流程
  }
}
```

如果函数需要支持多种参数组合，也可以用联合元组表达，而不一定立刻写重载。

```typescript
type SearchArgs =
  | [keyword: string]
  | [keyword: string, page: number]
  | [keyword: string, page: number, pageSize: number];

function search(...args: SearchArgs) {
  const [keyword, page = 1, pageSize = 20] = args;
  return { keyword, page, pageSize };
}
```

联合元组适合参数差异不复杂的场景。参数越多、返回值还随参数变化时，重载会更清楚。

## 函数重载

重载用于描述同一个函数的多种调用方式。它特别适合“参数形态不同，返回类型也不同”的 API。

```typescript
function getValue(id: string): User;
function getValue(ids: string[]): User[];
function getValue(input: string | string[]) {
  if (Array.isArray(input)) {
    return input.map((id) => findUser(id));
  }

  return findUser(input);
}
```

重载签名是给调用方看的，实现签名负责兼容所有情况。不要把完全无关的行为硬塞到一个重载函数里，否则阅读成本很高。

重载的价值在于让返回类型跟调用方式对应起来。直接写联合参数时，返回值往往也只能是联合类型，调用方还要自己判断；重载可以把这种关系提前表达清楚。

```typescript
function parseValue(value: string): string;
function parseValue(value: number): number;
function parseValue(value: string | number) {
  return value;
}

const name = parseValue('Ada');
const age = parseValue(28);
```

不过重载不适合替代清晰 API。如果一个函数既能查用户、又能发请求、还能格式化日期，只是为了“入口统一”写成一堆重载，那类型虽然能描述，设计却已经变混乱。重载应该用于同一抽象下的不同调用形态。

## `this` 参数

TypeScript 可以显式声明函数中的 `this` 类型。它只存在于类型层面，不是运行时参数。

```typescript
function handleClick(this: HTMLButtonElement, event: MouseEvent) {
  this.disabled = true;
}
```

这个能力在 DOM 回调、对象方法工具、老式事件绑定中很有用。它能避免“函数里用到了 `this`，但调用方忘了绑定上下文”的问题。

在现代前端里，箭头函数和组合式 API 用得更多，显式 `this` 参数出现频率没有以前高，但它仍然适合描述老式库、DOM API 和一些插件系统。

```typescript
interface ButtonPlugin {
  init(this: HTMLButtonElement, options: { loadingText: string }): void;
}

const plugin: ButtonPlugin = {
  init(options) {
    this.textContent = options.loadingText;
  },
};
```

需要注意，箭头函数没有自己的 `this`，所以不能用箭头函数实现依赖动态 `this` 的回调。遇到需要 `this` 的 API，要优先确认调用方式，而不是只看类型能不能写出来。

## `void`

`void` 表示函数返回值不应被调用方依赖。日志、埋点、事件处理函数常用它。

```typescript
type EventHandler = () => void;

const handleClick: EventHandler = () => {
  console.log('clicked');
};
```

`void` 不等于绝对不能返回值，而是调用方不应该依赖这个返回值。

这个特性在事件处理器里很常见。一个返回 `void` 的回调类型，可以接受实际返回值的函数，因为调用方会忽略它。

```typescript
type ClickHandler = () => void;

const handler: ClickHandler = () => {
  return 'clicked';
};
```

这不代表返回值会消失，只是类型契约要求调用方别依赖它。异步事件处理要特别小心：`async` 函数返回 `Promise`，如果框架或调用方不会处理这个 Promise，异常可能变成未捕获拒绝。需要等待结果时，就不要把类型写成 `() => void`。

```typescript
type SubmitHandler = () => Promise<void>;
```

## `never`

`never` 表示函数不会正常返回。它适合抛错函数、无限循环和穷尽检查。

```typescript
function fail(message: string): never {
  throw new Error(message);
}

function assertNever(value: never): never {
  throw new Error(`Unexpected value: ${value}`);
}
```

函数类型最实用的地方，是把参数、返回值、回调协议、重载和上下文绑定一起显式化。接口回调、事件处理、策略对象这些边界，都能更稳定。

`never` 最常用于联合类型的穷尽检查。当新增状态但忘记处理时，编译器会在默认分支报错。

```typescript
type Status =
  | { type: 'idle' }
  | { type: 'loading' }
  | { type: 'success'; data: string }
  | { type: 'error'; error: Error };

function renderStatus(status: Status) {
  switch (status.type) {
    case 'idle':
      return '未开始';
    case 'loading':
      return '加载中';
    case 'success':
      return status.data;
    case 'error':
      return status.error.message;
    default:
      return assertNever(status);
  }
}
```

函数类型和 [[1.5.5 类型收窄|类型收窄]] 的联系很紧：参数越精确，函数内部越少防御式判断；返回值越准确，调用方越少猜测。好的函数类型不是把所有可能都写成联合，而是把调用前提、返回结果和异常路径表达清楚。
