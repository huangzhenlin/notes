## 存储类型

浏览器提供多种存储能力：Cookie、LocalStorage、SessionStorage、IndexedDB、Cache Storage。它们的容量、生命周期、访问方式和安全边界都不同。

| 存储 | 适合内容 |
|---|---|
| Cookie | 会话、少量服务端需要读取的信息 |
| LocalStorage | 少量长期偏好 |
| SessionStorage | 单标签页临时状态 |
| IndexedDB | 大量结构化数据 |
| Cache Storage | 请求和响应缓存 |

选择存储时先看数据大小、是否敏感、是否需要服务端读取、是否需要离线、是否需要复杂查询。

还要看数据是否需要跨标签、跨设备、跨登录态同步。浏览器本地存储只存在当前设备和当前浏览器环境里，用户清理数据、隐私模式、浏览器策略、第三方上下文限制都可能让数据不可用。能丢的数据才适合放本地，不能丢的数据应该以服务端为准。

```text
服务端需要读取 -> Cookie
少量偏好 -> LocalStorage
当前标签页流程 -> SessionStorage
大数据 / 离线 -> IndexedDB
请求缓存 -> Cache Storage
```

## Cookie

Cookie 会随请求发送给服务器，适合会话和服务端鉴权。

```http
Set-Cookie: session=abc; HttpOnly; Secure; SameSite=Lax
```

| 属性 | 作用 |
|---|---|
| `HttpOnly` | JS 不可读取 |
| `Secure` | 只在 HTTPS 发送 |
| `SameSite` | 控制跨站携带 |
| `Max-Age` | 生命周期 |
| `Path` | 限制路径范围 |
| `Domain` | 限制域范围 |

Cookie 容量小，不适合存大量业务数据。更重要的是，Cookie 会受到同站策略、路径、域、HTTPS 和浏览器隐私策略约束。

```javascript
document.cookie = 'theme=dark; path=/';
```

如果 Cookie 需要服务端读取，又不想被 JS 直接碰到，`HttpOnly` 是很重要的边界。

Cookie 也不是越多越好。它会随匹配请求自动发送，过大的 Cookie 会增加请求体积；Domain 和 Path 配得太宽，会让不需要的请求也携带凭证。会话 Cookie 应尽量小、作用域清楚，并配合 `HttpOnly`、`Secure`、`SameSite` 降低风险。

## LocalStorage

LocalStorage 是同步 API，适合少量长期本地数据。

```javascript
localStorage.setItem('theme', 'dark');
const theme = localStorage.getItem('theme');
localStorage.removeItem('theme');
```

它不适合存 token、隐私数据和大对象。同步读写会阻塞主线程，大量操作会影响性能。

LocalStorage 更适合用户偏好、简单开关、轻量缓存，不适合复杂状态同步。能被 JS 读取的存储，都要按 XSS 风险处理。

LocalStorage 的同步 API 是一个实际性能边界。页面启动时大量读取和解析大 JSON，会阻塞主线程。主题、语言、少量偏好适合放这里；大型列表、离线数据、复杂索引应该转向 IndexedDB。

## SessionStorage

SessionStorage 生命周期绑定当前标签页。关闭标签页后数据清除，不同标签页之间也不会共享同一份 SessionStorage。

```javascript
sessionStorage.setItem('draft', JSON.stringify(form));

const draft = JSON.parse(sessionStorage.getItem('draft') || 'null');
```

它适合临时草稿、当前流程状态、一次性跳转参数。如果业务需要跨标签页共享状态，就不要依赖 SessionStorage。

SessionStorage 常用于“当前标签页里的流程状态”，比如多步骤表单、支付跳转前的临时上下文、未提交草稿。它不适合保存登录态，也不适合承载用户期望长期保留的数据。

## IndexedDB

IndexedDB 是浏览器端结构化数据库，适合大数据、离线缓存、复杂查询和二进制数据。

```javascript
const request = indexedDB.open('app-db', 1);

request.onupgradeneeded = () => {
  const db = request.result;
  db.createObjectStore('notes', { keyPath: 'id' });
};
```

IndexedDB API 较底层，实际项目经常使用封装库。它适合笔记、离线列表、媒体缓存、编辑器草稿等场景。

```javascript
const transaction = db.transaction('notes', 'readwrite');
const store = transaction.objectStore('notes');
store.put({ id: 1, title: 'HTML' });
```

它的优势是容量更大、结构更灵活；代价是操作模型更复杂，版本升级也需要谨慎设计。

IndexedDB 的版本升级要认真设计。对象仓库、索引、keyPath 的变化通常发生在 `onupgradeneeded` 中，升级失败可能影响整个数据库打开。离线应用和编辑器类产品要把 schema 迁移当成真实数据迁移，而不是随手改字段。

## Cache Storage

Cache Storage 常与 Service Worker 配合，用于缓存请求和响应。

```javascript
const cache = await caches.open('static-v1');
await cache.addAll(['/index.html', '/assets/app.js']);
```

它适合离线资源、静态文件、接口响应缓存。缓存策略要谨慎，否则用户可能长期拿到旧内容。

Cache Storage 更像“请求级缓存仓库”，不是通用业务状态仓库。它保存的是 Request/Response 对，和 HTTP 缓存、Service Worker 一起工作。

Cache Storage 适合缓存“资源响应”，不适合保存任意业务对象。需要查询、排序、更新单条记录的数据，用 IndexedDB 更自然；需要离线返回某个请求响应，用 Cache Storage 更合适。两者经常在 PWA 中配合使用。

## 安全边界

浏览器存储都在用户设备上，不能当成可信数据库。

| 风险 | 说明 |
|---|---|
| XSS | JS 可访问的存储可能被读取 |
| 用户清理 | 数据可能消失 |
| 多标签同步 | 状态可能不一致 |
| 容量限制 | 写入可能失败 |
| 隐私策略 | 第三方场景可能受限 |

敏感凭证应优先考虑 HttpOnly Cookie、短 token、服务端会话等方案。存储和 [[1.6.8 敏感信息|敏感信息]] 密切相关。

```text
能被 JS 读取 -> 不适合放敏感票据
需要长期保留的少量偏好 -> 适合 LocalStorage
需要大数据和离线能力 -> 适合 IndexedDB
```

浏览器存储的另一个现实边界是隐私策略。第三方 Cookie、第三方存储、嵌入式 iframe、无痕模式都可能受到限制。登录、埋点、广告、跨站嵌入和 SSO 场景不能只按一方页面的存储行为设计，要考虑浏览器隐私策略。

## 过期策略

LocalStorage 和 IndexedDB 不会自动按业务过期，需要自己设计过期字段。

```javascript
function setCache(key, value, ttl) {
  localStorage.setItem(key, JSON.stringify({
    value,
    expiresAt: Date.now() + ttl,
  }));
}
```

没有过期策略的缓存，迟早会变成线上问题：旧配置、旧用户信息、旧接口响应都可能影响业务。

```javascript
function getCache(key) {
  const raw = localStorage.getItem(key);
  if (!raw) return null;

  const data = JSON.parse(raw);
  if (Date.now() > data.expiresAt) {
    localStorage.removeItem(key);
    return null;
  }

  return data.value;
}
```

过期策略不一定只按时间，也可以按版本号、用户 ID、环境版本或发布号做失效。

本地缓存还应该考虑用户切换。多账号系统里，如果缓存 key 没有带用户维度，A 用户的数据可能被 B 用户读到。退出登录时应清理与用户相关的本地数据，或用用户 ID、租户 ID、环境版本组成更明确的 key。

## 多标签同步

LocalStorage 改变时，其他同源标签页可以收到 `storage` 事件。

```javascript
window.addEventListener('storage', (event) => {
  if (event.key === 'theme') {
    applyTheme(event.newValue);
  }
});
```

它适合做简单偏好同步，不适合做复杂实时状态同步。复杂跨标签通信更适合 BroadcastChannel、SharedWorker 或服务端推送。

`storage` 事件不会在触发修改的同一个标签页里触发，只会通知其他同源页面。它适合“我在另一个标签页改了主题或退出登录”的简单通知；如果需要双向实时通信，BroadcastChannel 的语义更直接。
