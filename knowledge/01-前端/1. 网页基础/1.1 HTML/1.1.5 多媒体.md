## 图片资源

图片既是内容资源，也是性能资源。写 `img` 时要同时考虑语义、尺寸、加载优先级和响应式适配。

```html
<img
  src="/images/banner.jpg"
  alt="课程首页横幅：从 HTML 到工程化的学习路径"
  width="1200"
  height="400"
/>
```

#### 替代文本

`alt` 描述图片在当前上下文里承担的信息。商品图、流程图、截图、图标按钮都应该有有意义的替代文本；纯装饰图片可以写空字符串，让辅助技术跳过。

| 图片类型 | `alt` 写法 | 示例 |
| --- | --- | --- |
| 内容图片 | 描述关键信息 | `alt="HTML 文档树结构示意图"` |
| 商品图片 | 描述对象 | `alt="黑色机械键盘正面图"` |
| 图标按钮 | 描述动作 | `alt="搜索"` |
| 装饰图片 | 空文本 | `alt=""` |

#### 尺寸预留

`width` 和 `height` 可以让浏览器在图片下载完成前计算比例并预留空间，减少布局跳动。尤其是懒加载图片，如果没有尺寸，图片进入视口后才撑开页面，会明显影响阅读体验。

#### 响应式图片

```html
<img
  src="/images/card-800.jpg"
  srcset="/images/card-400.jpg 400w, /images/card-800.jpg 800w, /images/card-1200.jpg 1200w"
  sizes="(max-width: 600px) 100vw, 50vw"
  alt="课程卡片封面"
  width="800"
  height="450"
/>
```

`srcset` 描述有哪些候选资源，`sizes` 描述图片在不同视口下大概显示多宽，浏览器会结合设备像素比和网络情况选择更合适的版本。它不是视觉响应式的替代品，而是资源层面的响应式。

图片资源还要区分“内容必须出现”和“体验增强”。商品详情主图、文章题图、头像通常是内容本身，加载失败时应该有替代文本和空间占位；背景纹理、装饰插画、氛围图则更多属于视觉增强，可以放进 CSS 背景，避免污染文档语义。这个边界会影响 `alt`、懒加载、缓存策略和图片是否进入搜索引擎图片理解。

如果页面中图片很多，可以先统一三个策略：图片是否必须有尺寸、首屏图是否允许高优先级、非首屏图是否默认懒加载。不要每张图都临时判断，否则后续性能问题会变成一堆零散补丁。

## 音频元素

`audio` 用于嵌入声音内容。只要音频是页面内容的一部分，就应该给用户控制权，不要假设用户一定愿意自动播放。

```html
<audio controls preload="none">
  <source src="/media/intro.mp3" type="audio/mpeg" />
  <source src="/media/intro.ogg" type="audio/ogg" />
  当前浏览器不支持 audio。
</audio>
```

`controls` 使用浏览器默认控件，通常比自定义播放器更稳：键盘操作、可访问性、音量、进度条和系统媒体控制都由浏览器兜底。自定义播放器只有在品牌体验或复杂交互确实需要时才值得做。

| 属性 | 含义 | 使用判断 |
| --- | --- | --- |
| `controls` | 显示默认控件 | 内容音频通常需要 |
| `preload="none"` | 不预加载音频 | 非首屏、非核心音频 |
| `preload="metadata"` | 只加载元信息 | 需要时长、基本信息 |
| `autoplay` | 尝试自动播放 | 谨慎使用，常受限制 |

音频内容最好不要默认自动播放。浏览器通常会限制带声音的自动播放，即便成功播放，也容易打断用户当前环境。课程、播客、讲解音频更适合让用户主动播放；提示音、通知音这类交互反馈则要受用户设置控制，不能把声音当成唯一反馈方式。

## 视频元素

视频体积大、加载慢、交互强，标签写法要比图片更谨慎。基础结构通常包括默认控件、封面图、预加载策略和多个格式。

```html
<video
  controls
  width="720"
  height="405"
  poster="/images/video-cover.jpg"
  preload="metadata"
>
  <source src="/media/demo.webm" type="video/webm" />
  <source src="/media/demo.mp4" type="video/mp4" />
  当前浏览器不支持 video。
</video>
```

#### 视频封面

`poster` 在视频加载或播放前显示封面，避免黑框和空白区域。课程页、商品页、新闻页里的视频通常都应该准备封面。

#### 播放与预加载

`preload` 是给浏览器的加载提示，不是强制命令。常见取值：

| 值 | 含义 | 适合场景 |
| --- | --- | --- |
| `none` | 不主动预加载 | 页面有很多视频，用户不一定播放 |
| `metadata` | 只加载时长、尺寸等元信息 | 内容视频、课程预览 |
| `auto` | 浏览器可预加载更多内容 | 视频是页面核心体验 |

如果写了 `autoplay`，浏览器为了播放通常需要下载资源，`preload` 的节省意义会下降。带声音自动播放常被浏览器限制，即使能绕过，也可能伤害用户体验。

#### 字幕轨道

视频有对白、讲解或重要声音信息时，应考虑提供字幕。

```html
<video controls poster="/images/course-cover.jpg">
  <source src="/media/course.mp4" type="video/mp4" />
  <track src="/media/course.zh.vtt" kind="subtitles" srclang="zh" label="中文" default />
</video>
```

字幕不仅服务听障用户，也服务静音环境、嘈杂环境和非母语用户。

视频还要考虑“海报图、字幕、时长、清晰度、网络失败”的完整体验。用户在列表页看到视频卡片时，通常先消费封面和标题；进入详情页后，才决定是否播放。封面和标题应能独立表达视频内容，不要把关键信息只藏在视频第一帧里。

## 资源格式

多媒体格式选择要在兼容性、体积、质量、编码成本之间取平衡。HTML 的 `source` 允许为同一内容提供多个格式，浏览器会选择自己支持的版本。

```html
<picture>
  <source srcset="/images/hero.avif" type="image/avif" />
  <source srcset="/images/hero.webp" type="image/webp" />
  <img src="/images/hero.jpg" alt="课程主视觉" width="1200" height="630" />
</picture>
```

```html
<video controls>
  <source src="/media/demo.webm" type="video/webm" />
  <source src="/media/demo.mp4" type="video/mp4" />
</video>
```

| 类型 | 常见格式 | 判断重点 |
| --- | --- | --- |
| 图片 | AVIF、WebP、JPEG、PNG、SVG | 体积、透明、清晰度、兼容性 |
| 音频 | MP3、AAC、OGG、WAV | 兼容性、音质、文件大小 |
| 视频 | MP4、WebM | 浏览器支持、编码成本、清晰度 |

SVG 适合图标和矢量图，但如果允许用户上传 SVG，要特别注意脚本、外链和安全清洗，不能简单当作普通图片处理。

格式选择不是越新越好。AVIF、WebP 往往体积更小，但编码成本、透明支持、动画支持、浏览器兼容和 CDN 转码能力都要一起看。对内容站来说，常见策略是优先提供 AVIF/WebP，再保留 JPEG/PNG 兜底；对图标系统，则优先 SVG 或图标字体之外的现代方案，避免把小图标做成大量位图请求。

## 媒体加载

多媒体加载策略决定页面是“先可用再补资源”，还是“资源抢占导致首屏变慢”。判断顺序通常是：是否首屏关键内容、是否影响布局稳定、是否用户一定会消费。

#### 懒加载

```html
<img
  src="/images/cover.jpg"
  alt="课程封面"
  loading="lazy"
  width="640"
  height="360"
/>
```

`loading="lazy"` 适合首屏之外的图片和 iframe。首屏关键图不要盲目懒加载，否则可能拖慢最大内容绘制。懒加载图片尤其要写尺寸，避免进入视口后造成页面抖动。

#### 资源优先级

首屏主视觉如果确实是最大内容，可以提高发现和加载优先级：

```html
<img
  src="/images/hero.webp"
  alt="课程首页主视觉"
  width="1200"
  height="630"
  fetchpriority="high"
/>
```

不要把所有图片都设成高优先级。优先级是稀缺资源，滥用会让真正关键的 CSS、字体、脚本和首屏图互相抢带宽。

判断一张图是否首屏关键，可以看它是否会成为最大内容绘制元素、是否在首屏可见、是否影响用户理解页面主题。首屏 logo 不一定需要高优先级，首屏商品主图或文章封面更可能需要。性能优化不是把所有资源都提前，而是让真正影响用户感知的资源先到。

#### 内容与装饰

内容图片用 `img`，装饰图片更适合 CSS 背景。这个判断会影响语义、可访问性、加载顺序和是否参与搜索引擎图片理解。

| 场景 | 推荐方式 | 原因 |
| --- | --- | --- |
| 商品图、头像、文章配图 | `img` | 是内容，需要替代文本和尺寸 |
| 背景纹理、装饰渐变 | CSS background | 只是视觉效果 |
| 响应式主视觉 | `picture` / `srcset` | 需要按环境选择资源 |
| 视频课程预览 | `video` + `poster` + `preload` | 需要控制加载和播放体验 |

多媒体优化会继续进入 [[6.2.6 图片优化|图片优化]]、[[6.2.7 字体优化|字体优化]] 和 [[1.4.7 页面加载|页面加载]]。在 HTML 阶段先把语义、尺寸和加载意图写清楚，后续性能优化才有抓手。

## 资源选择

#### 媒体语义

多媒体标签不是“能显示就行”，而是要区分内容、装饰、交互和可访问性。图片、音频和视频都应该在 HTML 里表达它们是内容、说明还是可选补充。

```text
内容媒体：商品图、课程封面、教学视频
说明媒体：流程图、示意图、讲解音频
装饰媒体：背景纹理、装饰图案
交互媒体：播放器封面、可点击预览
```

不同角色决定了不同标签选择。比如课程页面里的封面图应该是真正的内容图片，而不是 CSS 背景；视频封面如果承载信息，也应该有明确的替代描述。

#### 图片组合

当一张图片需要根据格式、清晰度和设备适配多种资源时，`picture` 是最常见的组合写法。

```html
<picture>
  <source srcset="/images/hero.avif" type="image/avif" />
  <source srcset="/images/hero.webp" type="image/webp" />
  <img src="/images/hero.jpg" alt="课程主视觉" width="1200" height="630" />
</picture>
```

浏览器会从上到下选择自己支持的格式。`picture` 更适合“同一张图的不同资源版本”，`srcset` 更适合“同一张图的不同分辨率”。两者一起用时，优先关注资源选择是否符合视觉和体积要求。

#### 默认控件与移动端播放

音频和视频默认控件通常比自定义播放器更稳，因为浏览器已经处理了键盘、焦点、播放状态和系统媒体能力。

```html
<video controls playsinline preload="metadata" poster="/images/video-cover.jpg">
  <source src="/media/demo.webm" type="video/webm" />
  <source src="/media/demo.mp4" type="video/mp4" />
</video>
```

`playsinline` 在移动端尤其重要，它能减少某些浏览器把视频强制全屏播放的情况。`controls` 则能把可访问性和基础交互交给浏览器兜底。

#### 字幕与描述

`track` 不只是“给听障用户看字幕”，它还服务静音环境、跨语言学习和视频检索。

```html
<track src="/media/course.zh.vtt" kind="subtitles" srclang="zh" label="中文" default />
```

如果页面有大量视频课程，字幕文件也应该纳入资源管理和版本管理。视频和字幕版本不一致时，用户体验会明显变差。

#### 加载场景

媒体加载不能只看首屏。高优先级资源会影响关键渲染，低优先级资源则要避免阻塞用户操作。

```text
适合高优先级：
1. 首屏主视觉
2. 当前视图的视频封面
3. 会立即播放的音频

适合低优先级：
1. 页面外的预览图
2. 非首屏视频
3. 用户未触发的音频
```

如果页面内容主要靠图片传达信息，懒加载和尺寸预留就比“先显示再说”更重要。如果视频只是辅助内容，就不要抢占主内容的加载预算。

#### 选型顺序

多媒体资源的选择通常不是单点问题，而是兼容性、体积、质量和编码成本的平衡。

```text
选型顺序：
1. 先选语义正确的标签
2. 再补合适的资源格式
3. 再决定是否需要响应式资源
4. 最后再调加载策略
```

如果一个项目里图片很多，先统一格式和尺寸策略；如果视频很多，先统一封面、字幕和预加载策略。先把资源模型写清楚，后面性能优化才不会反复推倒重来。

多媒体文档最终要落到工程约定。比如上传侧限制原图尺寸，构建侧生成多尺寸资源，运行时按视口选择合适资源，监控侧观察 LCP、CLS、带宽和错误率。HTML 标签只是入口，真正稳定的体验来自“资源生产、资源声明、资源加载、失败兜底”这一整条链路。
