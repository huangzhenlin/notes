## 基本分类

JavaScript 的值可以先分成两类：原始值和对象。原始值包括 `string`、`number`、`boolean`、`undefined`、`null`、`bigint` 和 `symbol`；对象则包括普通对象、数组、函数、日期、正则、Map、Set 等。

原始值的特点是“值本身就是结果”。它们通常更适合表达状态、枚举、标识、计数和轻量配置；对象更适合表达结构化数据和可变状态。

```javascript
let title = 'hello';
title = title.toUpperCase();

const user = { name: 'Ada' };
user.name = 'Grace';
```

原始值和对象最核心的差别，不是语法，而是语义：前者更像数据片段，后者更像数据容器。这个差别会直接影响比较、复制、序列化和状态管理方式。

在工程里，数据类型往往决定“变化怎么表达”。原始值变化通常意味着替换成新值，对象变化则可能是修改原引用，也可能是创建新对象。React、Vue、Redux、Zustand 这类状态系统都非常依赖这种差异：引用没变时，框架或缓存层可能认为数据没有变化；引用变了时，即使内容相似，也可能触发更新。

#### 原始值与对象

原始值比较的是内容本身，对象比较的是引用是否相同。

```javascript
console.log(1 === 1); // true
console.log('a' === 'a'); // true
console.log({} === {}); // false
```

这意味着很多“看起来一样”的对象，其实并不是同一个值。只要涉及缓存、去重、状态更新，就要先想清楚你要比较的是“内容相等”还是“同一引用”。

| 类型 | 是否可变 | 比较方式 | 常见用途 |
|---|---|---|---|
| 原始值 | 否 | 按值比较 | 标识、状态、枚举、计数 |
| 对象 | 是 | 按引用比较 | 结构化数据、集合、实例 |

#### 包装对象

`string`、`number`、`boolean` 这些原始值在需要调用方法时，会临时经过包装对象转换，但这不代表你应该主动创建包装对象。

```javascript
const text = 'hello';
console.log(text.toUpperCase());

console.log(new String('hello') instanceof String); // true
console.log(typeof new String('hello')); // object
```

`new String()` 之类的写法会把原始值变成对象，反而容易制造判断错误。业务代码里通常应直接使用字面量。

包装对象最容易造成的问题是条件判断和相等比较。比如 `new Boolean(false)` 是一个对象，在条件判断中是真值；`new Number(1) !== 1`，因为一个是对象，一个是原始值。除非你在研究语言机制，业务代码里几乎不需要主动创建这些包装对象。

## 类型判断

`typeof` 是第一层筛查工具，速度快，适合先分原始类型和函数。

```javascript
typeof 'a'; // string
typeof 1; // number
typeof true; // boolean
typeof undefined; // undefined
typeof Symbol(); // symbol
typeof 1n; // bigint
typeof function () {}; // function
typeof {}; // object
typeof null; // object
```

`typeof null === 'object'` 是历史遗留问题，所以它不能单独作为对象判断的最终答案。

#### 常用判断方式

不同场景适合不同判断工具。

| 方法 | 适合判断 | 注意点 |
|---|---|---|
| `typeof` | 原始值、函数 | `null` 会误判 |
| `Array.isArray` | 数组 | 只能判断数组 |
| `instanceof` | 构造器实例 | 跨 realm 可能失效 |
| `Object.prototype.toString.call` | 更细粒度类型 | 写法略长 |
| `Object.is` | 特殊相等比较 | 用于 `NaN`、`-0` |

```javascript
Array.isArray([]); // true
[] instanceof Array; // true
Object.prototype.toString.call(null); // [object Null]
Object.is(NaN, NaN); // true
Object.is(0, -0); // false
```

#### 相等比较

`===` 是业务里最常用的比较方式，但它仍然有两个容易忽略的点：`NaN !== NaN`，以及 `0 === -0`。

```javascript
console.log(NaN === NaN); // false
console.log(Object.is(NaN, NaN)); // true
console.log(0 === -0); // true
console.log(Object.is(0, -0)); // false
```

当你在做缓存键、记忆化、状态快照、浮点边界判断时，`Object.is` 往往比 `===` 更贴近直觉。

数组去重、对象比较和状态更新里要特别注意引用。`Set` 可以轻松去重原始值，但对对象只会按引用去重；两个内容完全相同的对象，只要不是同一个引用，就会被认为是两个元素。

```javascript
const set = new Set();
set.add({ id: 1 });
set.add({ id: 1 });

console.log(set.size); // 2
```

如果要按业务字段去重，应该显式使用 `id`、`key` 或序列化后的稳定标识，而不是期待对象自动深比较。

## `null` 与 `undefined`

`undefined` 通常表示“没有赋值”或“属性不存在”，`null` 通常表示“这里刻意为空”。

```javascript
let input;
const result = null;
```

这两个值在接口设计、表单初始化、可选字段处理中都很重要。最稳妥的做法是先统一约定语义，再写判断逻辑。

```javascript
function getUserName(user) {
  if (user == null) return '未知';
  return user.name ?? '匿名';
}
```

`user == null` 是少数有明确用途的宽松比较，它能同时匹配 `null` 和 `undefined`。如果团队不接受这种写法，也可以显式写成两次判断。

接口设计里最好提前约定“空值”语义。比如表单未填写可以是空字符串，接口缺失字段可以是 `undefined`，数据库里刻意清空可能是 `null`。如果这些值混用，前端判断会到处出现 `value || defaultValue` 这类看似简单、实际会误伤 `0` 和空字符串的写法。

## 数字

JavaScript 的 `number` 基于 IEEE 754 双精度浮点数，这决定了它既能处理整数，也会遇到精度问题。

```javascript
console.log(0.1 + 0.2 === 0.3); // false
```

#### 浮点边界

金额、计数、精确坐标这类场景，最好不要直接依赖浮点数相加。常见做法是转成最小单位再运算，或交给高精度库处理。

```javascript
const cents = 10 * 100 + 20 * 100; // 1200
```

#### 非数字

`NaN` 也是 `number` 类型，但它表示“不是一个合法数字”。

```javascript
typeof NaN; // number
Number.isNaN(NaN); // true
Number.isFinite(10 / 0); // false
```

判断数值是否可靠时，优先用 `Number.isNaN` 和 `Number.isFinite`。它们不会像全局 `isNaN` 那样先做隐式转换。

数值转换也要避免过度依赖隐式规则。`Number('')` 会得到 `0`，`Number(null)` 也会得到 `0`，但这不代表空输入就是合法数字。表单、URL 参数和接口字段都应该先判断是否为空，再决定是否转换。

```javascript
function parseAmount(input) {
  if (input.trim() === '') return null;

  const value = Number(input);
  return Number.isFinite(value) ? value : null;
}
```

#### 无穷与边界

`Infinity` 和 `-Infinity` 常出现在除零、超出范围和错误计算中。业务代码里通常应该尽早拦截，而不是等它们一路传播到渲染层。

```javascript
const ratio = total === 0 ? 0 : value / total;
```

## 字符串

字符串是不可变值。每次“修改”字符串，其实都是创建新字符串。

```javascript
const name = 'Ada';
const upper = name.toUpperCase();
```

字符串特别适合文本、ID、URL、JSON 字符串和用户输入。模板字符串适合拼接可读性更强的内容。

```javascript
const message = `你好，${name}`;
```

#### 字符串与结构化数据

如果字符串里装的是结构化数据，最好尽快转回对象，而不是一直按字符串传递。

```javascript
const payload = JSON.parse('{"name":"Ada"}');
```

字符串好传输，不好维护；对象好维护，不好直接传输。很多接口层和状态层的问题，都出在这个转换边界上。

字符串还有编码和标准化问题。用户输入的空格、大小写、全角半角、换行、不可见字符，都可能影响比较和存储。登录名、搜索词、标签、URL slug 这类字段通常要在进入业务逻辑前做明确清洗，而不是在每个使用点临时处理。

## 布尔值

布尔值只有 `true` 和 `false`，但在条件判断中，很多值会被隐式转成布尔值。

```javascript
if ('') {
  // 不会执行
}

if ([]) {
  // 会执行
}
```

#### 真值与假值

常见假值只有这些：

```text
false
0
-0
0n
''
null
undefined
NaN
```

理解真假值最重要的意义，不是背列表，而是减少“看起来能跑、实际判断不稳”的代码。

```javascript
const hasValue = value !== '' && value != null;
```

默认值处理时尤其要区分 `||` 和 `??`。`||` 会把所有假值都当成需要兜底，`??` 只会在 `null` 或 `undefined` 时兜底。端口号 `0`、空字符串、布尔 `false` 在业务里都可能是有效值。

```javascript
const pageSize = input.pageSize ?? 20;
const title = input.title || '未命名';
```

上面两种写法都可能合理，关键是你是否真的想把空字符串、0、false 当作“没有值”。

## `Symbol` 与 `BigInt`

`Symbol` 常用于创建唯一键，避免对象属性冲突；`BigInt` 用于安全整数范围之外的大整数。

```javascript
const cacheKey = Symbol('cache');
const total = 9007199254740993n;
```

`BigInt` 不能和普通 `number` 直接混算。

```javascript
// 1n + 1; // TypeError
```

`Symbol` 常见于库设计和内部标记，不适合拿来当用户可读数据。`BigInt` 更适合账务、加密、计数器和超大编号。

`BigInt` 不能被 JSON 原生序列化，和后端接口交互时通常需要转成字符串。超大 ID 如果从接口返回，前端也常常应该按字符串处理，避免超过安全整数后出现精度丢失。

```javascript
const id = '90071992547409931234';
```

如果 ID 只是标识，不需要数学运算，字符串往往比 `number` 更安全。

## 结构化数据

当数据天然是“多条记录”或“键值集合”时，优先选更合适的容器，而不是全部塞进普通对象。

```javascript
const list = [];
const map = new Map();
const set = new Set();
```

普通对象适合简单字典结构；`Map` 适合动态键；`Set` 适合去重；数组适合有序列表。选错容器，后面很多操作都会别扭。

`Object` 的键会被转换成字符串，`Map` 的键可以是任意值。缓存 DOM 节点、对象实例、请求配置这类场景，`Map` 通常比普通对象更合适；需要避免对象被缓存强引用时，还可以考虑 `WeakMap`，它不会阻止键对象被垃圾回收。

```javascript
const cache = new WeakMap();

function getMeta(node) {
  if (!cache.has(node)) {
    cache.set(node, { createdAt: Date.now() });
  }
  return cache.get(node);
}
```

| 容器 | 优势 | 适用场景 |
|---|---|---|
| `Object` | 简单、普遍 | 配置、普通字典 |
| `Map` | 键类型更自由 | 缓存、动态索引 |
| `Set` | 天然去重 | 标签、集合判断 |
| `Array` | 顺序明确 | 列表、时间线、队列 |

## 类型与工程

数据类型不是孤立知识。它会直接影响 [[1.3.2 作用域|作用域]]、[[1.3.3 闭包|闭包]]、序列化、状态更新和模块边界。

比如，原始值更适合做“快照”，对象更适合做“引用状态”；字符串更适合传输，数组和对象更适合计算。类型选对了，后面的代码通常更稳。

写业务代码时可以把类型当成接口契约的一部分：这个字段是否可能为空，数字是否可能超过安全整数，数组是否有顺序含义，对象是否允许被外部修改。只要契约清楚，类型判断和异常处理就不会散落在各处。
