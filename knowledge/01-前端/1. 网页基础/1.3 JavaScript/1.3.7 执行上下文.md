## 上下文对象

执行上下文可以理解为 JavaScript 运行时为一段代码准备的环境记录，它保存当前能访问的变量、函数、`this` 和外部引用。

```javascript
const name = 'Ada';

function greet() {
  const message = `Hello, ${name}`;
  return message;
}
```

当 `greet` 执行时，运行时需要知道 `message` 在哪里、`name` 去哪里找、`this` 是什么。这些信息都由执行上下文承载。

执行上下文不是语法概念，而是解释“代码在运行时到底怎么找变量、怎么绑定 `this`、怎么进入和退出函数”的运行时模型。

可以把执行上下文分成几类：全局执行上下文负责启动整个脚本，函数执行上下文负责一次函数调用，模块执行上下文负责 ES Module 的顶层代码。每次函数调用都会创建新的执行上下文，这也是为什么同一个函数被调用多次时，局部变量不会互相覆盖。

## 创建阶段

函数执行前，会先进入准备阶段，建立变量绑定、函数声明和 `this` 的初始值。

```javascript
say();

function say() {
  console.log('hello');
}
```

这也是为什么函数声明可以在声明前调用。执行上下文的创建阶段先把绑定建好，随后才进入逐行执行。

```javascript
console.log(value); // undefined
var value = 1;

console.log(count); // ReferenceError
let count = 1;
```

`var` 会在创建阶段完成初始化为 `undefined`；`let` 和 `const` 则要等到执行到声明语句才真正可用，所以会出现暂时性死区。

创建阶段还会建立作用域链和 `this` 绑定。注意“声明被处理”和“代码已经执行”不是一回事。函数声明能提前调用，是因为绑定已经可用；`let` / `const` 声明虽然也被记录在词法环境里，但在初始化前不能访问。

## 执行阶段

执行阶段按顺序运行语句，真正给变量赋值、调用函数、创建对象和触发副作用。

```javascript
let count = 0;

function increment() {
  count += 1;
  return count;
}

increment();
```

创建阶段只负责“有这个名字”，执行阶段才负责“这个名字现在是什么值”。理解这点后，很多“明明声明了却还不能用”的问题就容易解释了。

执行阶段也是副作用真正发生的阶段。DOM 修改、网络请求、计时器注册、事件监听、对象属性赋值都发生在执行阶段。创建阶段不会帮你执行函数体，也不会提前跑表达式，它只是在为接下来的逐行执行准备环境。

## 调用栈

调用栈记录当前正在执行的函数调用。

```javascript
function a() {
  b();
}

function b() {
  c();
}

function c() {
  console.trace();
}

a();
```

大致栈形态是：

```text
global
  -> a
  -> b
  -> c
```

函数执行完，栈帧就弹出。递归太深会导致栈溢出，因为调用栈空间有限。

调用栈也是调试异常的第一线索。报错堆栈从下往上通常能看到调用链：谁调用了谁，最终在哪一行出错。如果栈里出现大量重复函数名，往往是递归没有出口或循环调用过深。

```javascript
function factorial(n) {
  if (n <= 1) return 1;
  return n * factorial(n - 1);
}
```

递归不是不能用，而是要确保有明确终止条件，并且递归深度在可控范围内。

## 词法环境

执行上下文内部包含词法环境，用来记录标识符和它们的绑定关系。

```javascript
const outer = 'outer';

function create() {
  const inner = 'inner';

  return function read() {
    return `${outer}-${inner}`;
  };
}
```

`read` 能访问 `inner`，是因为执行上下文建立了对外层词法环境的引用。这也是闭包成立的基础。

词法环境记录的是标识符绑定，而不是简单的对象属性表。函数执行时，如果当前词法环境找不到某个名字，就会沿外层环境继续找。这个查找路径在函数创建时就已经确定，所以它和 [[1.3.2 作用域|作用域]]、[[1.3.3 闭包|闭包]] 是同一条机制链。

## `this` 绑定

执行上下文里还包括 `this` 绑定。普通函数的 `this` 由调用方式决定，箭头函数则捕获外层词法环境。

```javascript
const user = {
  name: 'Ada',
  say() {
    return this.name;
  },
};

user.say();
```

`this` 的规则可以继续看 [[1.3.4 this|this]]。在执行上下文中，它和词法环境并列存在，但不是通过作用域链查找出来的。

这点很重要：`this` 不是普通变量。普通变量按词法作用域查找，`this` 由调用方式或箭头函数捕获决定。把 `this` 当成“外层变量”理解，会在对象方法、事件回调和 class 方法里频繁误判。

## 异步关系

异步回调不会一直停留在原始调用栈里。当前同步代码执行完后，回调会在未来某个任务中重新进入调用栈。

```javascript
console.log('start');

setTimeout(() => {
  console.log('timer');
}, 0);

Promise.resolve().then(() => {
  console.log('promise');
});

console.log('end');
```

输出通常是：

```text
start
end
promise
timer
```

执行上下文解释“当下代码怎么跑”，而异步调度解释“以后代码怎么回来跑”。这部分可以和 [[1.4.2 事件循环|事件循环]] 一起看。

异步回调重新进入调用栈时，会创建自己的执行上下文。它仍然可以通过闭包访问之前保存的词法环境，但它不是暂停在原来的栈帧里继续执行。`await` 看起来像暂停函数，底层仍然要把后续逻辑安排到未来的微任务里继续运行。

```javascript
async function run() {
  const value = await Promise.resolve(1);
  return value + 1;
}
```

`await` 后面的代码不会在当前同步调用栈里立刻继续，而是在 Promise fulfilled 后重新调度执行。
