## 调用点

`this` 的值主要由函数“如何被调用”决定，而不是由函数“写在哪里”决定。

```javascript
function show() {
  console.log(this.name);
}

const user = {
  name: 'Ada',
  show,
};

user.show(); // Ada
```

这里 `show` 作为 `user` 的方法被调用，所以 `this` 指向 `user`。判断 `this` 时，不要先看函数定义位置，要先找真实调用点。

```javascript
const fn = user.show;
fn(); // this 不再是 user
```

函数一旦被取出来单独调用，原来的对象关系就丢了。这也是回调、事件监听和解构赋值里最常见的 `this` 问题。

判断 `this` 时，最稳的动作是找到函数执行时左边有没有“调用者”。`user.show()` 里调用者是 `user`；`const fn = user.show; fn()` 里 `fn` 前面没有对象，已经是普通函数调用。这个判断比记“函数属于哪个对象”更可靠，因为函数本身并不永久属于某个对象。

## 绑定规则

常见绑定方式可以分成五类：默认绑定、隐式绑定、显式绑定、`new` 绑定、箭头函数词法绑定。

| 调用形式 | this 来源 | 典型场景 |
|---|---|---|
| `fn()` | 默认绑定 | 普通函数调用 |
| `obj.fn()` | 调用对象 | 对象方法 |
| `fn.call(obj)` | 显式指定 | 借用方法、修正回调 |
| `new Fn()` | 新创建对象 | 构造函数、class |
| `() => {}` | 外层词法作用域 | 回调、定时器 |

真实排查时，还要结合严格模式、模块环境、回调传递和框架封装一起看。

绑定规则之间也有优先级。`new` 绑定通常高于显式绑定，显式绑定高于隐式绑定，隐式绑定高于默认绑定；箭头函数则不参与这些动态绑定，它从定义时外层环境捕获 `this`。只要先判断函数是不是箭头函数，再看调用形式，绝大多数问题都能定位。

## 默认绑定

普通函数直接调用时，非严格模式下 `this` 通常指向全局对象；严格模式下是 `undefined`。

```javascript
'use strict';

function printThis() {
  console.log(this);
}

printThis(); // undefined
```

现代代码默认应按严格模式理解，尤其是 ES Module、构建工具输出和 TypeScript 编译后的代码。不要依赖全局 `this`。

```javascript
// ES Module 顶层 this 是 undefined
console.log(this);
```

默认绑定最容易出现在回调里：你以为函数还是对象方法，实际已经变成普通函数调用。

ES Module、class 方法、构建工具输出通常都处在严格模式语义下，因此默认绑定变成 `undefined` 更常见。旧教程里“普通函数 this 指向 window”的说法在现代工程里很容易误导。写业务代码时，不要把全局对象当作默认兜底。

## 隐式绑定

对象方法调用会把 `this` 绑定到调用它的对象。

```javascript
const counter = {
  count: 0,
  increment() {
    this.count += 1;
  },
};

counter.increment();
console.log(counter.count); // 1
```

隐式绑定容易丢失。只要方法被单独赋值、解构或作为回调传递，调用点就改变了。

```javascript
const increment = counter.increment;
increment(); // this 不再指向 counter

const { increment: inc } = counter;
inc(); // 仍然丢失 this
```

如果函数依赖对象状态，就不要随意把它拆出来当普通函数传递。更稳妥的方式是绑定 `this`，或者把函数改造成显式接收参数的纯函数。

隐式绑定还有一个细节：只有最后一层调用者生效。

```javascript
const app = {
  user: {
    name: 'Ada',
    show() {
      return this.name;
    },
  },
};

app.user.show(); // this 是 app.user，不是 app
```

点号链很长时，不要误以为 `this` 会指向最外层对象。真正参与调用的是离函数最近的那个对象。

## 显式绑定

`call`、`apply`、`bind` 可以显式指定 `this`。

```javascript
function introduce(city) {
  return `${this.name} lives in ${city}`;
}

const user = { name: 'Ada' };

introduce.call(user, 'London');
introduce.apply(user, ['London']);

const introduceAda = introduce.bind(user);
introduceAda('London');
```

`call` 和 `apply` 会立即执行，区别只在参数传递形式；`bind` 返回一个新函数，适合回调和事件处理。

```javascript
class Counter {
  count = 0;

  increment() {
    this.count += 1;
  }
}

const counter = new Counter();
button.addEventListener('click', counter.increment.bind(counter));
```

`bind` 每次调用都会创建新函数。事件监听里如果要移除监听器，添加和移除必须拿到同一个函数引用。

因此不要在添加和移除监听时分别写一次 `bind`。

```javascript
const handler = counter.increment.bind(counter);

button.addEventListener('click', handler);
button.removeEventListener('click', handler);
```

如果两次都写 `counter.increment.bind(counter)`，得到的是两个不同函数，移除监听会失败。

## `new` 绑定

使用 `new` 调用函数时，`this` 指向新创建的对象。

```javascript
function User(name) {
  this.name = name;
}

const user = new User('Ada');
console.log(user.name); // Ada
```

`new` 调用大致做四件事：创建对象、连接原型、绑定 `this`、返回对象。`class` 构造函数也是基于这套语义，只是语法更清晰。

```javascript
class User {
  constructor(name) {
    this.name = name;
  }
}
```

构造函数如果忘记 `new`，在非严格模式下可能污染全局对象；严格模式下更容易直接报错。现代代码更推荐使用 `class` 或工厂函数降低误用。

`new` 绑定还会影响返回值。如果构造函数显式返回一个对象，这个对象会替代默认创建的实例；如果返回原始值，则仍然返回默认实例。这类规则在普通业务里很少主动使用，但能解释一些旧代码的奇怪行为。

## 箭头函数

箭头函数没有自己的 `this`，它会捕获外层词法环境中的 `this`。

```javascript
const timer = {
  seconds: 0,
  start() {
    setInterval(() => {
      this.seconds += 1;
    }, 1000);
  },
};
```

这里箭头函数里的 `this` 来自 `start` 方法执行时的 `this`，因此能访问 `timer`。如果把回调写成普通函数，`this` 就会按新的调用方式决定。

箭头函数不适合作为需要动态 `this` 的对象方法。

```javascript
const user = {
  name: 'Ada',
  say: () => {
    console.log(this.name);
  },
};
```

对象方法需要动态 `this` 时，使用普通方法语法更合适。

```javascript
const user = {
  name: 'Ada',
  say() {
    console.log(this.name);
  },
};
```

箭头函数更适合写“我需要外层 this”的回调，例如定时器、Promise、数组方法或事件包装；普通方法更适合写“调用者是谁，this 就是谁”的对象行为。两者不是谁更现代，而是绑定模型不同。

## DOM 事件

DOM 事件监听中，普通函数的 `this` 通常指向绑定事件的元素；箭头函数则使用外层 `this`。

```javascript
button.addEventListener('click', function () {
  console.log(this === button); // true
});

button.addEventListener('click', () => {
  console.log(this); // 外层 this
});
```

现代项目里更推荐通过 `event.currentTarget` 读取当前绑定元素，因为它比依赖 `this` 更明确。

```javascript
button.addEventListener('click', (event) => {
  console.log(event.currentTarget);
});
```

DOM 事件中的 `target` 和 `currentTarget` 差异，可以在 [[1.3.11 事件|事件]] 中继续展开。组件化项目里，事件对象通常比 `this` 更清楚。

在 React、Vue 等框架里，也不要默认把组件逻辑建立在 DOM 事件的 `this` 上。现代框架更强调状态、props、闭包和事件对象。`this` 更多出现在 class 组件、旧式组件 API、原生 DOM 和对象方法中。

## 排查顺序

判断 `this` 可以按优先级从高到低看：

```text
new 调用
bind/call/apply 显式绑定
对象方法调用
普通函数默认绑定
箭头函数看外层词法环境
```

遇到 `this` 问题时，先找真实调用点。如果函数被当作回调传递，原来的对象关系通常已经丢失。

| 现象 | 常见原因 | 处理方式 |
|---|---|---|
| 方法传给回调后报错 | 隐式绑定丢失 | `bind`、箭头包装、改纯函数 |
| 箭头方法拿不到对象 | 箭头函数没有动态 `this` | 使用普通方法 |
| 事件里 `this` 不符合预期 | 箭头函数捕获外层 `this` | 使用 `event.currentTarget` |
| class 方法作为监听器失效 | 方法未绑定实例 | 构造器绑定或类字段箭头函数 |

`this` 的难点不在规则多，而在调用点经常被回调、事件、框架和解构改变。把调用点找出来，问题通常就清楚了。

如果一段代码频繁需要 `bind` 或不断解释 `this`，可以考虑换成显式参数。显式参数牺牲一点调用简洁性，但会让依赖关系更清楚。工具函数、数据转换、请求处理这类逻辑通常没必要依赖 `this`。
