## 引用语义

JavaScript 中对象、数组、函数都是引用值。变量保存的不是对象本身，而是指向对象的引用。拷贝问题的核心是：新变量是否仍然共享原对象内部的某些引用。

```javascript
const user = {
  name: 'Ada',
  profile: {
    city: 'London',
  },
};

const copy = user;
copy.profile.city = 'Paris';

console.log(user.profile.city); // Paris
```

这里没有发生拷贝，只是两个变量指向同一个对象。判断是否需要拷贝，先看是否会修改数据，以及修改是否应该影响原对象。

拷贝不是为了“保险”，而是为了隔离变化。如果只是读取数据，不需要拷贝；如果要修改对象但不希望影响原对象，就要复制相关引用层级。很多性能问题来自无意义拷贝：数据刚从接口回来，只是渲染一次，却先完整深拷贝一遍；用户每输入一个字符，就把整个大状态复制一次。这些都不是不可变更新，而是没有想清变化边界。

## 浅拷贝

浅拷贝只复制对象第一层属性。如果属性值本身是对象，复制的仍然是引用。

```javascript
const user = {
  name: 'Ada',
  profile: {
    city: 'London',
  },
};

const copy = { ...user };
copy.name = 'Grace';
copy.profile.city = 'Paris';

console.log(user.name); // Ada
console.log(user.profile.city); // Paris
```

常见浅拷贝方式：

| 数据 | 写法 |
|---|---|
| 对象 | `{ ...obj }`、`Object.assign({}, obj)` |
| 数组 | `[...list]`、`list.slice()`、`Array.from(list)` |
| Map | `new Map(oldMap)` |
| Set | `new Set(oldSet)` |

浅拷贝适合只修改第一层字段的场景。如果要修改嵌套对象，就需要复制被修改路径上的每一层。

浅拷贝还会保留原型之外的普通属性，但不会复制属性描述符、getter/setter 的执行语义和不可枚举属性。对象展开和 `Object.assign` 主要面向普通数据对象，不适合复制复杂实例、DOM 节点、类对象或带内部状态的宿主对象。

## 路径复制

不可变更新常用“路径复制”：只复制从根对象到被修改节点的路径，其他未变部分继续共享引用。

```javascript
const state = {
  user: {
    name: 'Ada',
    profile: {
      city: 'London',
    },
  },
  theme: 'light',
};

const nextState = {
  ...state,
  user: {
    ...state.user,
    profile: {
      ...state.user.profile,
      city: 'Paris',
    },
  },
};
```

`theme` 没变，可以复用原引用；`user` 和 `profile` 在修改路径上，需要创建新对象。前端状态管理里的不可变更新大多基于这个思想。

路径复制的优势是成本可控：只复制发生变化的路径，不复制整棵树。它也让引用比较变得有意义。比如状态库可以通过 `nextState.user !== state.user` 判断用户数据变化，而 `nextState.theme === state.theme` 表示主题没有变化。不可变更新不是“所有东西都深拷贝”，而是“变化路径产生新引用，未变化部分保持共享”。

## 深拷贝

深拷贝会递归复制对象内部结构，让新对象尽量不共享旧对象的嵌套引用。但深拷贝不等于“万能复制”。

```javascript
const copy = JSON.parse(JSON.stringify(source));
```

JSON 深拷贝有明显限制：

| 问题 | 结果 |
|---|---|
| `undefined` | 属性会丢失 |
| `Date` | 变成字符串 |
| `Map` / `Set` | 结构丢失 |
| 函数 | 被丢弃 |
| 循环引用 | 抛错 |
| `BigInt` | 抛错 |

JSON 深拷贝只适合纯 JSON 数据，例如接口响应、简单配置、没有特殊类型的对象。复杂业务状态不建议依赖它。

JSON 深拷贝还会改变数据语义。`Date` 变成字符串后，再调用日期方法会失败；`undefined` 字段丢失后，调用方可能无法区分“字段不存在”和“字段存在但未定义”；`NaN`、`Infinity` 在 JSON 序列化中也会变成不符合原语义的值。只要数据里包含非 JSON 类型，就不要把 JSON 往返当作通用深拷贝。

## `structuredClone`

`structuredClone` 是现代浏览器和 Node 环境提供的结构化克隆能力，能处理更多内置类型，也支持循环引用。

```javascript
const source = {
  createdAt: new Date(),
  tags: new Set(['html', 'css']),
  map: new Map([['level', 1]]),
};

source.self = source;

const copy = structuredClone(source);

console.log(copy.createdAt instanceof Date); // true
console.log(copy.tags instanceof Set); // true
console.log(copy.self === copy); // true
```

`structuredClone` 仍然不能克隆函数、DOM 节点和部分宿主对象。遇到无法克隆的内容时会抛出 `DataCloneError`。

它适合复制可结构化克隆的数据、Worker 传输数据、缓存快照和历史记录。

`structuredClone` 更接近浏览器内部结构化克隆算法，适合复制“数据”而不是“行为”。函数、类实例的方法、DOM 节点、WeakMap 这类能力型对象并不适合用它复制。如果你需要复制一个业务实体，通常还要考虑身份字段、时间字段、状态字段，而不只是技术上能不能克隆。

## 可转移对象

结构化克隆支持转移部分对象，例如 `ArrayBuffer`。转移后原对象会失效，数据所有权移动到新对象。

```javascript
const buffer = new ArrayBuffer(1024);

const cloned = structuredClone(buffer, {
  transfer: [buffer],
});

console.log(buffer.byteLength); // 0
console.log(cloned.byteLength); // 1024
```

转移不是复制，原对象会被“掏空”。它适合大数据在线程间传递，不适合普通业务对象。

可转移对象的价值在于减少大数据复制成本。比如主线程和 Worker 之间传递音视频 buffer、二进制文件、图像数据时，转移比复制更省内存和时间。但转移后原对象不能继续使用，所以调用方必须明确所有权已经移动。

## 自定义拷贝

业务里经常不需要完整深拷贝，而是需要“按业务语义复制”。例如复制一份表单草稿时，要清空 ID、更新时间和服务端状态，但保留用户输入。

```javascript
function cloneDraft(order) {
  return {
    ...order,
    id: undefined,
    status: 'draft',
    createdAt: new Date().toISOString(),
    items: order.items.map((item) => ({
      ...item,
      id: undefined,
    })),
  };
}
```

这种方式比通用深拷贝更可控。拷贝不只是技术动作，经常意味着业务身份发生变化：复制订单、复制模板、复制配置都要明确哪些字段保留，哪些字段重置。

业务拷贝最好显式写规则。比如复制文章要清空发布时间，复制商品要重置库存状态，复制表单要保留用户输入但清空服务端校验结果。通用深拷贝不知道这些语义，反而可能把不该保留的状态一起带过去。

## 性能成本

深拷贝会消耗 CPU 和内存。对象越大、嵌套越深、频率越高，成本越明显。不要在滚动、输入、动画、频繁渲染中对大对象做完整深拷贝。

| 场景 | 建议 |
|---|---|
| 修改顶层字段 | 浅拷贝 |
| 修改嵌套字段 | 路径复制 |
| 复制纯数据快照 | `structuredClone` |
| 复制业务实体 | 自定义拷贝函数 |
| 高频 UI 更新 | 避免深拷贝大对象 |

拷贝和 [[1.3.1 数据类型|数据类型]]、对象引用、垃圾回收都有关系。写状态更新时，先问“我要隔离哪一层引用”，比直接问“用哪种深拷贝库”更接近根因。

拷贝策略可以按数据形态选择：普通浅层配置用浅拷贝，嵌套状态用路径复制，纯数据快照用 `structuredClone`，业务复制用自定义函数，大型共享数据优先考虑结构设计而不是频繁复制。越靠近高频渲染和交互路径，越要避免不必要的完整深拷贝。
