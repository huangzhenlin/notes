## 状态模型

Promise 表示一个未来才会完成的结果。它只有三种状态：`pending`、`fulfilled`、`rejected`。状态一旦从 `pending` 变成后两者之一，就不会再变回去。

```javascript
const promise = new Promise((resolve, reject) => {
  resolve('done');
  reject(new Error('ignored'));
});
```

上面的 `reject` 不会生效，因为 Promise 已经完成了。不可逆状态是 Promise 能稳定组合的前提。

```text
pending
  -> fulfilled
  -> rejected
```

Promise 自己只是结果容器，不会自动取消底层任务。要取消请求，通常要配合 `AbortController` 或业务层忽略旧结果。

更准确地说，Promise 状态只能从 `pending` 变成 `fulfilled` 或 `rejected` 其中之一，不能先 fulfilled 再 rejected。创建 Promise 时传入的 executor 会立即同步执行，但 `then/catch/finally` 回调会异步进入微任务队列。

```javascript
const promise = new Promise((resolve) => {
  console.log('executor');
  resolve(1);
});

promise.then(() => console.log('then'));
console.log('sync');

// executor
// sync
// then
```

## `then`

`then` 用于注册成功和失败回调，并返回一个新的 Promise。

```javascript
fetch('/api/user')
  .then((response) => response.json())
  .then((user) => render(user));
```

`then` 回调的返回值会传给下一个 `then`。如果返回的是 Promise，后续会等待它完成。

```javascript
fetch('/api/user')
  .then((response) => response.json())
  .then((user) => fetch(`/api/orders?userId=${user.id}`))
  .then((response) => response.json());
```

Promise 链最关键的是“每一步都返回下一步需要的值”。如果忘记 `return`，后面拿到的就是 `undefined`。

`then` 的返回规则可以记成三类：返回普通值，下一步收到这个值；返回 Promise，下一步等待它；抛出错误，链路进入 rejected。掌握这三条，Promise 链就不会神秘。

```javascript
Promise.resolve(1)
  .then((value) => value + 1)
  .then((value) => Promise.resolve(value * 2))
  .then((value) => {
    if (value > 3) throw new Error('too large');
    return value;
  })
  .catch((error) => error.message);
```

## `catch`

`catch` 用于处理链路中的 rejected 状态。

```javascript
fetch('/api/user')
  .then((response) => {
    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`);
    }
    return response.json();
  })
  .catch((error) => {
    showError(error);
  });
```

`catch` 不只会抓 rejected，也会抓前面 `then` 里抛出的异常。错误处理的位置很重要：靠近底层适合做日志和封装，靠近页面适合做用户提示。

`catch` 如果返回一个正常值，后续链路会恢复到 fulfilled 状态。这既可以用于降级，也可能意外吞掉错误。

```javascript
fetchUser()
  .catch(() => ({ name: 'Guest' }))
  .then((user) => render(user));
```

上面代码表示加载失败时渲染游客用户。如果这不是你想要的，就应该在记录错误后重新抛出。

## `finally`

`finally` 不关心成功还是失败，适合做清理工作。

```javascript
let loading = true;

fetch('/api/user')
  .then((response) => response.json())
  .catch(showError)
  .finally(() => {
    loading = false;
  });
```

按钮锁定、加载态关闭、资源释放、订阅清理，都很适合放在 `finally` 里。

`finally` 的返回值通常不会改变前面的成功值或失败原因，除非它自己抛错或返回 rejected Promise。它适合做“不影响结果的清理”，不适合在里面偷偷改业务结果。

## `Promise.all`

`Promise.all` 用于并行等待多个 Promise，全部成功才成功，任意一个失败就整体失败。

```javascript
const [profile, settings] = await Promise.all([
  fetchProfile(),
  fetchSettings(),
]);
```

它适合强依赖场景：页面必须同时拿到多个数据才能渲染。

```javascript
try {
  const result = await Promise.all(tasks);
  render(result);
} catch (error) {
  showError(error);
}
```

如果某个任务失败不应该拖垮其他任务，就别只用 `Promise.all`。

`Promise.all` 的另一个细节是结果顺序和输入顺序一致，而不是完成顺序一致。这让并行请求结果更容易对应回原任务。

```javascript
const [user, orders] = await Promise.all([
  fetchUser(),
  fetchOrders(),
]);
```

即使 `orders` 先返回，解构顺序仍然按数组位置来。

## `Promise.allSettled`

`Promise.allSettled` 会等待所有任务结束，并保留每个任务的状态和结果。

```javascript
const results = await Promise.allSettled([
  fetchBanner(),
  fetchNotifications(),
  fetchRecommendations(),
]);

const successList = results
  .filter((result) => result.status === 'fulfilled')
  .map((result) => result.value);
```

它适合弱依赖场景：推荐位、通知、侧边栏补充数据，一部分失败不该让整个页面空掉。

`allSettled` 返回的数据要显式区分成功和失败，不要直接访问 `value`。失败结果里是 `reason`，成功结果里才是 `value`。这会迫使你在代码里明确降级策略。

## `Promise.race`

`Promise.race` 会返回最先完成的 Promise，不管成功还是失败。

```javascript
function timeout(ms) {
  return new Promise((_, reject) => {
    setTimeout(() => reject(new Error('timeout')), ms);
  });
}

await Promise.race([
  fetch('/api/user'),
  timeout(3000),
]);
```

它常用于超时控制、竞速请求和只关心最快结果的场景。注意 `race` 不会自动取消输掉的 Promise。

如果用 `race` 做超时，超时只是让当前等待提前失败，原请求仍可能在后台继续完成。要真正取消 fetch，需要同时传入 `AbortController`。

```javascript
async function fetchWithTimeout(url, ms) {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), ms);

  try {
    return await fetch(url, { signal: controller.signal });
  } finally {
    clearTimeout(timer);
  }
}
```

## 微任务

Promise 的 `then/catch/finally` 回调通常进入微任务队列，会在当前同步代码执行完之后、下一个宏任务之前执行。

```javascript
console.log('start');

Promise.resolve().then(() => {
  console.log('promise');
});

setTimeout(() => {
  console.log('timer');
}, 0);

console.log('end');
```

通常输出是：

```text
start
end
promise
timer
```

这解释了为什么 Promise 回调经常比 `setTimeout(..., 0)` 更早执行。更完整的调度顺序可以继续看 [[1.4.2 事件循环|事件循环]]。

微任务适合承接 Promise 链路里的后续处理，但也要避免制造无限微任务。浏览器通常会在当前宏任务结束后清空微任务队列，再进入渲染和下一个任务；如果微任务一直追加微任务，页面可能无法及时响应用户输入。

## 错误边界

Promise 错误要么在链上 `catch`，要么在 `async/await` 的 `try/catch` 中处理。未处理的 rejected Promise 会带来隐性问题。

```javascript
async function load() {
  try {
    const user = await fetchUser();
    render(user);
  } catch (error) {
    showError(error);
  }
}
```

不要把所有错误都吞掉。

```javascript
fetchUser().catch(() => {});
```

更好的方式是记录、提示、必要时重新抛出，让调用方继续知道失败。

```javascript
fetchUser().catch((error) => {
  reportError(error);
  throw error;
});
```

Promise 的重点不是背 API，而是理解异步结果如何传播、如何组合、如何失败。掌握这条线之后，`async/await` 会自然很多。

`async/await` 本质上仍然建立在 Promise 上。`async` 函数总是返回 Promise，`await` 会等待 Promise 状态完成；`throw` 会变成 rejected，`return` 会变成 fulfilled。理解 Promise 链后，`try/catch/finally` 只是换了一种更接近同步代码的写法。

```javascript
async function loadUser() {
  const response = await fetch('/api/user');

  if (!response.ok) {
    throw new Error(`HTTP ${response.status}`);
  }

  return response.json();
}
```
