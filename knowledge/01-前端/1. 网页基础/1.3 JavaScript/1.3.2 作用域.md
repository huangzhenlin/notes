## 词法作用域

JavaScript 使用词法作用域，变量能否被访问，主要由代码写在哪里决定，而不是由函数从哪里调用决定。

```javascript
const name = 'global';

function printName() {
  console.log(name);
}

function run() {
  const name = 'local';
  printName();
}

run(); // global
```

`printName` 在定义时就已经决定了它能看到谁。调用点只影响执行时机，不改变变量查找规则。

词法作用域是理解闭包、模块边界和局部状态的前提。很多“为什么不是我以为的那个值”的问题，本质上都和它有关。

词法作用域也解释了为什么“把函数传到别处调用”不会改变它能访问的变量。函数创建时已经绑定了外层词法环境，后续只是被不同代码调用。事件监听、定时器、Promise 回调、数组方法回调，都遵循这个规则。

## 全局作用域

全局作用域里的变量可以被当前脚本中的其他代码访问。

```javascript
const appName = 'notes';

function getAppName() {
  return appName;
}
```

全局变量生命周期长、可访问范围大，容易造成命名冲突和隐式依赖。业务代码应尽量减少全局变量。

```javascript
// 不推荐：把业务状态直接挂到全局
window.currentUser = { id: 1 };
```

全局作用域更适合少量环境常量、调试入口和宿主对象暴露的能力，而不是承载业务状态。

浏览器里的全局对象通常是 `window`，但现代模块脚本顶层声明不会自动变成 `window` 属性。老项目里多个普通 script 文件共享全局作用域，容易发生命名冲突；现代工程通过模块、打包器和闭包把作用域收窄，是为了减少这种隐性耦合。

## 函数作用域

`var` 是函数作用域。

```javascript
function test() {
  if (true) {
    var count = 1;
  }

  console.log(count); // 1
}
```

这也是现代代码更推荐使用 `let` 和 `const` 的原因。函数作用域会让局部变量“看起来像块级”，但实际上能被整个函数访问，容易扩大变量暴露范围。

`var` 还会发生声明提升。变量声明会被提升到函数顶部，但赋值仍留在原位置。这会让“访问了一个尚未真正赋值的变量”变得不明显。现代代码用 `let` / `const` 配合暂时性死区，可以更早暴露这种错误。

## 块级作用域

`let` 和 `const` 是块级作用域。

```javascript
function test() {
  if (true) {
    const count = 1;
  }

  console.log(count); // ReferenceError
}
```

块级作用域能缩小变量可见范围，让变量只在真正需要的地方存在。循环、条件分支、临时代码块都应该优先使用它。

```javascript
for (let i = 0; i < 3; i += 1) {
  console.log(i);
}
```

块级作用域还会影响循环中的每一次绑定，这一点在闭包和异步回调里尤其重要。

`const` 不是“值不能变”，而是“绑定不能重新指向”。对象或数组用 `const` 声明后，内部内容仍然可以修改。选择 `const` 的意义是表达这个变量名不会重新绑定，能减少阅读时的心智负担。

```javascript
const user = { name: 'Ada' };
user.name = 'Grace';
```

## 作用域链

函数访问变量时，会先查找当前作用域，再沿外层作用域向上查找。这个查找路径就是作用域链。

```javascript
const outer = 'outer';

function create() {
  const middle = 'middle';

  return function inner() {
    const local = 'local';
    console.log(local, middle, outer);
  };
}
```

作用域链从内向外层层查找，找不到就继续向上，直到全局作用域。它决定了函数“能看见什么”，也决定了闭包能保留什么。

作用域链查找不是对象属性查找。变量解析发生在词法环境链上，对象属性解析发生在对象和原型链上。两者看起来都是“往外找”，但机制完全不同：`name` 是变量查找，`user.name` 是属性查找。

## 变量遮蔽

内层变量可以遮蔽外层同名变量。

```javascript
const value = 'global';

function run() {
  const value = 'local';
  console.log(value); // local
}
```

遮蔽不是语法错误，但同名变量太多会降低可读性。尤其是在长函数、嵌套回调和复杂分支里，命名应尽量表达真实语义。

遮蔽在短小代码块里可以接受，例如 `map` 回调里的局部变量；但在跨几十行的函数里，同名变量会让读者不知道当前引用的是哪一层。重构时如果发现需要频繁跳转确认变量来源，通常说明作用域边界已经不够清楚。

```javascript
function render(user) {
  const name = user.name;
  if (user.profile) {
    const profileName = user.profile.nickname;
  }
}
```

## 暂时性死区

`let` 和 `const` 在声明前不能访问。

```javascript
console.log(count); // ReferenceError
const count = 1;
```

从作用域开始到声明语句之间的区域，称为暂时性死区。它能避免变量在初始化前被误用。

```javascript
{
  // 这里访问 const/let 会报错
  const value = 1;
}
```

TDZ 的好处是让变量使用时机更明确，减少“先用后声明”造成的隐性错误。

暂时性死区常常在循环、条件分支和模块导入里暴露问题。它让错误尽早失败，而不是返回一个难以追踪的 `undefined`。这也是为什么“声明靠近使用位置”通常更好：变量可见范围越小，初始化顺序越清楚。

## 模块作用域

ES Module 顶层变量属于模块作用域，不会自动挂到全局对象上。

```javascript
// user.js
const cache = new Map();

export function getUser(id) {
  return cache.get(id);
}
```

模块作用域能让文件内部实现保持私有，只暴露明确的 `export`。这比把工具函数和缓存挂到全局对象上更安全，也更容易维护。

```javascript
// 同名变量不会互相污染
const cache = 'local cache';
```

模块作用域是现代前端工程能长期维护的基础。它减少了全局命名冲突，也让依赖边界更清楚。

模块作用域还能表达“私有实现”。文件内部的缓存、辅助函数、常量默认不会暴露出去，只有 `export` 的内容才成为公共 API。这样重构内部实现时，只要导出契约不变，外部调用方就不需要关心。

## 作用域与闭包

闭包本质上就是函数加上它能访问的外层变量。作用域决定“能访问”，闭包决定“能保留”。

```javascript
function createCounter() {
  let count = 0;

  return function increment() {
    count += 1;
    return count;
  };
}
```

`increment` 之所以还能访问 `count`，不是因为它在外层定义，而是因为它保留了创建时的词法环境。理解作用域链，才能真正理解闭包、模块封装和异步回调。

作用域和闭包的关系可以这样分开：作用域决定名字能不能被解析，闭包决定函数离开原始调用栈后是否仍然持有这些名字背后的变量。只要函数逃逸到外部，例如被返回、被保存、被注册成监听器，就可能形成更长生命周期。

## 作用域与异步

异步代码经常把“当下的变量”带到未来执行。

```javascript
function delayLog(value) {
  setTimeout(() => {
    console.log(value);
  }, 1000);
}
```

这里的 `value` 会被回调继续引用。只要你在作用域里创建了闭包，变量就可能比你想象得活得更久。这个特性既能实现缓存，也可能制造内存保留。

```javascript
function fetchAndRender(url) {
  let loading = true;

  fetch(url)
    .then((res) => res.json())
    .then((data) => {
      loading = false;
      render(data);
    });
}
```

作用域不是“变量在哪儿声明”，而是“变量在什么范围内可见、会活多久、会不会被别的代码误用”。这三个问题想清楚，很多前端 bug 就少一半。

异步场景还要警惕“变量被后来修改”。如果多个异步任务共享同一个可变变量，后完成的任务可能读到已经改变的值。更稳的方式是把每次任务需要的数据保存为局部常量，或者用请求 ID、AbortController、状态机来控制结果是否仍然有效。

```javascript
let requestId = 0;

async function search(keyword) {
  const current = ++requestId;
  const result = await fetchResult(keyword);

  if (current !== requestId) return;
  render(result);
}
```
