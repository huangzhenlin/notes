## 原型对象

JavaScript 的每个对象都可能有一个内部原型。通过原型，多个对象可以共享属性和方法，而不是每个实例都复制一份。

```javascript
const animal = {
  move() {
    return `${this.name} is moving`;
  },
};

const dog = Object.create(animal);
dog.name = 'Lucky';

dog.move(); // Lucky is moving
```

`dog` 自身没有 `move`，但它的原型 `animal` 上有这个方法。原型的作用是把“共享行为”提到更高一层，避免重复定义。

原型更像“委托”而不是传统复制继承。对象找不到某个属性时，会委托给原型继续找；原型上也找不到，再继续往上。实例并没有复制原型方法，而是在访问时沿链查找。这也是为什么给构造函数原型新增方法后，已有实例通常也能访问到。

## 原型链

对象读取属性时，会先查找自身，再沿原型链向上查找。

```text
dog -> animal -> Object.prototype -> null
```

如果整条链都找不到，结果就是 `undefined`。

```javascript
dog.toString(); // 来自 Object.prototype
```

原型链是 JavaScript 对象继承和方法共享的基础。理解它之后，`instanceof`、`class`、`hasOwn` 和方法解析顺序都会更好懂。

属性查找只发生在读取时。写入属性时，如果没有特殊 setter，通常会在对象自身创建或修改属性，而不是直接修改原型属性。这会产生“属性遮蔽”：自身属性会挡住原型上的同名属性。

```javascript
const parent = { role: 'member' };
const user = Object.create(parent);

console.log(user.role); // member

user.role = 'admin';
console.log(user.role); // admin
console.log(parent.role); // member
```

## `prototype`

函数的 `prototype` 属性用于给通过 `new` 创建的实例提供原型。

```javascript
function User(name) {
  this.name = name;
}

User.prototype.sayHello = function () {
  return `Hello, ${this.name}`;
};

const user = new User('Ada');
user.sayHello();
```

`user` 的原型指向 `User.prototype`，所以可以调用 `sayHello`。把方法放到原型上，能让所有实例共享同一份实现。

```javascript
User.prototype.role = 'member';
```

原型适合放行为，不适合放每个实例都不同的数据。

如果把可变对象放到原型上，多个实例会共享同一份数据，容易出现互相影响。

```javascript
function Group() {}

Group.prototype.members = [];

const a = new Group();
const b = new Group();

a.members.push('Ada');
console.log(b.members); // ['Ada']
```

实例私有数据应该在构造函数或 class 字段里初始化，原型上更适合放方法。

## `constructor`

默认情况下，`prototype.constructor` 会指回函数本身。

```javascript
User.prototype.constructor === User; // true
```

手动重设原型时，要注意恢复 `constructor`。

```javascript
Dog.prototype = Object.create(Animal.prototype);
Dog.prototype.constructor = Dog;
```

`constructor` 不是最核心的运行机制，但在调试、实例识别和一些旧代码里很常见。

不要把 `constructor` 当成绝对可靠的类型判断。它可以被手动改写，也可能因为跨 realm、原型重设、对象伪造而失真。业务里判断数组用 `Array.isArray`，判断对象能力更推荐看接口或特征，而不是迷信 `constructor.name`。

## `class` 与原型

`class` 只是更清晰的语法糖，底层仍然是原型。

```javascript
class User {
  constructor(name) {
    this.name = name;
  }

  sayHello() {
    return `Hello, ${this.name}`;
  }
}

const user = new User('Ada');
user.sayHello();
```

理解 `class` 的最好方式，不是把它看成“真正的类”，而是把它看成“原型语法糖”。这样在看继承、静态方法和原型方法时会更自然。

类中的普通方法会被放到原型上，实例字段则会放到实例自身。这个区别会影响内存和方法引用。

```javascript
class Counter {
  count = 0;

  increment() {
    this.count += 1;
  }
}

const counter = new Counter();
Object.hasOwn(counter, 'count'); // true
Object.hasOwn(counter, 'increment'); // false
```

## 属性归属

判断属性是否来自对象自身，可以用 `Object.hasOwn`。

```javascript
Object.hasOwn(user, 'name'); // true
Object.hasOwn(user, 'sayHello'); // false
```

`sayHello` 来自原型，不是实例自身属性。遍历对象时要区分自有属性和继承属性。

```javascript
for (const key in user) {
  if (Object.hasOwn(user, key)) {
    console.log(key);
  }
}
```

`for...in` 会遍历可枚举的自有属性和继承属性，所以处理普通数据对象时要谨慎。更常用的是 `Object.keys()`、`Object.entries()`、`Object.values()`，它们只处理对象自身可枚举属性，更符合大多数业务数据遍历需求。

## 原型污染

原型是共享的，随意修改内置原型风险很高。

```javascript
Array.prototype.first = function () {
  return this[0];
};
```

这类写法可能影响所有数组，也可能和第三方库冲突，还会引入枚举和兼容性问题。业务代码中通常不建议修改内置原型。

原型污染不仅是风格问题，也是安全问题。对象合并、用户输入和深拷贝逻辑如果处理不好，可能间接修改到原型链上的内容。

处理用户输入对象时，要特别警惕 `__proto__`、`constructor`、`prototype` 这类键。深合并函数如果不做过滤，就可能把恶意字段写入原型链，影响后续所有对象读取。安全场景下可以使用 `Object.create(null)` 创建无原型字典，或在合并时显式拒绝危险键。

```javascript
const dict = Object.create(null);
dict.safeKey = 'value';

console.log(dict.toString); // undefined
```

无原型对象没有 `Object.prototype` 上的方法，适合做纯字典，但使用时也要知道它没有 `hasOwnProperty` 这类继承方法。

## 使用场景

原型主要适合共享行为、节省内存和理解旧代码。

```javascript
user instanceof User; // true
```

`instanceof` 会沿原型链检查 `User.prototype` 是否出现在对象链上。只要涉及构造函数、实例识别、旧式继承和方法共享，原型就会出现。

`instanceof` 的本质是原型链检查，而不是检查对象“长得像不像”。跨 iframe、跨 vm、跨不同 JavaScript realm 时，同名构造函数可能不是同一个函数，`instanceof` 就可能失效。库代码如果需要更稳的类型判断，通常会用品牌检查、特征判断或内置方法。

## 原型与工程

现代业务代码很少手工操作原型链，但理解它仍然很重要，因为它解释了很多看似“语法层面”的行为：

- `class` 为什么能共享方法
- 为什么实例方法可以通过原型复用
- 为什么 `Object.create(null)` 没有普通对象原型
- 为什么 `hasOwn` 比直接遍历更安全

原型不是过时知识，它只是被更高层语法包起来了。

现代开发里即使很少手写 `prototype`，也经常间接遇到它：类方法共享、对象属性查找、数组方法、`Object.create`、`instanceof`、原型污染安全问题都依赖这套机制。理解原型，能让你在调试“这个方法从哪来的”“为什么这个属性被覆盖了”时少很多猜测。
