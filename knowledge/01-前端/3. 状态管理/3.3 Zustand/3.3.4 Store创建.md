## 建模方式

创建 Store 时要先确定状态形状和动作边界。

```javascript
const useTodoStore = create((set, get) => ({
  todos: [],
  addTodo: (text) =>
    set((state) => ({ todos: [...state.todos, { id: Date.now(), text }] })),
  completedCount: () => get().todos.filter((todo) => todo.done).length,
}));
```

状态、动作和派生读取可以放在一起，但派生读取如果依赖 React 渲染，通常更适合用选择器或组件内计算。

创建 Store 时最忌讳先把字段列满，再回头想怎么用。更好的方式是先写出业务动作，再根据动作需要补状态形状。

Zustand 的类型设计最好让状态和 action 都显式命名。不要在生产项目里长期使用隐式 `any` store，否则组件使用时会丢失最重要的类型保护。

## 初始化参数

Store 可以从默认值、外部配置或服务端注入数据初始化。要注意初始化不是无限制同步：如果状态来自服务端，仍然要考虑过期和重新获取。

```javascript
const initialTheme = window.matchMedia("(prefers-color-scheme: dark)").matches
  ? "dark"
  : "light";
```

初始化逻辑越复杂，越应该拆出函数，避免 Store 创建阶段混入太多副作用。

尤其不要在 Store 创建时直接发请求或依赖不稳定的浏览器环境。Store 创建应该尽量轻，真正的异步初始化可以交给 action 或页面入口触发。

如果初始化依赖浏览器对象，要考虑 SSR。比如 `window.matchMedia`、`localStorage`、`document` 都只存在于浏览器。可以在客户端 action 中初始化，或使用 persist 中间件的恢复机制。

## 按需拆分

不是所有状态都要放在同一个 Store。局部表单、临时弹窗状态仍然可以留在组件内部。

Zustand 适合跨组件共享的客户端状态。如果一个状态只在一个组件里使用，直接用组件状态更清楚。

## 基础创建

Zustand 通过 `create` 创建 Store。Store 里既可以放状态，也可以放修改状态的 action。

```ts
import { create } from "zustand";

type Todo = {
  id: string;
  title: string;
  done: boolean;
};

type TodoStore = {
  todos: Todo[];
  addTodo: (title: string) => void;
  toggleTodo: (id: string) => void;
};

export const useTodoStore = create<TodoStore>((set) => ({
  todos: [],
  addTodo: (title) =>
    set((state) => ({
      todos: [
        ...state.todos,
        { id: crypto.randomUUID(), title, done: false },
      ],
    })),
  toggleTodo: (id) =>
    set((state) => ({
      todos: state.todos.map((todo) =>
        todo.id === id ? { ...todo, done: !todo.done } : todo,
      ),
    })),
}));
```

这个 Store 可以直接在组件里使用，不需要 Provider 包裹。组件只订阅自己需要的字段，避免无关状态变化触发重渲染。

不需要 Provider 是 Zustand 上手快的原因，但也意味着 Store 更像模块级单例。测试、SSR 和多实例场景下，要特别注意状态隔离。

测试时要在每个用例后重置 Store，否则上一个测试写入的状态可能影响下一个测试。

```ts
afterEach(() => {
  useTodoStore.getState().reset();
});
```

如果需要同一页面里创建多个独立实例，例如多个编辑器互不影响，可以考虑使用 vanilla store 和 Context 注入，而不是共享同一个模块级 store。

```tsx
function TodoList() {
  const todos = useTodoStore((state) => state.todos);
  const toggleTodo = useTodoStore((state) => state.toggleTodo);

  return (
    <ul>
      {todos.map((todo) => (
        <li key={todo.id}>
          <button onClick={() => toggleTodo(todo.id)}>
            {todo.done ? "已完成" : "未完成"} {todo.title}
          </button>
        </li>
      ))}
    </ul>
  );
}
```

## set 函数

`set` 可以接收对象，也可以接收函数。依赖旧状态计算新状态时，优先使用函数形式。

```ts
const useCounterStore = create((set) => ({
  count: 0,
  increment: () => set((state) => ({ count: state.count + 1 })),
  reset: () => set({ count: 0 }),
}));
```

对象形式适合重置或明确覆盖，函数形式适合计数、数组追加、列表更新等依赖当前值的场景。

只要新状态依赖旧状态，就优先用函数形式。这样在连续更新、高频事件和批量操作里更不容易拿到旧快照。

## get 函数

`get` 用来读取当前 Store 快照，适合在 action 内组合状态或调用其他 action。

```ts
const useCartStore = create((set, get) => ({
  items: [] as Array<{ price: number; quantity: number }>,
  totalPrice: () =>
    get().items.reduce(
      (sum, item) => sum + item.price * item.quantity,
      0,
    ),
  clearWhenFree: () => {
    if (get().totalPrice() === 0) {
      set({ items: [] });
    }
  },
}));
```

`get` 读取的是当前快照，不会自动让组件订阅。组件中仍然应该通过 `useStore(selector)` 读取响应式状态。

组件外使用 `getState()` 或 `get()` 时，最好明确它只是快照读取。它不会让 UI 自动更新，也不应该替代组件里的 selector。

## 替换状态

`set(partial)` 默认浅合并。如果传入第二个参数 `true`，会替换整个 Store 状态，使用时要非常谨慎。

```ts
const useSessionStore = create((set) => ({
  user: null,
  permissions: [],
  logout: () =>
    set(
      {
        user: null,
        permissions: [],
      },
      true,
    ),
}));
```

替换模式会覆盖 action 字段，除非你把完整状态和 action 都重新放回去。大多数业务场景使用默认浅合并更安全。

需要整体重置时，更推荐提供明确的 `reset` action，并在 action 内恢复初始状态。这样不会意外丢掉方法，也更容易测试。

初始状态最好抽成常量或函数，避免 reset 时手写一份不一致的新对象。

```ts
const createInitialState = () => ({
  todos: [] as Todo[],
});

const useTodoStore = create<TodoStore>((set) => ({
  ...createInitialState(),
  reset: () => set(createInitialState()),
}));
```
