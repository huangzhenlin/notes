## Flexbox 默认值

React Native 的布局系统以 Flexbox 为核心，和 Web 上的 CSS Flexbox 很接近，但不是完整 CSS。RN 中 `flexDirection` 默认是 `column`，这和 Web 里常见的横向 flex 默认思维不同。

```tsx
import { View, Text, StyleSheet } from "react-native";

<View style={styles.container}>
  <Text>标题</Text>
  <Text>描述</Text>
</View>
```

```ts
const styles = StyleSheet.create({
  container: {
    flex: 1,
    padding: 16,
  },
});
```

`flex: 1` 表示占满父级剩余空间，是页面根容器里最常见的写法。布局异常时，先检查父级是否有明确尺寸或 `flex`，再看子元素对齐方式。

RN 布局调试最常见的误区，是按 Web 的默认值去猜。只要先记住“默认主轴是竖向、很多组件没有天然尺寸、父级不给空间子级就撑不开”，排查思路就会清晰很多。

## 主轴与交叉轴

`flexDirection` 决定主轴方向，`justifyContent` 控制主轴分布，`alignItems` 控制交叉轴对齐。

```tsx
<View style={styles.row}>
  <Text>商品名称</Text>
  <Text>￥99</Text>
</View>
```

```ts
const styles = StyleSheet.create({
  row: {
    flexDirection: "row",
    justifyContent: "space-between",
    alignItems: "center",
  },
});
```

如果横向布局没有按预期撑开，通常是父容器宽度、子元素 `flex`、主轴分布其中之一出了问题。移动端布局不要过度依赖固定宽度，内容长度、系统字体和屏幕尺寸都会改变最终效果。

移动端布局真正追求的不是“在开发机上刚好对齐”，而是“在不同屏幕、字体和语言下都还能稳定成立”。主轴和交叉轴一旦理解透了，很多适配问题就不需要靠补丁式 margin 去修。

## 尺寸单位

React Native 的尺寸是无单位数字，表示密度无关像素。不要写 `"16px"`。

```ts
const styles = StyleSheet.create({
  card: {
    marginHorizontal: 16,
    paddingVertical: 12,
  },
});
```

百分比字符串可以用于部分场景，例如宽度 `"100%"`。复杂适配不要单纯按屏幕宽度写死，可以结合安全区、窗口尺寸和内容约束。对于文字、按钮和表单项，优先保证可读性和可点击性，而不是追求所有设备上比例完全一致。

RN 的数字尺寸虽然省掉了单位，但并没有省掉适配判断。尺寸写成 `16` 只是表达方式更直接，真正要考虑的仍然是可读性、可点击性、安全区和设备形态。

## StyleSheet

`StyleSheet.create` 可以让样式结构更清晰，也方便静态检查和复用。它不是必须项，但大型项目中比到处写内联对象更容易维护。

```tsx
const styles = StyleSheet.create({
  page: {
    flex: 1,
    backgroundColor: "#f7f8fa",
  },
  content: {
    paddingHorizontal: 16,
    paddingTop: 12,
  },
});
```

样式对象不要和业务状态过度混杂。需要根据状态变化的样式，可以使用数组组合；需要跨页面统一的样式，适合抽成设计变量或主题函数。

```tsx
<View style={[styles.card, selected && styles.cardSelected]} />
```

样式组织做得好，后面的状态变化和主题切换会轻松很多。反过来，如果样式对象和业务条件混得太深，页面一复杂，布局和交互状态就会一起失控。

## 安全区

iPhone 刘海屏、Android 状态栏、底部手势区域都需要考虑安全区。

```tsx
import { SafeAreaView } from "react-native-safe-area-context";

export function Screen() {
  return (
    <SafeAreaView style={{ flex: 1 }}>
      <Content />
    </SafeAreaView>
  );
}
```

页面根部通常需要安全区处理，沉浸式头图、底部操作栏和全屏弹窗要单独设计边界。不要简单给所有页面都加相同 padding，否则沉浸式页面、地图页面和全屏图片预览会出现不自然的空白。

安全区不是一个“统一加边距”的技巧，而是页面和系统界面共存时的边界规则。不同页面使用方式差异很大，真正稳定的做法通常是页面级定义，而不是全局一刀切。

## 绝对定位

`position: "absolute"` 适合角标、浮层、固定按钮，但不要用它代替正常布局。

```tsx
<View style={styles.imageWrapper}>
  <Image source={{ uri }} style={styles.image} />
  <Text style={styles.badge}>热门</Text>
</View>
```

```ts
const styles = StyleSheet.create({
  imageWrapper: {
    position: "relative",
  },
  badge: {
    position: "absolute",
    right: 8,
    top: 8,
  },
});
```

大量绝对定位会让不同屏幕尺寸下的重叠问题变多。能用 Flexbox 表达的布局，优先使用 Flexbox。固定底部按钮、悬浮客服、角标和弹窗遮罩可以用绝对定位，但要同时验证安全区和键盘场景。

绝对定位在 RN 里不是不能用，而是更需要节制。因为一旦和安全区、键盘、横竖屏、动态内容长度叠在一起，原本“刚刚好”的定位很容易在另一台设备上完全跑偏。

## 键盘避让

表单页要考虑键盘弹出后输入框被遮挡。

```tsx
import { KeyboardAvoidingView, Platform } from "react-native";

<KeyboardAvoidingView
  behavior={Platform.OS === "ios" ? "padding" : "height"}
  style={{ flex: 1 }}
>
  <LoginForm />
</KeyboardAvoidingView>
```

键盘避让通常还要配合滚动容器、底部按钮和安全区一起验证。只在一个平台看起来正常，不代表另一个平台也正常。登录页、聊天页、评论页和地址表单尤其要真机测试键盘弹出、切换输入框、收起键盘和系统返回。

键盘避让的重点不是把所有内容一起顶上去，而是保证当前正在输入的区域和关键操作仍然可见、可达、可关闭。不同页面的最佳策略不一定一样，表单页和聊天页尤其要分开设计。

## 测量与更新

React Native 的布局不是依赖 DOM，而是根据组件树计算出原生视图的尺寸和位置。布局变化会影响整个视图树的测量和更新。

这意味着布局写法要尽量简洁，尽量避免深层嵌套，不要在一处变化时牵动过多节点。复杂列表中，如果每个 item 都有多层嵌套、动态高度、远程图片和条件渲染，滚动性能会明显受影响。

需要获取尺寸时，可以使用 `onLayout`，但不要把它当成每帧测量工具。

```tsx
<View
  onLayout={(event) => {
    const { width, height } = event.nativeEvent.layout;
    setCardSize({ width, height });
  }}
/>
```

布局系统和 [[7.5.6 性能优化|性能优化]] 联系很紧：布局越稳定、节点越少、更新范围越小，越容易获得接近原生的流畅体验。

布局系统写得成熟时，你会更少依赖“测出来再修”。能通过结构和约束直接表达清楚的布局，通常比运行时频繁测量再调整更稳，也更有利于性能。
