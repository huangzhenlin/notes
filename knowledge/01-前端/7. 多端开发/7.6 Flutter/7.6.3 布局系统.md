## 布局模型

Flutter 布局的核心是约束。父级给子级约束，子级在约束内选择尺寸，然后父级决定子级位置。它和 Web CSS 布局的思路不同，必须先理解约束再理解组件。

```text
Constraints go down
Sizes go up
Parent sets position
```

这个规则是 Flutter 布局最重要的底层认知。没有它，很多“为什么宽度不是 100”“为什么 Column 溢出”的问题都会反复出现。

对 Web 前端来说，这套规则最反直觉的地方在于：Flutter 不是先写一个元素，再用一堆 CSS 慢慢把它调对；而是从一开始就要求你理解“父级给了什么约束，子级能在里面怎么选尺寸”。

## 约束传递

每个 Widget 会从父级拿到 BoxConstraints，再把自己的子级约束和位置计算出来。

```dart
class BoxConstraints {
  const BoxConstraints({
    this.minWidth = 0.0,
    this.maxWidth = double.infinity,
    this.minHeight = 0.0,
    this.maxHeight = double.infinity,
  });
}
```

约束本身不是尺寸，尺寸是 Widget 在约束范围内选择出来的结果。理解这一点后，你会明白为什么同样的 Widget 放在不同父容器里表现会不同。

很多 Flutter 布局问题之所以让初学者困惑，就是因为大家很容易把“父级给的范围”和“子级最后选的大小”混成一件事。把这两者拆开理解，调布局的效率会快很多。

## 常见布局

常见布局 Widget 包括 `Row`、`Column`、`Stack`、`Container`、`Expanded`、`Flexible`、`Padding`、`Align`。它们通过组合完成大多数页面结构。

```dart
Row(
  children: const [
    Text("商品名"),
    Spacer(),
    Text("￥99"),
  ],
);
```

`Row` 和 `Column` 属于 Flex 系列，适合线性排列；`Stack` 适合叠层；`Container` 是方便的复合容器，但不应成为一切问题的默认答案。

`Container` 很顺手，但也最容易被滥用。只要一个组件里既没装饰、也没尺寸、也没内边距，通常不必为了“习惯”套一层 `Container`。布局越直接，约束链越容易看清。

## 主轴与交叉轴

`Row` 和 `Column` 的布局参数其实就是主轴与交叉轴的分布问题。很多布局错误，根源在于把主轴和交叉轴搞反了。

```dart
Row(
  mainAxisAlignment: MainAxisAlignment.spaceBetween,
  crossAxisAlignment: CrossAxisAlignment.center,
  children: const [
    Text("名称"),
    Text("价格"),
  ],
);
```

主轴控制“往哪儿排”，交叉轴控制“怎么对齐”。先分清轴向，再谈间距和居中，通常会快很多。

很多看起来像“间距不对”的问题，根因其实是轴向搞反了。只要先问自己这是横向排还是纵向排、主轴在哪里、交叉轴在哪里，后面的 `mainAxisAlignment` 和 `crossAxisAlignment` 就不会乱。

## 约束松紧

约束可以是 tight 也可以是 loose。tight 约束意味着尺寸被严格限制；loose 约束则允许子级在一定范围内自由选择。

```dart
Center(
  child: Container(
    width: 120,
    height: 40,
  ),
);
```

`Center` 常常把来自父级的紧约束转成对子级更宽松的约束。理解约束松紧，很多“为什么这个组件不能随便缩小”的问题就会变得清楚。

约束松紧可以理解成“父级到底替你决定了多少”。父级决定得越死，子级越没有空间；父级给得越松，子级越可以按自己内容来选尺寸。很多布局行为差异，本质上就是这条链路在变化。

## 无界约束

无界约束是 Flutter 常见报错来源，尤其发生在 `Row`、`Column`、`ListView` 嵌套时。某个方向的最大值如果是无限大，试图“尽可能变大”的组件就容易出问题。

```dart
ListView(
  children: const [
    Text("A"),
    Text("B"),
  ],
);
```

当你把可滚动区域嵌套进另一个同方向可滚动区域时，最容易遇到无界约束。这个时候要考虑固定高度、使用 `Expanded`、调整滚动层级或重构布局。

无界约束常常不是某个组件“坏了”，而是布局结构本身在表达冲突：一个方向上已经没有明确边界，但子级又想继续无限扩张。排查这类问题时，通常先看滚动容器和 Flex 容器的组合。

## 组合原则

Flutter 布局最强的地方，不是某个单独 Widget，而是组合。好的布局会把结构拆清楚，再用少量 Widget 拼起来。

```dart
Container(
  padding: const EdgeInsets.all(16),
  child: Column(
    children: const [
      Text("标题"),
      SizedBox(height: 12),
      Text("内容"),
    ],
  ),
);
```

尽量少用嵌套过深的神奇布局。布局越清楚，后续状态分层、性能优化和可维护性就越好。能用简单的 Flex 表达，就不要过早堆叠复杂容器。

Flutter 布局越写越复杂时，通常不是因为框架不够，而是因为结构本身没先想清楚。先画清楚区域关系，再落成 Widget 组合，往往比一层层试出来更稳。

## 复杂场景

`Expanded` 适合吃掉剩余空间，`Flexible` 适合在剩余空间里更灵活地取值，`Stack` 适合叠层内容，`Align` 适合对齐，`AspectRatio` 适合控制比例。

```dart
Row(
  children: const [
    Icon(Icons.search),
    SizedBox(width: 8),
    Expanded(
      child: TextField(),
    ),
  ],
);
```

复杂布局出现问题时，先看约束从哪里来，再看哪个 Widget 在主动扩张。大多数 Flutter 布局问题，本质上都是约束传递链中的某一环不符合预期。布局调试时，先把“谁给谁约束”理清，再去调整对齐、间距和尺寸。

复杂场景里最值得养成的习惯，就是先顺着约束链往上找，而不是先在当前 Widget 上不停试参数。只要父级给错了空间，子级怎么调通常都只是局部补丁。
